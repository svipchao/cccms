## 一、技术栈与启动

| 项 | 技术 |
|----|------|
| 框架 | Vue 3.5（`<script setup>` + Composition API） |
| 语言 | TypeScript 5.7（`strict: true`） |
| 构建 | Vite 5 |
| UI | Element Plus 2.x（中文语言包） |
| 样式 | Tailwind CSS 4 + 设计 token（`--art-*`） |
| 状态 | Pinia |
| 路由 | vue-router 4（**hash 模式**） |
| 图表 | ECharts 6（`echarts/core` 按需引入） |
| 测试 | Vitest 3 + `@vue/test-utils`（jsdom） |
| 进度条 | NProgress（统一经 `utils/progress` 调用） |

```bash
cd frontend
npm install
npm run dev            # http://localhost:5173，/api 代理到 127.0.0.1:8787
npm run build          # 先 vue-tsc --noEmit 再 vite build
npm run preview
npm run lint           # ESLint（扁平配置）
npm run lint:fix       # 自动修复
npm run format         # Prettier 写入
npm run format:check   # 只校验格式（CI 用）
npm run test           # Vitest 跑一遍单元测试
npm run test:watch     # 监听模式
npm run test:coverage  # 带覆盖率（CI 用，会卡核心模块阈值）
```

工具链约定：**ESLint 管「可能出错的代码」，Prettier 管格式**。
ESLint 刻意只启用 `vue/flat/essential`（而非 `recommended`），避免模板排版规则与 Prettier 打架，
也避免在既有代码里刷出成百上千条噪音。

## 二、应用引导（`main.ts`）

`main.ts` 的顺序是有讲究的：

```ts
import '@/assets/styles/index.css'                    // 1. Tailwind + 设计 token
import 'element-plus/dist/index.css'                  // 2. Element Plus
import 'element-plus/theme-chalk/dark/css-vars.css'   //    暗色变量
import '@/assets/styles/element.css'                  // 3. EP 主题覆盖
import '@/assets/styles/app.css'                      // 4. 业务全局
import 'nprogress/nprogress.css'

const app = createApp(App)
app.use(pinia)
app.use(ElementPlus, { locale: zhCn, zIndex: 3000 })
setupDirectives(app)          // 注册 v-auth
app.use(router)

useSettingStore(pinia).init() // 先用本地/默认主题上色，避免白屏闪烁

// 再拉后台品牌/UI 配置，最多等 2.5 秒，拿不到就兜底，绝不卡住启动
const ready = Promise.race([useAppStore(pinia).load(), timeout(2500)])
void ready.finally(() => {
  app.mount('#app')
  document.getElementById('cccms-loader')?.remove()   // 移除 index.html 的首屏 loading
})
```

> **样式导入顺序不可随意调整**：`element.css`（覆盖层）必须在 Element Plus 之后、业务样式之前。

## 四、路由机制

采用 `createWebHashHistory()`（hash 路由）。

### 4.1 静态路由（`router/index.ts`）

| 路径 | 组件 | 说明 |
|------|------|------|
| `/login` | `pages/cccms/login/index.vue` | `meta.public = true` |
| `/` → `BasicLayout` | 布局 | `redirect: /dashboard` |
| `/dashboard` | 工作台 | 菜单里的 `cccms:dashboard` 指向它 |
| `/profile` | 个人中心 | **静态路由**，不进左侧菜单 |
| `/403` | `pages/cccms/error/403.vue` | 无权访问；**刻意不带 `meta.node`**，否则守卫会「403 → 403 校验失败 → 再跳 403」无限重定向 |
| `/:pathMatch(.*)*` | `404` | 兜底 |

> ⚠️ **陷阱**：404 兜底**不能**标 `public`。刷新时首帧会先落到兜底路由（动态路由还没注册），若判为 public 提前返回，就会跳过动态路由注册。

### 4.2 动态路由（菜单驱动）

```ts
const pageModules = import.meta.glob('/src/pages/**/*.vue')   // 自动收集页面组件

function buildRoutes(menus: MenuNode[]) {
  // 只注册 type === 2（菜单）且 component 非空的节点
  //   path = m.path 去掉前导 '/'（相对挂在 layout 下）
  //   name = m.node || `menu-${m.id}`
}
```

- 数据源：`GET /menu/userTree`（`menuStore.load()`）。
- **目录（type=1）与按钮（type=3）不产生路由**。
- `component` 字段（如 `cccms/user/index`）映射到 `/src/pages/cccms/user/index.vue`。
- 菜单 `name` 也用于 keep-alive 的 `include` 名单。
- `reloadMenus()`：重挂动态路由 + 刷新用户信息（菜单 / 按钮变更后调用）。

### 4.3 路由守卫（`beforeEach`）

1. 启动进度条令牌 `ROUTE_PROGRESS`。
2. 无 token：只放行 `meta.public`，否则跳 `/login?redirect=...`。
3. 无用户信息：`fetchProfile()`，失败跳登录。
4. 动态路由未注册：`menuStore.load()` → `addDynamicRoutes()`；失败标记已注册（不阻塞，交给 404 兜底）。
5. **动态路由注册后必须按 path 重新导航**：

   ```ts
   return { path, query, hash, replace: true }
   // ⚠️ 不能写 { ...to, replace: true }：to.name 为 'notFound' 时 name 优先，会再解析回兜底路由
   ```
6. **节点级权限校验（路由级守卫）**：动态路由已注册后，取 `to.meta.node`（`buildRoutes`
   写入的菜单 slug）调 `userStore.hasAuth(node)`；不通过则 `{ path: '/403', replace: true }`。
   - `meta.node` 为空（`/dashboard`、`/profile`、404 兜底、`/403` 本身）一律不校验；超管在 `hasAuth()` 内直通。
   - `v-auth` 只管按钮显隐，**直接输入 URL 要靠这一步拦**（后端 403 是最后一道，不该是唯一一道）。

`afterEach`：结束进度条 + 设置 `document.title`。

### 4.4 401 处理

响应拦截器收到 401 时：清 token → 提示 → `resetAfterLogout()`（清动态路由与标签页，**避免换账号残留**）→ 跳 `#/login`；800ms 内不再重复跳转（防 401 风暴）。

## 五、请求层（`api/request.ts`）

```ts
const instance = axios.create({ baseURL: import.meta.env.VITE_API_BASE || '/api', timeout: 15000 })

export const http = {
  get:  <T>(url, params?) => instance.get(url, { params }).then(r => r as T),
  post: <T>(url, data?)   => instance.post(url, data).then(r => r as T),
}
```

约定：

| 项 | 约定 |
|----|------|
| 成功判定 | **只看 `code === 0`**，不做 HTTP 状态判断 |
| 返回值 | 拦截器已解包，`http.get()` 拿到的**就是 `data`** |
| 错误提示 | 拦截器统一 `ElMessage.error`，页面 `catch` 只做兜底 |
| 鉴权头 | 自动注入 `Authorization: Bearer <token>`（localStorage `cccms_token`） |
| 令牌续期 | 响应头带 `X-Refresh-Token` 时静默 `setToken()` 替换（**blob 分支也处理**）；由后端在剩余不足 TTL 的 1/3 时下发，见 [05-鉴权与权限 §5.2](05-鉴权与权限.md#52-tokenservicejwt) |
| 响应体无 `code` 字段 | 原样透传（用于非标准响应） |
| 401 | 清 token + 提示 + `resetAfterLogout()` + 跳登录 |
| 网络异常 | 提示「网络异常，请检查服务是否启动」 |

> 后端虽然支持 `json/jsonp/xml/view` 四种编码，但前端只使用 `json`，未做 jsonp 适配。文件上传走 `el-upload` 直传（不经 axios），单独登记上传进度令牌。

### 5.1 文件下载 `downloadFile`

后端导出接口返回的是**文件流**（不是统一信封），因此：

- 响应拦截器对 `response.config.responseType === 'blob'` 的请求**保留完整响应**
  （调用方要读 `Content-Disposition` 里的文件名），其余照旧解包 `data`。
- 用 `downloadFile(url, params?, fallbackName?)` 下载：它复用同一个 axios 实例
  （自动带鉴权头、401 处理与进度条），解析文件名后触发浏览器下载。

```ts
import { downloadFile } from '@/api/request'
await downloadFile('/log/export', { status: 1 }, '操作日志.csv')
```

命名约定：导出函数放在对应 `api/{模块}.ts` 里，如 `logExport()`（当前仅**日志导出**在用它）。

| Store | 职责 | 关键点 |
|-------|------|--------|
| `app` | 品牌与 UI 默认值（`system.*` / `ui.*`） | `load()` 有兜底，异常不抛出；`logo` / `systemName` / `pageSize` / `tagsView` |

## 七、主题与设计 token

**颜色一律使用设计 token，禁止写死颜色**（否则暗色模式会花）。

| token | 用途 |
|-------|------|
| `--art-primary` | 品牌主色（默认 `#2b6cff`） |
| `--art-main` / `--art-sub` / `--art-muted` | 主 / 次 / 弱文本 |
| `--art-card-bg` / `--art-card-border` | 卡片背景 / 边框 |
| `--art-body-bg` / `--art-hover-bg` | 页面背景 / 悬停背景 |
| `--art-success` / `--art-warning` / `--art-danger` / `--art-info` | 语义色 |
| `--art-radius` | 圆角（联动 Element Plus） |
| `--art-container-width` | 内容区最大宽度 |
| `--art-header-height` / `--art-tagbar-height` / `--art-sidebar-width` / `--art-sidebar-collapsed-width` | 布局尺寸 |

- 定义在 `assets/styles/tokens.css`：亮色在 `:root`，暗色在 `html.dark`。
- `assets/styles/index.css` 通过 Tailwind 的 `@theme` 把 token 映射成工具类（`bg-card`、`text-sub`、`border-line`、`rounded-art` 等）。
- 主色变化必须经 `utils/theme.ts` 的 `applyPrimary()`，它会同时重算 `--el-color-primary-light-3/5/7/8/9` 与 `dark-2`。
- 主色浅色阶用 `var(--el-color-primary-light-9)`。

## 八、三种页面范式

### 8.1 列表页

根节点 `.art-fill`（撑满高度，**表格内部滚动**），使用 `ArtTable` + `useTable`：

```vue
<template>
  <div class="art-fill">
    <ArtTable :columns="columns" :data="list" :loading="loading" :total="total"
              v-model:page="page" v-model:limit="limit"
              @refresh="load">
      <template #toolbar-right>
        <RecycleToggle :active="recycle" :label="t('user.recycleLabel')" @toggle="toggle" />
        <el-button v-auth="'cccms:user:save'" type="primary" @click="openCreate">{{ t('common.create') }}</el-button>
      </template>
    </ArtTable>
    <!-- 新增 / 编辑 el-dialog -->
  </div>
</template>
```

**筛选只声明在列的 `filter` 上，页面不要再手写搜索表单**：`ArtTable` 会按列的 `filter` 配置
自动生成表格上方的搜索卡片（列头筛选入口同样由它生成），页面无需维护筛选状态，也不提供
`#search` 插槽。给需要筛选的列加 `filter` 配置即可：

```ts
const columns = computed<ArtTableColumn[]>(() => [
  { prop: 'username', label: t('user.username'), filter: { type: 'text' } },
  {
    prop: 'status',
    label: t('user.status'),
    filter: {
      type: 'enum', // 多选，值以逗号串（如 "1,0"）写入 query
      options: [
        { label: t('user.enabled'), value: 1 },
        { label: t('user.disabled'), value: 0 },
      ],
    },
  },
])

// 所有筛选字段都要写进 initialQuery（它同时是「筛选记忆」回填的白名单），
// 且 enum 多选字段的类型声明为 string
interface Query { username: string; status: string }
useTable<Row, Query>({ api: userList, initialQuery: { username: '', status: '' } })
```

后端接收逗号串或数组均可（`plugin\cccms\support\FilterInput::ints()` / `values()` → `whereIn`）。

时间列用 `filter: { type: 'date' }`：选择器是 `datetimerange`（带时分秒，格式 `YYYY-MM-DD HH:mm:ss`），
并自带今天 / 昨天 / 最近 3·7·30 天 / 本月 / 上月 七个快捷项。后端统一用
`FilterInput::range($params['start'] ?? null, $params['end'] ?? null)` 解析，**它返回的就是可直接比较的
`Y-m-d H:i:s`**（纯日期会补 `00:00:00` / `23:59:59`），调用方不要再自己拼时间后缀。
同一页有多个时间条件时必须各配一组 `startKey` / `endKey`，否则会互相覆盖。

### 8.2 树形页

`ArtSplitView` + `ArtTreePanel`（左侧树）+ `ArtTable`（右侧，可 `tree` 且 `:pagination="false"`）。例：部门、角色、字典、附件。

### 8.3 表单页

根节点 `.art-scroll`（**整体滚动**）+ `el-card` 分组。例：配置管理、个人中心、代码生成。

### 8.4 布局与顶栏能力

`layouts/BasicLayout.vue` 组合侧边栏 / 顶栏 / 标签栏 / 内容区。顶栏 `LayoutHeader.vue` 提供：

| 能力 | 说明 |
|------|------|
| 快捷导航 | **Ctrl / ⌘ + K** 打开菜单对话框（数据源 `menuStore.flatMenus`，即 `type = 2` 且 `path` 非空）。上半区是**本机收藏**（上移 / 下移排序 + 取消收藏，空态有提示），下半区是全部菜单 / 搜索结果，每行右侧星标可切换收藏。收藏与标签栏星标、工作台「我的收藏」宫格共用同一份 store 状态 |
| 标签栏收藏 | 标签栏刷新按钮**旁边**：星标切换「当前标签页是否收藏」，已收藏是金色实心星 + 底色、未收藏是灰色轮廓星；不在菜单里的页面（如个人中心）不渲染该按钮 |
| 面包屑 | 由 `route.matched` 生成，**中间层级可点击跳转**（最后一级是当前页，不给链接） |
| 顶栏图标 | 快捷导航 / 全屏 / **消息 + 导出任务**（合并入口）/ 设置 |
| 消息中心 | 顶栏铃铛图标，角标 = 未读消息 + 未完成导出任务（> 99 显示 `99+`）。抽屉内用 **tabs** 区分「我的消息」（点击标记已读并弹详情，富文本经 `sanitizeHtml` 净化后渲染）与「导出任务」（列表 + 下载）。组件 `MessageCenterDrawer.vue`，开合 / 当前 tab 状态放 `exportTaskStore`，任意页面调 `open(tab)` 即可唤起（如日志导出后自动定位「导出任务」） |
| 侧边栏用户卡片 | 侧边栏**置顶**，**两行**：第一行头像 + 用户名 / 角色（靠左，点击进个人中心）+ **注销登录**（靠右）；第二行四个功能图标「**切换平台**（仅超管）/ 切换主题模式 / 切换语言 / 清除缓存」（系统刷新下拉：整体同步 / 菜单同步 / 权限同步 / 清理缓存，`v-auth="'cccms:config:refresh'"` 才显示，刷新中图标旋转）。菜单 / 按钮变更后会重挂动态路由并刷新权限 |
| 切换租户 | 侧边栏用户卡片图标行**第 1 位**（图标 + 下拉切换，仅 `userStore.superAdmin` 可见），二次确认后切换并**整体重载**页面 |
| 主题设置 | 顶栏「设置」图标打开抽屉（主题模式等） |
| 用户操作 | 注销登录会重置通知 store 与导出任务 store，避免换账号残留未读角标与任务 |

## 九、前端开发约定清单（必守）

| # | 约定 | 原因 |
|---|------|------|
| 1 | 页面文件一律 `index.vue`，并用 `defineOptions({ name: '<菜单 slug>' })` | 动态路由 `name`、keep-alive `include`、标签页三者靠它对齐；不声明会互相撞名导致缓存失配 |
| 2 | 颜色只用 `var(--art-*)` / `var(--el-*)` | 暗色模式与换肤 |
| 3 | 权限按钮用 `v-auth="'cccms:xxx:yyy'"`（支持数组） | 与后端 slug 对齐；**界面显隐不等于拦截** |
| 4 | 列表页统一用 `ArtTable` + `useTable` | 行为一致（搜索 / 分页 / 列显隐 / 回收站） |
| 5 | 回收站 `useRecycle` 必须写在 `useTable` **之前** | 列表闭包在 setup 阶段就会执行一次，`recycle` 需已初始化 |
| 6 | 列表接口带 `trashed: recycle.value ? 1 : 0` | 回收站不是独立接口，靠参数切数据源 |
| 7 | 页面滚动交给页面自身：列表页 `.art-fill`，普通页 `.art-scroll` | 内容区自身不滚动 |
| 8 | 图标用 `<ArtIcon name="icon-xxx" />`；候选来自 `MENU_ICON_OPTIONS` | 按需注册，保证 tree-shaking |
| 9 | 长耗时操作经 `utils/progress` 登记令牌 | NProgress 统一入口，避免多来源抢占 |
| 10 | 操作列列配置用 `slot: 'action'` + `lockVisible: true` | 回收站模式会接管操作列 |
| 11 | 接口函数放 `api/`，不在页面里直接 `axios` | 统一鉴权 / 错误处理 |
| 12 | 密码类配置项留空表示「不修改」 | 与后端 `type=password` 约定一致 |
| 13 | 字段级 `encrypt` 用 `utils/crypto.decryptField(值, userStore.cryptoKey)` | 后端返回 AES-256-GCM 密文 |
| 14 | cron 统一六段；前端预览仅供参考 | 真正调度以后端 `CronMatcher` 为准 |
| 15 | 导出用 `downloadFile()`，不要自己拼 `axios` | 统一带鉴权头、401 处理与文件名解析（当前仅日志导出在用） |
| 16 | 列表条件自动回填 / 「筛选方案」覆盖**所有表格含树表** | `useTable`（需分页）与 `useTableFilter`（纯前端过滤，如 menu/dept 树表）共用同一套 `cccms_table_filter:` 机制 |
| 17 | 全局状态（顶栏角标等）放 store，页面级状态留在页面 | 顶栏常驻组件不适合逐页取数 |
| 18 | 列表列宽拖拽会自动持久化，无需页面处理 | `ArtTable` 已内建 `cccms_table_width:` 记忆 |
| 19 | 界面文案走 `t('命名空间.键')`，不要硬编码中文 | 语言切换后无需刷新（`ElConfigProvider` 响应式联动） |
| 20 | lint 为 **ESLint 10** 扁平配置，格式交给 Prettier | 提交前必须 `npm run lint` + `npm run format:check` 双绿 |
| 21 | 开 `selection` 的列表**必须显式传 `row-key="id"`**，并在 `#toolbar` 放「批量操作」`el-dropdown` | 否则勾选状态在数据刷新后错乱；批量接口返回 `{affected, skipped[]}`，**有跳过时用 `ElMessage.warning` 说明原因**（越权 / 受保护 / 不存在） |

## 十一、新增一个页面的步骤

1. 后端建好接口、声明权限节点，执行 `perm-scan`，并在 `db/menu.php` 声明菜单（`component = {插件}/{模块}/index`）。
2. 前端建 `src/pages/{插件}/{模块}/index.vue`：

   ```vue
   <script setup lang="ts">
   defineOptions({ name: '{插件}:{模块}' })   // 必须等于菜单 slug
   // ...
   </script>
   ```

3. 建 `src/api/{插件}/{模块}.ts` 封装接口。
4. 执行 `php webman cccms:menu-sync` 同步菜单。
5. 刷新页面，动态路由会自动带上新页面；给角色授权对应节点。
6. `npm run build` 通过（含 `vue-tsc` 类型检查）。

## 十二、国际化（i18n）

前端用 `vue-i18n`（Composition 模式），语言包**按来源分目录**：`src/locales/{zh-CN,en-US}/core/<模块>.ts` 放框架级文案、`src/locales/{zh-CN,en-US}/cccms/<模块>.ts` 放 cccms 插件文案，后续插件各加一个同名子目录；每个语言目录的 `index.ts` 递归聚合，入口 `src/locales/index.ts`。

| 关注点 | 约定 |
|--------|------|
| 语言列表 | `SUPPORTED_LOCALES`：`zh-CN`（默认）/ `en-US`；归一化支持 `zh` / `en` 前缀简写 |
| 本机偏好 | `localStorage['cccms_locale']`；**只存用户自己选过的值** |
| 后台默认值 | 由 `/config/ui` 下发（对应后端 `plugin.cccms.app.locale`）；仅在用户**没存过**本机偏好时应用 |
| 切换 | `setLocale()`：更新 i18n + `currentLocale` ref + 持久化 + 同步 `<html lang>`，**无需刷新页面** |
| Element Plus | `App.vue` 的 `<ElConfigProvider :locale>` 绑 `currentLocale`，日期 / 分页等内置文案随之切换 |
| 组件内 | `const { t } = useI18n({ useScope: 'global' })` |
| 非组件上下文 | `import { t } from '@/locales'`（axios 拦截器、store 等） |

### 12.1 语言包怎么组织

- **一个插件一个子目录**，不要拉平到 `zh-CN/` 根下（插件多了会乱，且无法判断某条文案属于谁）：
  - `core/`：框架级文案 —— `common.ts`（按钮名 / 通用提示）、`table.ts`（表格 / 回收站）、`layout.ts`（布局）、`route.ts`（静态路由标题）、`login.ts` / `error.ts` / `setting.ts` / `panel.ts` / `richEditor.ts`。
  - `cccms/`：cccms 插件文案，一个业务模块一个文件：`user.ts` / `role.ts` / `config.ts` …
  - 后续插件：新建 `zh-CN/<plugin>/` 与 `en-US/<plugin>/`，**两端同名同结构**。
- **命名空间 = 目录路径**（`cccms/user.ts` → `cccms.user`），因此插件之间天然隔离：两个插件各有一个 `user.ts` 也不会冲突，不需要任何重名兜底。
- 代价是引用要写全路径：`t('cccms.user.name')`、`t('core.common.back')`；模板拼接同理（`` t(`cccms.dashboard.weekday${d}`) ``）。
- 新增文件**无需注册**（`index.ts` 用递归 `import.meta.glob` 自动收集），但 `zh-CN` / `en-US` 的**相对路径**与 key 必须一一对应。
- 校验：`npm run i18n:check`。比对相对路径与 key 集合，不一致直接失败（已接入 CI）；另会列出仍有硬编码中文的非注释行（仅提示不影响结果）。
- **没有 `menu` 命名空间**：菜单 / 权限节点标题由后端按请求语言下发（见 [08-后端开发规范 §十三](08-后端开发规范.md#十三国际化i18n)），前端不做二次翻译。

### 12.2 三个必守点

**① 列头 / 校验规则 / 选项数组要 `computed` 化**

`ArtTableColumn[]`、`FormRules`、`el-radio` 的选项数组若写成 setup 顶层的普通对象，切换语言时不会重新求值（表头、校验提示仍是旧语言）：

```ts
const columns = computed<ArtTableColumn[]>(() => [
  { prop: 'name', label: t('post.nameLabel'), minWidth: 150 },
])

const rules = computed<FormRules>(() => ({
  name: [{ required: true, message: t('post.nameRequired'), trigger: 'blur' }],
}))
```

**② 带变量的文案整句进语言包，不要用 `t()` 拼串**

中英语序不同，拼出来的句子必然有一边别扭：

```ts
// 不要：「{label}回收站」到英文会变成「Post 回收站」
t('table.recycle', { label })

// 要：整句各自成句（zh：「{label}回收站」/ en：「{label} recycle bin」）
t('table.enterRecycle', { label })
```

**③ 路由 / 标签页标题用 `translateTitle()`**

标题有两个来源：前端 i18n key（静态路由的 `route.dashboard`）与后端已翻译好的成品文本（动态菜单标题）。`src/locales/title.ts` 的 `translateTitle()` 用 `i18n.global.te()` 探测区分：命中 key 才翻译，否则原样返回 —— **不能让后端下发的自定义菜单名被顶成 key 原文**。`document.title` 统一走 `router` 导出的 `syncDocumentTitle()`。

> 切换语言时 `ArtSettingsDrawer` 会 `reloadMenus()` 重新拉菜单并刷新 `document.title`；标签页存的是 i18n key，无需重建。

请求头：`api/request.ts` 自动带 `Accept-Language: <当前语言>`，后端 `I18n::locale()` 按
`?lang=` → `Accept-Language` → 配置默认 的顺序解析，接口报错文案因此也是多语言的。

> ⚠️ **不要**在 `setLocale()` 之外直接写 `localStorage`，也不要把后台下发的默认值当成用户偏好存进去。

## 十三、前端测试怎么写

引入 Vitest 3 + `@vue/test-utils`（jsdom），配置在 `vitest.config.ts`，用例放在与源码同级的
`__tests__/*.spec.ts`。**刻意不合并 `vite.config.ts`**：单元测试的对象是纯函数与 composable，
不需要编译 Vue 单文件组件、也不需要跑 Tailwind。

### 13.1 什么该测、什么不测

| 该测（有回归价值） | 不测（收益低 / 成本高） |
|---|---|
| 纯函数工具：`utils/cron.ts`、`utils/password.ts`、`utils/richText.ts`、`utils/auth.ts` | 页面组件 `src/pages/**`：其正确性靠构建 + 人工验收 |
| composable：`useTable` 的条件序列化 / 持久化 / 分页 | 浏览器 API 薄封装：`utils/{crypto,progress,theme,icon}.ts` |
| store：`stores/user.ts` 的权限与令牌流转 | 依赖组件渲染 / 路由上下文的 `stores/{menu,notice,setting,worktab}.ts` |
| 请求拦截器：`api/request.ts` 的解包 / 续期 / 401 / 429 分支 | 前端 E2E（Playwright）——已在更新日志「明确不做」中定案 |

覆盖率**只统计上表左列的 7 个模块**（`vitest.config.ts` 的 `CORE_MODULES` 显式列出，不用通配），
阈值 80% / 80% / 80% / 70%。**新增核心模块时必须同时加进 `CORE_MODULES` 并补用例**，
否则等于没有回归保护。

> 为什么 `include` 不用 `src/utils/**` 这种通配：那样分母里会混进一堆「只是在断言框架行为」的文件，
> 数字难看又没有意义；宁可用显式清单 + 约定把范围说清楚。
>
> ⚠️ 配置里的 `coverage.all: false` 是**必须**的：Windows 上 `include` 的路径形式（盘符大写）
> 与模块加载记录（盘符小写）对不上，`all: true` 会给每个文件再补一行恒为 0% 的重复统计，
> 本地 `test:coverage` 永远失败而 CI（Linux）通过，属于假信号。

### 13.2 写法约定

- **显式导入** `import { describe, expect, it, vi } from 'vitest'`，不开 globals（避免污染全局、也让编辑器能跳转）。
- `describe` / `it` 的标题写**行为与原因**（中文），不要写 `should work` 这类空话：
  例：`it('日与周同时限定按 AND 处理（不是 OR）')`。
- 涉及时间 / 时区的断言**不要写死时间戳**：用 `new Date(2026, 0, 15, 10, 30, 0)` 构造本地时间再换算，
  否则换个时区就红。
- **不要 mock axios**，而是给真实实例换 adapter（`instance.defaults.adapter = …`）：
  拦截器是 axios 的组成部分，只有跑在真实实例上才验证得到解包 / 续期 / 401 这些真正会出问题的分支。
- `localStorage` 在每个用例前 `clear()`；`vi.mock` 的工厂里引用外部变量要用 `vi.hoisted()`（否则命中 TDZ）。
- 组件测试用 `@vue/test-utils` 的 `mount`；**`provide` 与 `inject` 不能写在同一个组件里**
  （Vue 的 `inject` 只沿 `instance.parent.provides` 向上找），父组件调 composable、子组件 `inject`。

### 13.3 命令

```bash
cd frontend
npm run test           # 跑一遍（本地）
npm run test:watch     # 监听模式
npm run test:coverage  # 带覆盖率，CI 用（会卡 CORE_MODULES 的阈值）
```

CI（`.github/workflows/frontend.yml`）在 `build` **之前**跑 `npm run test:coverage`：
类型错误与逻辑回归在这里就拦下，不必等一次完整构建。
