# 前端开发规范

> 面向页面开发：工程结构、请求约定、路由与权限、状态管理、主题与国际化、测试与检查。

---

## 一、技术栈与命令

| 命令 | 作用 |
|------|------|
| `npm run dev` | 开发服务器（5173） |
| `npm run build` | `vue-tsc` 类型检查 + Vite 构建 |
| `npm run lint` | ESLint |
| `npm run format` | Prettier |
| `npm run test` | Vitest 单测 |
| `npm run i18n:check` | 校验中英文文案键一致 |

技术栈：Vue 3.5、TypeScript 5、Vite 5、Element Plus 2、Tailwind CSS 4、Pinia、Vue Router 4、ECharts 6。

## 二、目录职责

| 目录 | 放什么 | 不放什么 |
|------|--------|----------|
| `api/` | 接口函数、请求/响应类型 | 业务状态、页面逻辑 |

## 三、请求约定

统一使用 `src/api/request.ts`，不要在页面里直接 `axios`。

```ts
export function listUsers(params: UserQuery) {
  return http.get<PageResult<UserOut>>('/user', params)
}
```

### 3.1 响应解包

- 后端返回 `{ code, message, data, ... }`。
- 拦截器在 `code === 0` 时直接返回 `data`，所以 `api` 函数的泛型写 `data` 的类型。
- 非 0 会弹错误提示并 reject，页面只需处理成功分支和 `finally`。

### 3.2 错误提示

- 401：清除令牌、重置动态路由、跳转登录。
- 其它错误：自动拼接操作 ID，便于到日志页检索。
- 页面不要重复 `ElMessage.error`，避免一次失败弹两次。

### 3.3 下载

```ts
await downloadFile('/log/export', params, 'logs.csv')
```

- 复用同一 axios 实例，自动带鉴权与续期。
- 文件名优先取 `Content-Disposition`。

### 3.4 链路头

每次请求自动带：

| 头 | 来源 |
|----|------|
| `Authorization` | `localStorage.cccms_token` |
| `Accept-Language` | 当前语言 |
| `X-Action-Id` | 一次页面动作 |
| `X-Session-Id` | 一次浏览器会话 |

写请求会开启新的 `action_id`，读请求复用当前动作。

## 四、路由与权限

### 4.1 静态路由

- `/login`、`/dashboard`、`/profile`、`/403`、`404` 兜底为静态路由。
- 业务页面由菜单表动态注册。

### 4.2 动态路由

```ts
const pageModules = import.meta.glob('/src/pages/**/*.vue')
const component = pageModules[`/src/pages/${menu.component}.vue`]
```

- 只有 `type=2` 且 `component` 非空的菜单生成路由。
- 路由 `name` 优先用 `menu.node`，避免重名。
- 登出/换账号必须 `resetDynamicRoutes()`，否则会残留上一账号的菜单。

### 4.3 新增页面

1. 在 `pages/cccms/<模块>/index.vue` 创建页面。
2. 在菜单管理新增菜单，`component` 填 `cccms/<模块>/index`。
3. 给角色授权对应权限节点。
4. 页面按钮加 `v-auth`。

> ⚠️ **陷阱**：刷新时首帧会先匹配 404 兜底，动态路由注册后必须按 `path` 重新导航；不要用 `{ ...to, replace: true }`，否则 `name` 会把导航解析回 404。

## 五、状态管理

| Store | 职责 |
|-------|------|
| `user` | 令牌、资料、权限集合、`hasAuth()` |
| `menu` | 菜单树、动态路由数据 |
| `app` | 站点配置、侧边栏折叠、语言 |
| `worktab` | 多页签 |
| `notice` | 未读消息、轮询 |
| `setting` | 主题、布局、水印 |
| `exportTask` | 导出任务轮询 |

约定：

- 只把跨页面共享的状态放 store。
- 页面局部状态用 `ref` / `reactive`。
- store 不直接操作 DOM，不弹全局提示（除非是全局流程，如 401）。

## 六、组件使用

通用组件文档见 [10-前端组件参考](10-前端组件参考.md)。

- 列表页统一用 `ArtTable` + `useTable`。
- 回收站开关用 `RecycleToggle` + `useRecycle`。
- 分类树用 `useCategoryTree`。
- 富文本用 `ArtRichEditor`，提交前经 `utils/richText.ts` 清洗。
- 图标用 `ArtIcon` + RemixIcon 类名。

## 七、样式与主题

- Tailwind CSS 4 负责布局与间距；Element Plus 负责表单与表格。
- 颜色、圆角、阴影使用设计 token（CSS 变量），不要在页面写死十六进制。
- 主题切换由 `utils/theme.ts` 写入 `data-theme`，暗色模式通过 CSS 变量覆盖。
- 页面样式加 `scoped`；需要覆盖 Element Plus 时用 `:deep()`。

---

## 八、国际化

- 文案统一放 `locales/zh-CN.ts` / `locales/en-US.ts`。
- 页面用 `t('key')`，不要拼接中英文。
- 后端下发的菜单标题视为已翻译文本，通过 `translateTitle()` 兜底。
- 新增文案后执行 `npm run i18n:check`。

---

## 九、类型规范

- 接口出入参类型放 `api/types.ts` 或对应 `api/*.ts`。
- 禁止 `any`；确需未知类型用 `unknown` 再收窄。
- 组件 `defineProps` / `defineEmits` 使用类型声明。
- 后端字段名保持 snake_case，前端不做自动驼峰转换，避免与接口文档不一致。

## 十一、常见约定

- 页面文件名统一 `index.vue`；子组件放同目录 `components/`。
- 事件命名用 `kebab-case`，如 `@row-click`。
- 请求参数去掉空字符串与 `undefined`，避免后端收到 `""` 当有效筛选。
- 时间展示统一走格式化工具，不直接 `toLocaleString()`。
- 删除/批量操作必须二次确认，并展示影响条数。
- 长列表使用分页，不做前端全量过滤（数据权限在后端）。
