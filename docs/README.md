## 二、编写规范

### 2.1 文件与命名

- 文件名用「两位序号 + 中文标题」：`NN-标题.md`，序号决定阅读顺序；插入新章节时顺延后续序号，不出现 `04-1`。
- 标题与文件名一致；单个文件超过约 800 行时按主题拆分。
- 交叉引用用相对链接并锚点到小节，如 `[数据权限](06-数据权限.md#二角色级预置范围sys_roledata_scope)`。

### 2.2 结构

```markdown
# 标题

> 一句话导读（本文讲什么、适合谁看）

---

## 一、二级标题（中文数字）
### 1.1 三级标题
```

- 一级标题只有文档标题一个，正文从 `## 一、…` 开始。
- 关键结论用 `> **提示**：` / `> ⚠️ **注意**：` 强调；「为什么这样设计」单独成小节，不混在步骤里。
- 代码块必须标注语言（`php` / `bash` / `sql` / `ts` / `vue`）；命令统一写 `bash` 块，路径以仓库根为基准。
- 枚举型内容（参数、常量、字段、接口）一律用表格。
- 不粘贴大段源码：只贴签名与关键几行，并注明文件路径。
- 流程图优先用 ASCII / Mermaid，避免二进制图片。

### 2.3 写作约定

- **统一术语**：插件（plugin）、控制器（Controller）、逻辑层（Logic）、模型（Model）、权限节点（slug）、受控表、预设基线、`fail-closed`。首次出现给中英文对照，之后只用中文。
- **只写现状**：未实现的能力写进 [开发计划](开发计划.md) 或用 `> ⚠️ 本能力尚未实现` 标注；已完成的能力写进 [更新日志](更新日志.md)，正文不再复述「本次新增了……」。
- **不留验证过程**：测试用例数量、回归结论、临时踩坑记录属于更新日志或代码注释，不写进正文。
- **不重复机制**：同一机制只在一篇里讲，其余位置给链接。
- **文档随代码改**：改动机制、接口、命令、配置时，同一次提交内更新对应文档与更新日志。

### 2.4 状态标记

| 标记 | 含义 |
|------|------|
| `> 待补充：…` | 已知缺口 |
| `> 已废弃：…` | 历史机制，仅为兼容保留 |
| `> ⚠️ 陷阱：…` | 极易踩坑、必须注意 |
