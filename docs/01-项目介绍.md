# 项目介绍

> 面向技术选型与首次接触者：CCCMS 是什么、由哪些部分组成、解决了中后台系统的哪些共性问题。

---

## 一、定位

CCCMS 是一套**可直接作为企业级项目起点**的中后台管理系统，覆盖组织、权限、租户、配置、日志、附件、通知、定时任务等基础能力，并提供可复用的前端交互框架。

它不绑定具体业务，而是把中后台最常见的「安全默认值」做对：

| 目标 | 落地方式 |
|------|----------|
| 不漏权限 | 路由必须声明 `@permission` / `@no_auth` / `@no_login`，漏写启动失败 |
| 不串租户 | 所有业务表带 `tenant_id`，查询由服务层显式收口 |
| 不越权取数 | 角色 5 档数据范围 + 行级/字段级规则，统一 `apply_scope()` |
| 可追溯 | 操作日志同表记录登录与业务动作，`trace_id / action_id / session_id` 三层链路 |
| 可运营 | 平台租户统一管理租户、菜单、定时任务与系统配置 |

## 二、技术栈

| 层 | 技术 |
|----|------|
| 后端 | Python 3.12+、FastAPI、SQLAlchemy 2.0（async）、asyncmy、Pydantic v2、Redis、croniter、prometheus-client |
| 前端 | Vue 3.5、Vite 5、TypeScript 5、Element Plus 2、Tailwind CSS 4、Pinia、Vue Router 4、ECharts 6、RemixIcon |
| 数据库 | MySQL 8（`utf8mb4`，支持生成列与 JSON 列） |
| 缓存 | Redis 6+（令牌、会话、配置缓存、限流、调度锁） |
| 存储 | 本地磁盘（`CCCMS_STORAGE_DRIVER=local`）；未实现的远端驱动会在启动时直接拒绝，不会静默降级 |
| 工程化 | uv、Ruff、mypy、pytest、ESLint、Prettier、Vitest |

## 三、系统组成

```text
浏览器
  │  Vue 3 SPA（hash 路由 + 动态菜单）
  ▼
Nginx / Vite dev server
  ├─ /            → 前端静态资源
  ├─ /api         → FastAPI
  └─ /storage     → FastAPI（登录 + 数据范围，不可见与不存在同为 404）
                     │
                     ▼
                FastAPI 应用
                ├─ 中间件：请求 ID / 租户识别 / CSRF / 操作日志 / 安全响应头
                ├─ 路由层 api：权限声明 + 参数校验
                ├─ 业务层 services：事务、数据权限、领域规则
                ├─ 模型层 models：租户 / 软删 / 时间戳 mixin
                └─ 基础设施 core：JWT、RBAC、Redis、审计、导出、配置
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
        MySQL 8               Redis
```

独立进程 `cccms.scheduler` 扫描 `sys_crontab` 执行定时任务，使用 Redis 锁避免多实例重复执行。

## 四、功能总览

### 4.1 身份与权限

- 账号密码登录、图形验证码、登录失败限流。
- JWT 双通道：`Authorization: Bearer` 与 HttpOnly Cookie；剩余有效期不足阈值时下发续期令牌。
- RBAC：用户 → 角色 → 权限节点；角色支持父子继承，权限取并集。
- 数据范围：全部 / 本部门及以下 / 本部门 / 仅本人 / 自定义，多角色取**最严**档位（`merge_data_scope` 取 max）。
- 行级与字段级规则：按受控表配置条件、隐藏、只读、脱敏、加密动作。
- 按钮级权限：前端 `v-auth` 控制显隐，后端权限依赖兜底。

详见 [05-鉴权与权限](05-鉴权与权限.md) 与 [06-数据权限](06-数据权限.md)。

### 4.2 多租户

- 单库共享表 + `tenant_id` 硬隔离。
- 租户可通过域名绑定识别，也可在登录页手动选择；超级管理员可显式切换租户。
- 平台租户（`is_platform=1`）独占租户管理、全局菜单维护等能力。
- 全局配置允许 `tenant_id` 为空作为默认值，租户保存时自动生成覆盖行。

详见 [18-平台与运维](18-平台与运维.md)。

### 4.3 组织与账号

- 无限级部门、用户多部门、岗位与用户关联。
- 用户支持批量启停、批量删除、批量分配角色/部门/岗位。
- 角色支持复制、授权节点、设置数据范围与自定义部门。
- 回收站统一处理软删除数据的还原与彻底删除。

### 4.4 系统能力

| 模块 | 能力 |
|------|------|
| 菜单 | 目录 / 菜单 / 按钮三类节点，平台统一维护，登录后按角色下发 |
| 字典 | 分类树 + 字典类型 + 字典数据，前端按类型取选项 |
| 配置 | 分组键值配置，支持文本、数字、布尔、JSON、密钥等类型 |
| 附件 | 分类树、普通上传、分片上传、秒传、移动、软删除 |
| 导出 | 后台任务生成 CSV（进程内并发受 `export_max_concurrency` 限制），任务记录可下载、到期清理 |
| 通知 | 站内公告、定向投放、已读回执、未读数 |
| 定时任务 | 六段 Cron、立即执行、执行日志、失败重试、重叠保护 |
| 代码生成 | 读取表结构，预览并生成后端模型/服务/路由与前端页面骨架 |
| 在线升级 | 仅本地开发启用，固定 git 命令白名单 |

### 4.5 日志与可观测

- 登录日志与业务操作日志同表（`sys_log`），按 `event_type` 区分。
- 三层链路：`trace_id`（一次请求）、`action_id`（一次页面动作）、`session_id`（一次浏览器会话）。
- 审计哈希链：按批次封存日志摘要，支持完整性校验。
- `/ping` 存活、`/healthz` 就绪、`/metrics` Prometheus 指标（默认仅本机可读）。

## 五、适用与不适用

**适用**：

- 需要多租户 SaaS 后台、企业内部管理平台、运营后台。
- 团队希望从一套已经处理好权限/租户/日志的骨架上开始业务开发。

**不适用**：

- 纯公网内容站点、强实时协作、强事务金融核心。
- 需要跨库分片或海量写入的场景（当前为单库共享表模型）。
