## 一、`ArtTable` — 列表页核心表格

文件：`src/components/core/ArtTable.vue`

集成了工具栏、搜索卡片、列头筛选、表格、分页、列设置（显隐 / 排序 / 汇总展示）、**列头服务端排序**、回收站模式的通用表格。

| Prop | 类型 | 默认 | 说明 |

| `selection` | `boolean` | `false` | 是否显示多选列 |
| `pagination` | `boolean` | `true` | 是否显示分页（树表常设 `false`） |

### 1.5 特性

- **列设置弹窗（工具栏齿轮图标）**：列出**全部列**，支持拖拽排序、逐列显隐、逐列「排序」开关、逐列「隐私」、逐列「汇总展示」，
  顶部另有整表的「斑马纹」开关（虚拟滚动模式下用奇数行底色模拟）。改动先存草稿，点「确定」才生效并持久化，「取消」丢弃。
  `lockVisible` 列（操作列等）不可隐藏、不可拖动、不可遮罩。
  - 列显隐：`localStorage['cccms_table_hidden:v2:{storageId}']`（列默认全部显示）；
  - 列顺序：`localStorage['cccms_table_order:v1:{storageId}']`（页面后续新增的列自动追加到末尾）；
  - 列头排序：`localStorage['cccms_table_sortable:v1:{storageId}']`（记录**关掉排序**的列；空 = 全部开启）。
    只有页面声明 `sortable: 'custom'` 的列能勾选，计算列置灰；
  - 隐私遮罩：`localStorage['cccms_table_privacy:v2:{storageId}']`（记录**开启遮罩**的列；无记录时用列的 `privacy` 声明作默认值）。
    页面可在列定义里写 `privacy: true` 默认开启；用户勾过隐私开关后以本地记录为准（`v2` 前缀用于让新默认值对老缓存一次性生效）。
    开启后单元格内容默认隐藏、只显示小眼睛图标，鼠标悬停该单元格才显示真实内容；仅影响前端展示，不改变接口返回；
  - 汇总展示：`localStorage['cccms_table_summary:v1:{storageId}']`（记录**不展示**的列；空 = 全部展示）。
    汇总值仍由页面的 `summaryMethod` / `summaryData` 提供，组件只做「显示 / 不显示」的过滤；
    一列都没勾时整个汇总行收起。
  - 弹窗左下角三个重置入口：「重置列宽」只清掉拖拽过的列宽；「重置列」恢复默认顺序 + 全部显示 + 全部排序 + 回到列声明的默认隐私 + 全部汇总（不动列宽）；
    「全部重置」= 两者都做。三者都在点「确定」时才落库，点「取消」不影响现有设置。
- **列头服务端排序**：列声明 `sortable: 'custom'` 后，表头出现排序箭头；
  页面用 `useTable` 时 `ArtTable` 会自动接管 `sort-change` —— 写排序状态 → 回第 1 页 → 请求带上
  `sort={prop}&order=asc|desc`，**页面零接线**；排序状态与筛选条件一起被「筛选方案」记忆。
  - 只给**有实际价值**的列开排序：时间列（创建 / 登录 / 执行 / 到期）、数值列（耗时 / 大小 / 阅读量）、排序号；
    用户名、昵称、手机号、邮箱、标题、编码、IP 等标识类列**不提供**排序 —— 排了也帮不上找数据；
  - 排序只影响接口返回顺序，前端**不对当前页重排**（分页在服务端，本地排序翻页就会露馅）；
  - 列设置里关掉某列的排序、或隐藏当前排序列时，会自动清空排序回接口默认顺序；
  - 后端必须按白名单排序，见 [08-后端开发规范 §七](08-后端开发规范.md#七数据访问规则)；
  - 虚拟滚动（`virtual`）与树表暂不支持列头排序。
- **搜索卡片（表格上方）**：搜索项由各列的 `filter` 配置**自动生成**，页面零接线，改列即改搜索项。
  - 与表格卡片同级，单独一张卡放在表格**上方**；没有 `filter` 列时整卡不渲染。
  - 控件按 `filter.type` 生成：`text` → 输入框、`enum` → 多选下拉（折叠标签）、`date` → 日期范围选择器。
  - 与列头筛选**共用同一份 `query`**（同样经 `readFilter` / `writeFilters` 读写），因此两边天然联动：
    列头改了顶部的值跟着变，顶部查询后列头漏斗也高亮，条件同样被「筛选方案」持久化。
  - 草稿与列头弹层分开保存，**输入过程不发请求**；点「查询」把全部筛选字段一次性写回（只触发一次重新查询），
    「重置」清空全部筛选字段。回车即查询。
  - 搜索项超过 3 个（`SEARCH_COLLAPSE_LIMIT`）时默认折叠，只显示前 3 项，右侧给「展开 / 收起」入口
    （`table.searchExpand` / `table.searchCollapse`）。
- **列头筛选**：给列加 `filter` 配置后，该列表头出现筛选入口：
  - 列头用 `#header` 插槽渲染「标题 + 漏斗图标」，**漏斗图标固定在列头最右侧**（标题对齐跟随列的 `align`）；
    有生效条件时图标高亮为主题色。
  - `type: 'enum'` 弹层内是**复选下拉框**（`el-select multiple`，折叠标签 + 可清空），多值按逗号拼接；
  - `type: 'text'` 弹层内是输入框，做模糊查询，回车或点「筛选」提交；
  - `type: 'date'` 弹层内是**时间范围**选择器（`datetimerange`，值格式 `YYYY-MM-DD HH:mm:ss`，
    `defaultTime` 让手动选择默认落在 `00:00:00 ~ 23:59:59`），起止分别写入 `startKey` / `endKey`
    （默认 `start` / `end`）；内置 7 个常用区间快捷项：今天 / 昨天 / 最近 3 天 / 最近 7 天 /
    最近 30 天 / 本月 / 上月。同一页有多个时间条件时**务必各配一组独立的 `startKey` / `endKey`**，
    否则会互相覆盖（如在线用户的 `login_start` / `login_end`、公告的 `publish_start` / `publish_end`）；
  - 弹层底部按规范**重置在左、筛选在右**，均为按钮形式（筛选为主题色 `primary`）；
  - 不使用 el-table 原生 `filters`（其面板为纯文本按钮，且无法把入口固定在列头右侧），真正的过滤都在后端做；
  - 筛选值统一写 `query`，经 `readFilter` / `writeFilter` 读写，**自动被「筛选方案」持久化**；
    服务端分页场景 `writeFilter` 自动回第 1 页并重新查询。
  - **页面不要再手写搜索表单**：顶部搜索卡片已由列的 `filter` 配置自动生成，`ArtTable` 不提供
    `#search` 插槽与 `search` / `reset` emit。
- **列宽拖拽记忆**：拖动表头后按页面持久化到 `localStorage['cccms_table_width:{storageId}']`；
  已保存的宽度**优先于**页面声明的 `width`（用户意图优先）；「列设置 → 重置列宽 / 全部重置」会清掉列宽（确定后生效）。
- 用可见列指纹作 `:key` 强制重挂载表格（解决列设置后布局不刷新）。
- **回收站模式**：工具栏左侧换成「回收站模式」标签 + 还原 / 彻底删除按钮（`v-auth` 校验 `cccms:recycle:restore` / `cccms:recycle:delete`）；`slot: 'action'` 列被统一替换为操作列。
- 响应式分页：窄屏自动切换为 `prev, pager, next`。
- 刻意**不开** `reserve-selection`（避免跨刷新残留脏勾选）。
- **批量操作**：开启 `selection` 的页面在工具栏放一个 `el-dropdown`（`批量操作（N）`，
  `:disabled="selected.length === 0"`），通过 `@selection-change` 维护 `selected`。
  每个 `el-dropdown-item` 各自挂 `v-auth`（如 `cccms:user:batch_status` / `batch_delete` / `batch_assign`）。
  后端返回 `{affected, skipped[]}`，**有跳过时提示降级为 `ElMessage.warning` 并说明原因**
  （越权 / 受保护 / 不存在），避免「点了没反应」的困惑。参考实现：
  `pages/cccms/user/index.vue`、`pages/cccms/post/index.vue`、`pages/cccms/dict/index.vue`。
  注意：`ArtTable` **必须显式传 `row-key="id"`**，否则勾选状态在数据刷新后错乱。
- **虚拟滚动（`virtual`）**：仅对**非树形、非回收站**的普通列表生效，命中 `tree` / `recycle` 时自动回退
  普通 `el-table`（行为完全不变），因此**业务页零改动**——只有确实存在「单页数千行以上」的列表才需要
  显式加 `virtual`。开启后内部改用 `el-auto-resizer` + `el-table-v2`：
  - 列的 `width` 为 `el-table-v2` 必填项，未声明 `width` / `minWidth` 的列按 `150px` 兜底；
    拖拽记忆的列宽（`cccms_table_width:*`）依然优先生效。
  - 列 `slot` 通过 `cellRenderer` 重建，作用域仍为 `{ row, index, value }`，页面插槽写法不变。
  - `selection` 由组件内部用 `ElCheckbox` 自绘表头全选 / 行勾选，并照常派发 `selection-change`，
    翻页或刷新后自动剔除已不在当前数据里的勾选（与普通表格不开 `reserve-selection` 的语义一致）。
  - `fixed: 'right'`（操作列）会映射为 `el-table-v2` 的右固定列，需保持为列数组的最后一项（现有页面均满足）。
  - 分页、列设置、列宽记忆、筛选方案等工具栏能力与普通模式共用，无需区分。

> 列宽持久化由组件内部处理（监听 el-table 的 `header-dragend`），页面无需任何额外代码。

## 九、`useTable` — 列表页通用逻辑

文件：`src/composables/useTable.ts`

```ts
interface UseTableOptions<T, Q extends object> {
  api: (params: Record<string, unknown>) => Promise<PageResult<unknown>>
  initialQuery?: Q
  pageSize?: number       // 默认取后台配置 ui.page_size
  immediate?: boolean     // 默认 true，setup 阶段立即加载
  transform?: (list: T[]) => T[]
}

function useTable<T, Q extends object>(options: UseTableOptions<T, Q>)
```

返回值：

| 返回 | 说明 |
|------|------|
| `list` | 列表数据 |
| `loading` | 加载状态（**至少可见 300ms**，避免一闪而过） |
| `total` / `page` / `limit` | 分页 |
| `query` | 查询条件对象（响应式） |
| `selection` | 当前勾选行 |
| `load()` | 加载（参数为 `{ ...query, page, limit }`） |
| `search()` | 重置到第 1 页再加载 |
| `reset()` | 恢复 `initialQuery` 并回第 1 页 |
| `onPageChange` / `onLimitChange` | 分页事件处理 |
| `onSelectionChange` | 多选变化处理 |

**筛选方案持久化（页面零配置）**：

- 条件（含 `limit`，不含 `page`）一变就自动写入 `localStorage['cccms_table_filter:{storageId}']`；下次进入同页面**自动回填**（不自动提交，避免误触发请求）。
- 命名方案整体存 `localStorage['cccms_table_filter_scheme:{storageId}']`；`storageId` 默认取当前路由 path，可经 `storageKey` 覆盖。
- 回填只保留 `initialQuery` 声明过的字段（白名单），避免旧版本遗留字段被重新发给接口；页面未声明 `initialQuery` 时退化为原样回填。
- 这些能力**不经 `useTable` 返回值暴露**，而是通过 `provide(TABLE_FILTER_KEY, …)` 供 `ArtTable` 工具栏的「筛选方案」入口消费：

| 上下文成员 | 说明 |
|------|------|
| `key` | 当前页面的 storageId |
| `hasSaved()` | 是否存在上次保存的条件（决定是否显示「清空记忆」） |
| `clearSaved()` | 清空自动记忆的条件 |
| `listSchemes()` | 已保存方案名列表（`string[]`） |
| `saveScheme(name)` | 以 `name` 保存当前条件（同名覆盖） |
| `applyScheme(name)` | 应用方案（回填并回到第 1 页重新加载） |
| `removeScheme(name)` | 删除方案 |
| `readFilter(prop)` | 读取该字段当前值（列头筛选与顶部搜索卡片共用） |
| `writeFilter(prop, value)` | 写入该字段并重新查询（树表场景由 computed 重算） |
| `writeFilters(fields)` | 批量写入多个字段，只触发一次重新查询（顶部搜索卡片的「查询 / 重置」用它） |

**树表等纯前端过滤场景用 `useTableFilter`**：

`menu` / `dept` 这类树表**一次性拉全量、靠 computed 过滤**，没有分页与请求，用不上 `useTable`。
`useTable` 把筛选方案内核抽成 `useTableFilter()` 供它们复用（同一份 `localStorage` 键与同一个
`TABLE_FILTER_KEY` 入口，所以 `ArtTable` 工具栏的「筛选方案」照常出现）：

```ts
// 只返回条件对象与重置函数，不涉及分页 / 请求
const { query, reset } = useTableFilter<Query>({ initialQuery: { name: '', leader: '' } })
```

- 条件变化后由页面自己的 `computed` 响应（无需重新请求）；应用命名方案同理。
- 条件同样会自动记忆、自动回填，字段白名单规则与 `useTable` 一致。
- 树形过滤建议：**命中节点保留整棵子树**；未命中但子孙命中的节点保留自身、`children` 换成过滤结果。

**列显隐**：

- 列**默认全部显示**；页面可用组件的 `defaultHidden` 给一组初始隐藏列（用户动过列设置后以本地记录为准）。
- 用户在工具栏「列设置」弹窗里可**手动**隐藏 / 恢复列、拖拽排序、开关列头排序、开关隐私遮罩、勾选「汇总展示」，点「确定」生效；
  左下角提供「重置列宽 / 重置列 / 全部重置」三个入口。
- 隐藏结果存 `localStorage['cccms_table_hidden:v2:{storageId}']`（前缀带版本号，改动默认显隐策略时升版本即可让旧缓存一次性失效），
  顺序、排序、隐私与汇总展示分别存 `cccms_table_order:v1:` / `cccms_table_sortable:v1:` /
  `cccms_table_privacy:v2:` / `cccms_table_summary:v1:`。

## 十、`useRecycle` — 回收站

文件：`src/composables/useRecycle.ts`

```ts
interface RecycleOptions {
  reload: () => void       // 切换模式 / 操作完成后重新加载
  ids?: () => number[]     // 批量操作用的当前勾选 id
  clear?: () => void       // 清空勾选
}

function useRecycle(type: string, options: RecycleOptions)
// → { recycle, toggle, onRestore, onForceDelete }
```

- `type` 是后端 `RecycleLogic` 注册表里的类型（`user` / `role` / `dept` / `post` / `dict_type` / `dict_data` / `category` / `crontab` / `data_rule` / `file` / `menu`）。
- `onRestore(row?)` / `onForceDelete(row?)`：不传 `row` 用 `ids?.()`（批量），传 `row` 用其 id；均二次确认后调接口，再 `clear` + `reload`。

> ⚠️ **必须在 `useTable` 之前调用**（列表闭包在 setup 阶段就会执行一次）。三处接线见 [07-功能模块 §十六](07-功能模块.md#十六回收站recycle)。

## 十二、类型 `ArtTableColumn`

文件：`src/types/table.ts`

```ts
export interface ArtTableColumn {
  prop: string
  label: string
  width?: number | string
  minWidth?: number | string
  fixed?: boolean | 'left' | 'right'
  align?: 'left' | 'center' | 'right'
  sortable?: boolean | 'custom'     // 'custom' = 服务端排序（useTable 页面自动接管，无需监听）
  slot?: string                     // 具名插槽名 <template #xxx="{ row, value }">
  lockVisible?: boolean             // 锁定可见（不可隐藏）
  privacy?: boolean                 // 默认开启隐私遮罩（仅初始值；用户调过隐私后以本地记录为准）
  showOverflowTooltip?: boolean
  filter?: ArtTableColumnFilter     // 筛选配置：列表头出现筛选入口，同时自动生成顶部搜索项
}

export interface ArtTableColumnFilter {
  type: 'enum' | 'text' | 'date'    // enum：复选下拉；text：模糊查询输入框；date：时间范围选择器（datetimerange）
  options?: ArtTableFilterOption[]  // type='enum' 时必填
  queryKey?: string                 // 写入 query 的字段名，默认取列的 prop
  placeholder?: string              // type='text' 时的输入框占位文案
  startKey?: string                 // type='date' 时的起始字段名，默认 start
  endKey?: string                   // type='date' 时的结束字段名，默认 end
}
```

筛选的读写经 `TABLE_FILTER_KEY` 上下文的 `readFilter(prop)` / `writeFilter(prop, value)` /
`writeFilters(fields)` 落到页面 `query` 上（服务端分页场景会自动回第 1 页并重新请求，树表场景由 computed 重算）。
列头筛选与顶部搜索卡片**同源**：搜索项就是带 `filter` 的列，两边读写同一份 `query`。

另重导出 `PageResult<T>`（`{ total, list }`）。
