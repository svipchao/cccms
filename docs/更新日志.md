# 更新日志

> 只记录**已交付的变更**与**已决策不做的事项**。
> 计划中的工作见 [开发计划](开发计划.md)；机制与用法见对应专题文档（索引见 [README](README.md)）。
> **不设版本号、不区分已发布 / 未发布**：按日期倒序，前后端分列。
> 每条固定三段：`【分类】功能名称` → `问题内容` → `修复内容`；分类只有 `安全 / 新增 / 变更 / 修复 / 移除 / 性能与可观测 / 工程化 / 文档` 八类。
> 已决策不做的事项集中在文末 [附录 · 明确不做](#附录--明确不做)。

## 分类口径

| 分类 | 用于 | 问题内容写什么 | 修复内容写什么 |
|------|------|----------------|----------------|
| 安全 | 漏洞、暴露面、权限收口 | 原风险与触发条件 | 拦截点、生效前提 |
| 新增 | 新能力 / 新接口 / 新页面 | 原来缺什么、痛在哪 | 落地形态与边界 |
| 变更 | 既有行为、结构、默认值调整 | 原行为 | 新行为 + 存量兼容动作 |
| 修复 | 缺陷 | 现象 + 根因 | 改了哪几处 |
| 移除 | 下线能力 / 删代码 | 为什么留不住 | 删了什么 + 存量怎么清 |
| 性能与可观测 | 缓存、索引、指标、探活 | 原瓶颈或盲区 | 实现要点 |
| 工程化 | CI、静态分析、测试、构建、脚本 | 原缺口 | 接入方式 |
| 文档 | docs 与代码同步 | 原漂移点 | 补了哪篇 |

## 2026-10-23

### 后端

- **【新增】结构迁移机制（复核 A1 / G1）**
  - 问题内容：`db/schema.sql` 全是 `CREATE TABLE IF NOT EXISTS`，对已存在的表不做任何 `ALTER`，也没有任何地方记录「这台库到哪一版」——新增列 / 索引 / 默认值调整只能靠人记得在每台库上手工执行，漏了不报错。
  - 新增内容：`support/Migrator.php` + `sys_schema_migration`（`version` 主键、`checksum`、`batch`）+ `plugin/*/db/migrations/*.sql`。文件名即版本号（`YYYYMMDD_HHMMSS_描述`），全局排序、按版本只执行一次；已执行文件被改动只报「漂移」告警、不重跑。`db-upgrade` 顺序改为「核心 schema → 插件 schema → 迁移 → 核心 seed → 插件 seed」。`SqlFileRunner` 新增迁移模式：「重复列 / 重复索引」按已生效跳过，因此 `schema.sql` 与迁移写同一份结构是安全的。
  - 首个迁移：`20261023_120000_data_rule_index.sql` 给 `sys_data_rule` 补 `idx_table_field(table_name, field)`（规则编译在每个请求上跑）。
  - 验证：本机库连续执行两次 `cccms:db-upgrade`，第一次执行 1 个版本、第二次「已是最新」；`phpstan` 0 错误。

- **【修复】字典值与数据规则不允许重复（复核 A8）**
  - 问题内容：同一字典类型下可以建两个同值项（下拉同值多项、回显不确定）；数据权限规则可以配出「绑定对象 + 表 + 字段 + 动作」完全相同的两条，编译时叠加。
  - 修复内容：`DictLogic::assertValueFree()`（只看未删除行，`dataCreate/dataUpdate` 都走）+ 回收站恢复前 `RecycleLogic::assertNoDuplicateValues()`；`DataRuleLogic::assertNoDuplicate()`（绑定对象按**部门集合**比较，忽略顺序；`row` 动作额外比较 `operator/value/value_type`）。
  - 为什么**不加**数据库唯一索引：唯一键 + 软删除会让「删掉再建同值」直接失败（`uk_type` 已是这个坑），且回收站恢复会因历史重复值报 500。理由写进 `docs/13 §2.2`。

- **【安全】配置的敏感分组仅平台超管可改（复核 A6）**
  - 问题内容：`cccms:config:save` 一个节点覆盖全部配置，拿到它就能关掉登录锁定 / 验证码、放宽上传白名单、把 `mail.*` / `sms.*` 的网关改成攻击者地址（找回密码的验证码链路直接变成凭据收集器）。
  - 修复内容：`ConfigLogic::assertGroupsWritable()` 拦截 `security.` / `upload.` / `mail.` / `sms.` 前缀，控制器在写库前用 `$request->user` 校验；无用户上下文（CLI / 初始化）放行。文案 `config.admin_only` 中英同步。

- **【性能】工作台 13 个计数合并为一条聚合 SQL（复核 B11）**
  - 问题内容：工作台是登录后默认落地页，原实现串行执行 13 个 `count()`（各有租户与数据权限条件），再加在线人数（Redis）与未读数。
  - 修复内容：各模型用 `fetchSql(true)->count()` 拿出**带作用域**的子查询，拼成 `SELECT (子查询) AS 键, ...` 一次取回；Redis 计数与未读数仍单独取。取数失败自动退化为逐项统计（宁可多几次往返，不能让落地页 500）。往返次数 13+ → 1。
  - 验证：新增 `tests/cases/DashboardTest.php`，断言合成结果与逐项查询一致、无权限节点时不下发对应键。

- **【新增】`cccms:orphan-check` 孤儿数据体检（复核 G2）**
  - 问题内容：全库没有物理外键，关联靠应用层维护；批量删除 / 回收站彻底删除 / 租户删除任一路径漏掉某张关联表，残留行不会报错也不会展示，只会在「权限莫名失效」「未读数对不上」里慢慢暴露。
  - 新增内容：`support/OrphanChecker.php`（17 组关联：用户↔角色/岗位/部门、角色↔权限节点、菜单/分类父节点、字典数据↔类型、通知↔目标/已读、数据权限规则三个绑定维度）+ `cccms:orphan-check` 命令（默认只报告，`--strict` 返回非 0）。
  - 口径：父行**完全不存在**才算孤儿；父行在回收站里不算（恢复父行后子行还要能用）。`0` 表示「不绑定」，不参与判定。

  - 问题内容：批量接口普遍是「循环里逐条执行」—— 字典类型批删（每个 id 一个事务 + 一次 `DictCache::bump()`）、用户批量分配角色/部门/岗位（每人 3 条 DELETE + N 条 INSERT，整批无事务）、岗位批删逐个 `count()`、回收站彻底删除菜单逐条 DELETE `role_node`、角色授权逐条 `insert`、公告「全部已读」逐条 `INSERT IGNORE`、配置保存逐条 `update`；另有 `Tree::subtreeIds()` 用 `in_array` 判重、菜单可见性传播用「每轮全表扫描直到不再变化」、租户账号数把全表 `tenant_id` 拉进 PHP 自增。
  - 修复内容：批量写统一「一个事务 + 一次 DELETE + 一次 `insertAll`」（`UserLogic::bulkSyncRoles/Depts/Posts`、`DictLogic::typeBatchDelete`、`RoleLogic::assignNodes`、`RecycleLogic` 的 `role_node` 清理）；`PostLogic` 用一次 `whereIn` 反查占用；`NoticeLogic` 用多值 `INSERT IGNORE`（`read_count` 按整批 +1），未读数与「只看未读」改成 `whereNotIn(子查询)`，不再把已读 id 全拉进 PHP；`ConfigLogic` 用一条 `ON DUPLICATE KEY UPDATE`；`Tree` 改哈希判重；`MenuLogic` 改「沿父链上溯 + 64 层防环」；`TenantLogic` 改 `group by` 计数。

- **【安全】会话与默认值收口（A2 / A3 / A5 / A7）**

- **【新增】WebSocket 推送通道（F9 收尾）**
  - 问题内容：SSE 只做服务端下行，客户端无法上送任何东西 —— 协作、终端输出流式回传这类场景没有通道可用；而「等真有需求再另做一套推送」意味着把事件总线重写一遍。
  - 修复内容：新增 `process/Websocket.php`（`websocket://`，默认 8789 / `CCCMS_WS_PORT`），**复用** `Realtime` 事件源与按用户分组轮询，事件名与载荷与 SSE 完全一致：SSE 把 `id` / `event` 放协议层，WS 用一个 JSON 对象承载（新增 `Realtime::payload()`），前端 `useRealtime` 的两种 driver 都还原成 `{id, event, data}` 再分发，页面零改动。鉴权走握手 query（浏览器原生 WS 同样不能带自定义头）：验签 + `TokenBlacklist`；**回调内不抛异常**（workerman 对 `onWebSocketConnect` 抛出的异常执行 `Worker::stopAll()`，一条坏令牌就能停掉整个进程），失败一律 `close()`。连接状态存进程内 `$clients`（`spl_object_id` 为键，不往连接上挂动态属性）、`last_id` 补发、应用层 ping/pong 心跳、连接上限复用 `Realtime::maxConnections()`。前端新增 `VITE_REALTIME_DRIVER=ws` + `VITE_WS_URL`；`disconnectRealtime()` 先置空再 `close()`，`onclose` 据此区分「主动断开」，避免登出后又自己连回来。
  - 已知边界：WS 与 SSE 端口必须分开（一个端口只能跑一种应用层协议）；Windows 不启动自定义进程，开发机两条通道都收不到推送；上行目前只有 `{"type":"ping"}` → `pong`，业务上行按需扩展，**不要在消息里接受身份字段**（身份只认握手令牌）。

- **【修复】角色继承树直查未收敛租户（`data-scope-check` 增 R5）**
  - 问题内容：`AuthService::effectiveRoleIds()` 解析角色继承要读 `sys_role.parent_id`，走的是 `Db::name('role')->column('parent_id', 'id')` —— 没有 where，全表扫。而 `role` 明确参与租户隔离（`TenantContext::TABLES`）：模型查询会自动带 `tenant_id`，这条直查不会，同一张表两套口径。继承链实际跨不出租户（父角色只能从本租户选），所以不是越权漏洞；但「模型一套、直查一套」正是 R4 想防的那类隐患，且扫描量随租户数线性上升。
  - 修复内容：`effectiveRoleIds()` 增 `$tenantId` 参数（**角色归属租户**，不是超管切换后的生效租户）并据此收敛查询。`buildContext()` 传刚查出的 `sys_user.tenant_id`；`DataScope::plan()` 传 `$user->homeTenantId`；业务层两个调用点不传，回退到当前用户的 `homeTenantId` —— 直接用 `currentTenantId()` 会在超管切换租户后一个角色都查不到。`DataScopeChecker` 新增 **R5**：`support/` 里对隔离表的 `Db::name()` 直查必须带 `tenant_id` / 走 `TenantContext::table()`，或按主键定位，否则退出码 1；判定窗口取匹配点后 400 字符，只认同一条链式调用。
  - 验证：`php webman cccms:data-scope-check` 通过；临时探针（未收敛的 `Db::name('role')`）能被精确报到行号；`php tests/run.php` 216 通过 0 失败。

- **【新增】实时推送（SSE 通道，F9）**
  - 问题内容：站内消息只能靠轮询 —— 公告发布后角标要等下次刷新；「强制下线」要等对方下一次请求才生效，管理员看着人还在列表里；作业跑完任务中心不会自己变。要「立刻」就得有服务端主动下行的通道。
  - 修复内容：新增 `support/Realtime`（Redis List 事件总线 —— `LPUSH` 写入、`LTRIM` 只留最近 100 条、`EXPIRE` 600s 让长期无人读的频道自动消失，事件 id 用 `INCR` 保证跨频道单调递增）与 `process/Sse`（独立 workerman 进程，**裸 TCP 手写 SSE 响应头** —— workerman 的 HTTP 协议每次 `send()` 都会补完整响应头，第二帧就不是同一条事件流了）。鉴权：query token（`EventSource` 不能带自定义头）+ 验签后再查 `TokenBlacklist`（登出 / 被踢的令牌签名仍有效，不查黑名单的话「强制下线」在实时通道上等于没做）。按 `userId` 分组拉取（同一用户多标签页只查一次 Redis）、心跳 15s、单进程连接上限 500（超出 503）。接入三处：公告创建 / 改为已发布时只推**当前在线且属于投放范围**的用户（新增 `OnlineSession::onlineUserIds()`）、作业完成 / 失败按 payload 的 `user_id` 推、强制下线推 `logout`（单会话带 `jti`，整用户不带）。端口由 `CCCMS_SSE_PORT` 控制，默认 **8788**（8787 已被 HTTP 服务占用）。

- **【新增】在线命令终端 `GET /terminal`、`POST /terminal/run`（F2）**
  - 问题内容：`cccms:menu-sync`、`perm-scan`、`log-archive` 这些运维命令只能在服务器上敲 —— 后台改完菜单忘了同步、审计链要定期校验都无处落手；而在后台放一个「随便敲」的输入框，等于把整台机器的执行权交出去。
