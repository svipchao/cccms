## [未发布] · 安全加固与体验收口

> 以下条目均已在代码中落地，随下一版本打 tag 发布。

### 安全

- **JWT 密钥不再回退默认值（P0-1）**：`JWT_SECRET` 未配置或不足 32 字节时，`support/SecurityBootstrap.php` 在启动期直接失败；同时补上缺失的 `vlucas/phpdotenv` 依赖 —— 此前 `.env` 从未被加载，配置全部静默回落硬编码默认值。
- **消除同域存储型 XSS（P0-2）**：上传白名单移除 `svg`；`StorageDriver` 增加危险扩展名硬拒绝名单（`svg` / `html` / `xml` / `mhtml` 等）与魔数校验；新增中间件 `app/middleware/StorageGuard.php`，`/storage/` 下非图片 / PDF 强制 `Content-Disposition: attachment`，全局下发 `X-Content-Type-Options: nosniff`。
- **登录失败限流拆为账号 + IP 双维度（P1-1）**：`cccms:login_fail:user:{用户名}` 与 `cccms:login_fail:ip:{IP}`；IP 维度达阈值只限流该 IP、不锁账号。新增配置 `security.login_fail_ip_limit`（默认 20）。
- **全站接口限流（P1-2）**：`support/RateLimiter.php`（Redis 固定窗口）+ 中间件 `app/middleware/RateLimit.php`，按「每用户每路由」计数，`export` / `import` / `generate` 单独更严；超限返回 `429` 与 `Retry-After` / `X-RateLimit-*`。Redis 不可用时 fail-open。
- **密码策略强化（P1-4）**：长度上限 64、内置弱口令黑名单、字符类别数要求、不得与用户名 / 昵称 / 邮箱相同或包含；补上 `UserLogic::update` 此前缺失的校验。新增 `security.password_max_length` / `security.password_strength`。
- **CORS 白名单可配置（P1-6）**：新增 `config/cors.php`（`CORS_ORIGIN`，默认留空 = 仅同源）；命中白名单才下发整组 CORS 头并回显 Origin，带 `Origin` 时无条件 `Vary: Origin`。
- **令牌 TTL 7 天 → 2 小时 + 滑动续期（P1-3）**：剩余有效期不足 TTL 的 1/3 时签发新令牌，经 `X-Refresh-Token` 下发、前端 `api/request.ts` 静默替换；`OnlineSession::rotate()` 同步迁移会话 `jti`，旧令牌不入黑名单（避免并发请求被判 401）。
- **收敛 `crypto_key` 下发范围（P1-5）**：仅持有 `cccms:data_rule*` 节点的管理员与超管可从 `/auth/me` 获取（`AuthLogic::mayDecryptFields()`）；规则配置页选择 `encrypt` 时提示「存储加密不等于访问控制」。
- **真实 IP 溯源（R-01）**：新增 `support/ClientIp.php`，仅当直连来源命中 `security.trusted_proxies`（CIDR）时才解析转发头，采用「取最右非可信 IP」算法；6 处调用点（登录限流 / 登录日志 / 在线会话 / 操作日志 / 慢接口告警 / 找回密码限流）统一改走 `ClientIp::resolve()`。部署要求见 [02-安装部署 §5.4](02-安装部署.md#54-反向代理下的真实-ip-溯源必配)。
- **写入口字段白名单（R-02，防 Mass Assignment）**：新增 `FilterInput::only()`，13 个 Logic 的 22 个写方法显式声明 `FIELDS` 并在入口过滤；新增 `cccms:write-guard-check`（已入 CI），允许一跳委托，逃生口为 `// @write-guard-ignore`（须写理由）；代码生成器同步产出该常量，生成即合规。
- **审计日志链式哈希（P2-14）**：`sys_log` 增 `prev_hash` / `row_hash` / `hash_version`，新增单行表 `sys_log_chain` 记录链尾与校验起点；写入统一走 `support/LogChain.php`（同一事务内锁链尾，防并发分叉），操作日志与登录日志不再直接 `INSERT`。
- **审计链校验与归档协同**：新增 `support/LogVerifier.php` + `cccms:log-verify`（`--from` / `--to`），可区分并定位 `content_modified` / `link_broken` / `tail_stale` / `chain_missing`，退出码非 0 即发现断点；归档额外产出 `<文件>.chain.json` 并在归档、清理后 `reanchor()`。链表缺失或库不可用时 fail-open 降级为普通插入。

### 新增

- **全局水印**：后台「配置管理 → 水印」可配内容与渲染效果（不透明度 / 角度 / 字号 / 颜色 / 间距），默认关闭。内容支持 `{username}` / `{user_id}` / `{time}` / `{newline}`（中英文写法等价），口径集中在 `utils/watermark.ts`；`components/Watermark.vue` 挂在 `BasicLayout` 顶层，canvas 平铺 + `pointer-events: none`；参数经 `GET /config/ui` 下发，老库由 `cccms:db-upgrade` 补插。
- **自动升级新增 `--force-all`**：下游落后过多时整体对齐上游（覆盖本地已改 / 恢复本地已删 / 删除上游已移除文件，均先备份）；命令行、后台页面与 `Upgrader::apply()` 三处同步支持。
- **自动升级兼容老版本 git**：去掉 `git -C` 依赖，改用 `proc_open` 工作目录参数（CentOS 6/7 自带 1.7.x 不再报 `Unknown option: -C`）；注入 `GIT_TERMINAL_PROMPT=0`；失败时自动附本机对该源的 HTTP 探测结果与 git 版本，URL 凭据一律打码。
- **在线升级限定本地开发环境**：`upgrade.enable` 默认改为 `false`，另加目录自检（仓库根须存在 `frontend/package.json`）；被拦截时页面禁用全部升级按钮并给出原因，`cccms:update` 退出码 2。同时删除从未被 seed 注册的 `UpgradeCheckTask`。
- **导出异步化与任务中心（P2-7）**：新增 `sys_export_task` 表，`GET /log/export` 及各模块导出改为一律异步；内置任务 `ExportTaskConsumer`（默认每 10 秒，消费前 `UPDATE ... WHERE status=pending` 抢占防重复）用 keyset 分页流式写 CSV，归档落在 `runtime/exports/`（不进 `public/storage`），`export.keep_minutes`（默认 60）到期清理。下载按 `user_id` 归属校验。前端入口为顶栏全局面板（`stores/exportTask.ts`，带未完成角标与轮询），任意页面可唤起。
- **附件分片上传 / 秒传（P2-9）**：同一个上传按钮按体积分流，`> 10MB` 走 `init → chunk → complete` 三阶段（节点 `cccms:file:upload:chunk`），单片上限 8MB，支持断点续传与 SHA-1 秒传（≤ 64MB 由 WebCrypto 计算）；合并后校验大小与哈希，流式合并避免大文件撞 `memory_limit`。会话存 Redis（TTL 24h），`ChunkCleanTask` 每小时回收残留。
- **列表批量操作（P2-1）**：用户 / 岗位 / 字典支持批量启停与删除，用户额外支持批量分配角色 / 部门 / 岗位（传哪个键就重设哪个关联）。新增 9 个接口与 9 个权限节点，统一语义为「只作用于可见行 + 跳过并回报 + 不整批失败」（`{affected, skipped[]}`）。
- **角色复制（P2-2）**：新增 `POST /role/copy` 与节点 `cccms:role:copy`，复制角色本体（显式复制 `data_scope`）与自身授权节点；`code` 自动派生 `_copy` 后缀；可选「另存为模板」（复制为禁用角色）。
- **密码找回（P2-3）**：新增 `POST /auth/password/sendCode` 与 `/auth/password/reset`（`#[NoLogin]`），支持用户名 / 邮箱 / 手机号。通道为可插拔适配器（`support/Mailer.php` 零依赖 SMTP、`support/SmsSender.php` 通用 HTTP 网关），核心逻辑在 `support/PasswordReset.php`。验证码只存 bcrypt hash（TTL 300s、尝试上限 5、一次性消费），不泄露账号存在性；重置成功后作废该用户全部令牌与在线会话。新增 20 项配置（`security.reset_*` / `mail.*` / `sms.*`）。
- **「我的登录设备」（P2-5）**：`GET /profile/sessions` 与 `POST /profile/sessions/revoke`，只能查看与注销自己的会话，注销同时写令牌黑名单与在线会话。
- **前后端 i18n 补全（P2-16）**：后端语言包按命名空间拆分，20 个控制器 + 18 个 Logic + 2 个中间件的中文提示全部迁移，`throw new ApiException('中文')` 归零；菜单与配置项标题由后端按请求语言下发（`MenuLogic::localizeTitles()` / `ConfigLogic::localize()`，用户录入数据不翻译）。前端语言包按模块拆分为 17 个文件，`translateTitle()` 统一 `document.title` / 面包屑 / 标签页，17 个页面与公共组件的列头、校验规则改为 `computed` 化以随语言刷新。
- **公共富文本编辑器（P2-19）**：新增 `components/core/ArtRichEditor.vue`（tiptap v3），仅用于通知公告等长文录入。存储为 HTML，保存侧 `NoticeLogic::sanitizeContent()` 正则白名单 + 渲染侧 `utils/richText.ts` 的 `sanitizeHtml()`（DOMPurify）双重净化，所有 `v-html` 位置必须先过净化。
- **多租户（P2-17）**：单库共享表 + `tenant_id` 列，`tenant_id = 0` 为平台租户（虚拟，不落库）。租户作为**最外层**硬边界叠加在数据权限之上（`BaseModel::$globalScope = ['tenant', 'dataScope']`），隔离 12 张业务表；`sys_menu` / `sys_config` / `sys_log` / `sys_crontab_log` 与全部关联表保持平台级。`withoutGlobalScope()` 恒保留租户条件，新增 `withoutAllScopes()` 才跨租户；`Db::name()` 直查统一改走 `TenantContext::table()` / `stamp()`。超管跨租户须显式切换（`POST /auth/switchTenant` 重签带 `tid` 的令牌）。详见 [06-数据权限 §十二](06-数据权限.md#十二多租户租户是硬边界档位是租户内的软范围)。
- **快捷导航收藏与排序**：顶栏 `Ctrl / ⌘ + K` 对话框拆为「本机收藏（可排序）+ 全部菜单」两区，收藏存 `localStorage`，按用户 + 租户隔离；`menuStore` 的收藏同时供顶栏、标签栏星标、工作台宫格三处使用。
- **时间范围筛选支持时分秒与常用区间**：所有 `filter.type = 'date'` 列统一改为 `datetimerange`，新增今天 / 昨天 / 最近 3·7·30 天 / 本月 / 上月 7 个快捷项；后端 `FilterInput::range()` 直接返回可比较的 `Y-m-d H:i:s`（只给日期时补 `00:00:00` / `23:59:59`）。
- **补齐缺失的时间筛选列**：在线用户的 `login_at` / `last_at` / `expire_at` 与公告的 `publish_at` / `expire_at` 各配独立 `startKey` / `endKey`；`OnlineSession` 新增 `RANGE_FIELDS` 与时间戳区间匹配。
- **插件脚手架（P2-18）**：新增 `cccms:plugin-create {name}`，生成四份 config + 示例 Controller（后台额外带 Logic 与 `db/menu.php`），可选前台（公开路由）或后台（自动执行 `menu-sync` + `perm-scan`）。落盘逻辑抽到 `support/PluginScaffolder.php`，与同步命令共用；插件名校验内置名，目录已存在默认拒绝。
- **表格列级默认显隐与隐私**：`ArtTableColumn` 新增 `defaultShow?: boolean`（`false` = 初始隐藏，与组件 `defaultHidden` 取并集）与 `defaultPrivacy?: boolean`（默认开启隐私遮罩，单元格先显示小眼睛、悬停才显示内容）；用户动过列设置后仍以本地记录为准，「重置列 / 全部重置」都会回到这两个声明值，`lockVisible` 列不参与隐私。隐私存储前缀升级为 `cccms_table_privacy:v2:`，避免旧缓存里的空数组压掉新默认值。

### 变更

- **`cccms:db-upgrade` 只做新装**：删除 `DbUpgradeCommand` 的 `COLUMNS` / `INDEXES` 与 `migrateColumns()`，不再按 `information_schema` 给老表 `ALTER ADD COLUMN`。表结构只以 `plugin/cccms/db/schema.sql` 为准（`sys_log.action_id` / `session_id` / `hash_version` 与索引本就在建表语句里），同一字段不再在安装与升级两条链路各写一份。
- **DDL 兼容老版本 MySQL**：`sys_data_rule.dept_ids` / `sys_config.options` / `sys_crontab.params` 由原生 `json` 改为 `text`（原生 `json` 5.7.8 才支持），并去掉 TEXT 列上的显式 `DEFAULT NULL`。代码侧本就按字符串读写，无需改动。
- **上传 MIME 改存服务端探测值（R-07）**：附件 `mime` 改取 `StorageDriver::probeMime()` 的 finfo 结果，客户端上报值仅在探测不到时兜底；校验阶段完成探测并随 `validate()` 返回。
- **工作台统计与收藏**：`GET /dashboard/stats` 的统计项扩到 13 项，逐项按权限节点下发（无权限的键不返回），数字再按数据范围收窄；原「常用功能」改为「我的收藏」宫格，支持拖拽排序。
- **列表页筛选重构**：以 `ArtTableColumn.filter` 为唯一声明源，列头筛选（`text` 输入弹层 / `enum` 多选 / `date` 区间）与表格上方搜索卡片共用同一份 `query`；`useTable` 抽出 `createFilterStore()` 并导出 `useTableFilter()`，`menu` / `dept` 两个树表也具备筛选方案；筛选值沿用 `cccms_table_filter:` 前缀持久化。新增 `support/FilterInput.php`（`values()` / `ints()` / `range()` / `only()`）承接后端枚举多选与区间解析。
- **表格列默认全部显示**：删除 `ArtTableColumn.defaultHidden` 与相关逻辑，「列设置」仍可手动隐藏；存储前缀升级为 `cccms_table_hidden:v2:`。
- **顶栏与侧边栏布局定稿**：顶栏为「快捷导航 / 全屏 / 消息 + 导出任务合并入口 / 设置」，消息与导出任务合并在 `MessageCenterDrawer.vue`（tabs 区分）中，角标 = 未读消息 + 未完成任务；语言切换、系统刷新、切换租户、清理缓存移入侧边栏用户卡片（两行：头像与注销 + 四个功能图标）；侧边栏宽度 230px。
- **图标库切换为 RemixIcon**：新增 `remixicon` 依赖，`utils/icon.ts` 的 `ICON_MAP` 改为 `icon-xxx` → `ri-xxx` 映射，业务图标全部替换；`ArtTable` 与 `ArtRichEditor` 内部仍用 Element Plus 图标。
- **云存储凭证迁到后台配置**：`upload.oss_*` / `upload.cos_*` / `upload.qiniu_*` 落 `sys_config`，密钥类项 `enc:` 密文存库、接口只回「是否已配置」；配置页按当前驱动动态显示字段；`.env.example` 与文档删除 `OSS_*` / `COS_*` / `QINIU_*`。`cccms:db-upgrade` 幂等补插 14 项。
- **工作台在线用户改按去重用户数统计**：新增 `OnlineSession::countUsers()`（扫会话明细按 `user_id` 去重），在线列表与 `/metrics` 的 `cccms_online_sessions` 仍是会话数口径。

### 移除

- **清理 Webman 脚手架残留（R-06）**：删除无人引用的 `app/model/Test.php` 与 `app/view/index/view.html`。
- **下线用户 / 数据权限规则的导入导出**：只保留日志导出。前端删除两个页面的导出 / 模板 / 导入按钮与相关 API，后端删除 6 条路由、6 个权限节点与对应实现；`cccms:db-upgrade` 幂等清理老库残留的 `sys_menu` / `sys_role_node` 行并失效权限缓存。通用 `support/Csv.php` 保留（日志导出仍在用）。

### 性能

- **`SysConfig` 缓存防击穿（R-08）**：回填前加 Redis `SET NX EX` 短锁（`cccms:config:lock`，TTL 5s），抢不到锁的请求等 20ms 后二次读缓存，仍无则直读库（fail-open）；Redis 不可用时与改造前一致。
- **字典数据缓存（P2-8）**：新增 `support/DictCache.php`，复用「全局版本号 + 缓存键含版本」范式（`cccms:dict:ver`，TTL 600）；字典增删改与回收站操作均 `bump()`，回收站视图不缓存。

### 可观测性

- **登录安全分析（P2-13）**：新增 `GET /log/login/analysis`（节点 `cccms:log:analysis`），输出失败趋势（≤ 48 小时按小时分桶、补空桶）、失败 TOP 用户名 / IP、异地登录；一条聚合语句取全，走同一份数据范围。前端日志页新增「登录分析」标签页，无权限不渲染入口。
- **日志链路聚合（P2-6）**：新增 `GET /log/trace?trace_id=`（节点 `cccms:log:trace`），按 `id` 升序还原一次请求的日志并汇总 `{total, failed, cost}`；日志页可按「链路ID」检索并支持 `/log?trace_id=xxx` 直达。
- **可观测端点（P2-12）**：新增 `ObservabilityController` 与 `support/{HealthProbe,Metrics,EndpointAccess}.php`。`GET /healthz` 逐项检查 MySQL / Redis / 磁盘 / 内存（Redis 用「写 → 读回 → 删」），失败返回 503 并指明项；`GET /metrics` 输出 Prometheus 文本，指标统一从 `sys_log` / Redis 派生以适配多进程与多实例。两端点均为 `#[NoLogin]` + IP 白名单（`security.metrics_allow_ips`），非白名单来源返回 404；探活与抓取请求不写操作日志。Docker `HEALTHCHECK` 改为探 `/healthz`，`/ping` 保留为存活探针。

### 体验

- **定时任务执行日志抽屉重做**：改为「工具条 + 撑满高度的表格 + 底部固定分页」，分页器补齐每页条数与跳页，工具条新增结果筛选与刷新。
- **大表格虚拟滚动（P2-15）**：`ArtTable` 新增可选 `virtual` 属性，内部改用 `el-table-v2` 只渲染可视区域；树形与回收站自动回退普通表格，业务页零改动。

### 修复

- **日志链路按「一次操作」聚合**：拆为 `trace_id`（请求级，后端生成）、`action_id`（操作级，前端 `X-Action-Id`）、`session_id`（会话级，前端 `X-Session-Id`），`sys_log` 补三列；新增 `GET /log/action` 与 `GET /log/session`，`GET /log/trace` 保留为请求级查询。

## 明确不做

> 本节是**决策留档**：不做项一律记在这里，避免反复讨论；需求变化时先改本节写明新决策，再动工。最后复核：2026-10-18。

| 事项 | 原因 |
|------|------|
| 前端 E2E（Playwright）、UI 自动化基线 | 用例随 UI 变动长期维护的成本高于收益；主链路回归由后端集成测试 + `lint` / `build` 覆盖 |
| 多因素认证 TOTP（P2-4） | 现有「口令策略 + 登录限流 + 图形验证码 + 2h 令牌 + 滑动续期」已覆盖，收益与改造量不成比 |
| 导入导出增强（P2-10） | 用户 / 规则导入导出已下线，仅保留日志导出，不再扩展 |
| 连续失败升级为强制验证码（P1-1 遗留） | 需前端登录页联动改造，成本高于收益 |
| 后端解密 + 按数据权限 mask 下发（P1-5 遗留） | 改造量 5 pd+，`decryptField` 与 `cryptoKey` 目前无调用方 |
| HttpOnly 刷新令牌（R-04） | 需服务端 refresh 接口 + CSRF 防护，5 pd+；现有短 TTL + 滑动续期已缓解 XSS 面 |
| 密钥轮换（`data_encrypt_key`） | 历史加密字段将无法解密，轮换须先设计密文版本号方案 |
| 兼容老 CCCMS（ThinkPHP 8）数据 | 本仓库为全新工程 |
| 在 `plugin/cccms` 内放业务功能 | 基础与业务必须分离，业务一律新建插件 |
| `sys_config` / 关联表 / 日志的软删除 | 配置无归属、日志按天数清理 |
| 站内消息实时推送（WebSocket / SSE） | 需常驻进程 + 多实例广播 + 断线重连，现有未读角标已够用 |
| SSO 单点登录（OIDC / 企微 / 钉钉 / 飞书） | 单个 provider 3~5 pd 且需长期回归，现有账号密码链路已闭环 |
| 工作流引擎（轻量审批流） | 产品级模块，15 pd 起步，暂无落地场景 |
| 数据权限铺开到 `post` / `notice` / `dict_*` | 这些表本质是全局共享配置，加行级范围会让管理员看不到自己建的数据 |
| 前端骨架屏 | 路由切换已有 NProgress，hash 路由 + keep-alive 下白屏窗口很短 |
| 云存储直传（预签名 / STS） | 需逐驱动实现签名与前端改造；P2-9 已覆盖大文件上传与断点续传 |
| 附件私有化 + 预签名下载 | 需签名接口 + 时效控制 + 前端全量替换 URL（4~6 pd），仅合规场景才值得 |
| API 签名防重放（timestamp + nonce + sign） | 已有 HTTPS + 短 TTL JWT + 全站限流 + `jti` 黑名单 |
| 密码历史校验 / 首次登录强制改密 / 密码过期 | 无对应场景；NIST SP 800-63B 亦不推荐强制定期改密 |
| 数据库连接池 / 断线重连自研 | 属 `think-orm` 框架层职责，且无实证断连问题 |
