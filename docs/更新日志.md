## 0.3.7（2026-10-22）— 口令历史

改密不再能改回旧口令；三条改密入口（自助、管理员重置、找回密码）口径一致。

### 变更

- **新增 `sys_password_history`**（迁移 `0005_password_history`）：只存被替换掉的 Argon2 哈希，不存明文。每个用户保留最近 `CCCMS_PASSWORD_HISTORY` 份（默认 5），更老的在同一事务内删除，行数不随改密次数增长。
- **改密前先查历史**：命中则返回密码策略错误（业务码 `10106`），此时**不写库、不作废令牌**——失败的改密不该把用户踢下线。
- **可调可关**：`CCCMS_PASSWORD_HISTORY=0` 关闭校验（连查询都不发），`=1` 退化为"只拦与当前相同"。
- **校验逻辑集中**在 `services/password_history.py`，三处调用点只负责顺序：`ensure_not_reused()` → 写新哈希 → `remember(旧哈希)` → 一次 `commit()`。

### 升级注意

- 存量库执行 `cli migrate`（若用 init-db/migrate 之外的流程，注意这是纯新增表、无数据回填）。

## 0.3.6（2026-10-22）— S3 对象存储

附件不再绑死本地盘，多副本部署的前置条件解除。

### 变更

- **新增 `S3StorageDriver`**（`services/storage/s3.py`）：AWS / MinIO / OSS 与 COS 的 S3 端点通用，固定 path-style 寻址（自建端点通常没有通配 DNS）。同步 boto3 + `asyncio.to_thread`，客户端按连接参数缓存——初始化比一次 PUT 还贵。
- **配置**：`CCCMS_S3_ENDPOINT` / `REGION` / `BUCKET` / `ACCESS_KEY` / `SECRET_KEY` / `PREFIX`。`s3` 缺桶或缺凭据**启动即失败**；`oss` / `cos` / `qiniu` 仍拒绝启动（专有协议未实现）。
- **`/storage/<path>` 按驱动分流**：local 用 `FileResponse`；s3 先在原地用 `apply_scope` 校验可见性，再 302 到 **300 秒**预签名直链。
- **软删除打通**：驱动协议新增 `quarantine` / `restore` / `purge`。local 移到 `shared/quarantine/`（不变），s3 复制到 `<prefix>/_quarantine/` 再删原件。
- **分片暂存与驱动解耦**：`chunks/<upload_id>/` 明确为本机暂存，不再经 `local_driver()`（那会让 s3 模式下分片上传直接 500）。

### 已知残余

- `copy_object` 单次上限 5GB，隔离区/还原对超大对象会失败，需改 multipart copy。
- 分片上传依赖粘性路由：分片在哪个节点，`complete` 就得落在哪个节点。
- 存量 `storage=local` 的记录不会自动搬进桶，需另写搬迁脚本（按需）。

## 0.3.5（2026-10-22）— 升级源可选

升级页可以在页面上选同步源，不再只能由后端配置决定走哪个远端。

### 变更

- **状态接口带远端列表**：`GET /api/upgrade` 新增 `remotes`（名字 + 脱敏 URL + `is_default`），默认项与 `CCCMS_UPGRADE_REMOTE` 的取舍一致。无远端或读取失败时为空，状态页照常返回。
- **`check` / `init` / `run` 接受 `remote` 查询参数**：必须是仓库已配置的远端名（名字白名单 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`），否则 422；缺省时仍按配置值 → 唯一远端兜底。
- **选了远端就按 `<remote>/<branch>` 比对**：不再沿用分支的跟踪上游，避免「检查 origin、升级 gitee」两边结论对不上。
- **远端 URL 脱敏**：去掉 userinfo / 查询串 / 片段，远端里内嵌的 token 不回传前端。

### 升级注意

- 选项来自仓库本身：先 `git remote add gitee <url>` 才会出现在下拉里；一个远端都没有时下拉不显示。

## 0.3.4（2026-10-22）— 下载改流式

`GET /api/file/{id}/download` 不再交给 `FileResponse`，字节流由存储驱动提供。

### 变更

- **Range / `Content-Length` / `Content-Disposition` 自实现**（`core/http_range.py`）：单区间 206、起点越界与空文件 416、多区间与语法错误按 RFC 9110 忽略并回整份；`Content-Length` 取驱动给的真实大小，不用库里可能过期的 `size`。
- **`Content-Disposition` 过滤 CRLF**：用户上传的文件名不会变成响应头注入。
- **`/storage/<path>` 保持 `FileResponse`**：它只服务 `storage=local` 的记录。

### 已知残余

- 不再发 `ETag` / `Last-Modified`：缓存过期后整份重下，而不是 304。

## 0.3.3（2026-10-22）— 存储驱动层

把上传落盘从业务代码里抽到驱动层，`services/file.py` 不再直接调用文件系统。行为零变化。

### 变更

- **新增驱动层** `services/storage/`：`base.StorageDriver`（对象级协议 `save` / `open` / `delete` / `exists` / `url` / `presign_url`）+ `local.LocalStorageDriver` + 注册表 `get_driver()`。协议刻意不含 `blob_path()`——那只有 local 实现得了。
- **上传走驱动**：`upload_file`、`complete_upload` 的落盘改为 `driver.save(relative, 异步字节流)`；哈希、大小上限、空文件校验仍在服务层。
- **本地专属能力收口**：隔离区与分片暂存经 `local_driver()` 获取，非 local 驱动下**抛错**而不是退回本地路径（退回会让多副本读到空）。
- **启动校验有落点**：`Settings.validate_storage()` 改查 `IMPLEMENTED_STORAGE_DRIVERS`，与注册表的一致性由 `tests/test_storage.py` 断言。
- **半截文件不再入库**：`save` 中途失败会删掉已写部分，调用方再兜一次 `driver.delete()`。

## 0.3.2（2026-10-22）— 找回密码可用

补齐真实投递通道。此前 prod 下该功能整体 503，用户无法自助找回密码。

### 变更

- **SMTP 投递**：新增 `services/mail.py`（`smtplib` + `asyncio.to_thread`，超时 `CCCMS_SMTP_TIMEOUT`，不新增依赖）；配置项 `CCCMS_SMTP_*`，模板见 `.env.example` / `.env.prod.example`。
- **验证码只在投递成功后落 Redis**：dev 未配 SMTP 仍写日志便于联调。
- **渠道可达性收敛**：`deliverable_channels()` 改为「email 看 `smtp_ready`、sms 仅 dev 可用」，登录页入口 / 公共配置 / 发码校验三处自动同步。
- **失败不锁用户**：冷却位改成「先占位 → 投递 → 落码」，投递失败立即释放并返回 503，不会"码没收到还得等 60 秒"。
- **不泄露绑定情况**：账号存在但未绑邮箱/手机，返回与"账号不存在"相同的成功外壳。
- **日志脱敏**：新增 `core/redact.mask_email()`，投递日志只记 `z***@example.com`。

### 已知残余

投递是同步的，真实发信耗时明显长于假响应，响应时间仍可作账号存在性的旁路；彻底消除需改为入队投递（见 N-01）。

## 0.3.1（2026-10-22）— 鉴权与可观测修正

含一个真正的鉴权修正：0.3.0 里「`/storage` 改为鉴权直出」因 `auth=False` 实际没生效。

### 功能与修复

- **附件恢复可读**：`/storage/**` 改为 `auth=True`，`load_user` 进入依赖链、`apply_scope` 真正生效；匿名 401，不可见 404。
- **新增鉴权下载**：`GET /api/file/{id}/download`，登录即可、可见性由 `apply_scope` 决定，文件名取 `original_name`——纯 Bearer 客户端与"另存为"的唯一出口。
- **服务端排序**：新增 `core/sorting.apply_sort()`（白名单 + 显式 fallback），日志/附件/公告/岗位/租户/定时任务 6 个列表接入；顺带补上用户页 `login_time → last_login_at` 映射（此前点"最后登录"静默失效）。
- **公告列表口径对齐**：没有 `cccms:notice:update` 的角色不再在列表里看到草稿/未发布/已过期/他人定向公告。
- **找回密码入口按投递能力收敛**：登录页初始化、公共配置、发码校验共用 `deliverable_channels()`；prod 无通道时不再显示「忘记密码」，直接调接口仍 fail-closed 拒绝。

### 安全与部署

- **代码生成器全入口 dev-only**：`/tables`、`/columns`、`/preview`、`/generate` 统一在路由层校验，prod 返回 422。
- **生产拒绝开发密钥**：prod 检出 `.dev-secrets.env` 直接拒绝启动（它位于 `env_file` 首位，会静默顶替正式密钥）。
- **租户解析失败 fail-closed**：域名→租户解析异常返回 503（业务码 10503），不再退化成"无租户上下文"继续处理；`/ping`、`/healthz`、`/metrics` 豁免。
- **compose 不再混用 dev 配置**：三个服务改读 `backend/.env.prod`，新增模板 `backend/.env.prod.example`；MySQL/Redis 端口改绑 `127.0.0.1`（Redis 无鉴权，原先等于对外开放）；`.dockerignore` 补 `.dev-secrets.env{,.lock,.tmp}` 与 `.env.prod`。

### 工程与文档

- **CI 落地**：`.github/workflows/ci.yml`（后端 ruff/mypy/pytest、前端 vue-tsc/eslint/vitest/i18n）。
- **审计丢弃可观测**：新增 `cccms_audit_dropped_total`；`clear_online_for` 失败改为带 `jti` 的 warning，不再静默。
- **版本号单一来源**：`src/cccms/__init__.py` 为唯一字面量，`pyproject.toml` 由 hatchling 动态读取；`tests/test_version.py` 兜住前端 `package.json`。
- **测试隔离**：`tests/conftest.py` 使单测不读工作区 `.env`（本地 `CCCMS_DEBUG=true` 曾让 prod 硬化用例必红）。
- **仓库基线**：首次纳管 backend（129 文件）、删除历史 `server/`、打 `v0.1.0` 基线 tag。
- **文档**：重写 README 的能力与部署描述；新增 `AGENTS.md`。

## 0.3.0（2026-10-22）— 架构整改

架构评审后的四轮整改，**含契约级变更**，升级前请看本节末尾的「升级注意」。

### 安全

- **生产启动硬门槛**：`CCCMS_DEBUG` 必须 false、`CCCMS_SECRET_KEY` ≥32 字节、`CCCMS_CORS_ORIGINS` 非空且不含 `*`、`CCCMS_ADMIN_PASSWORD` 非默认且 ≥12 位；调度器与 API 行为一致。
- **会话吊销真正生效**：登录不再清除 `user_cutoff`，水位只前进；改密、重置密码、强制下线后旧令牌立即失效，且不会因再次登录而复活。
- **多角色数据范围取最严**：`merge_data_scope()` 用 `max()`，任一角色的宽范围不再放大整个账号。
- **不再下发数据加密母密钥**：`/auth/me` 移除 `crypto_key`，前端 `stores/user.ts` 同步删除。
- **分配角色补委派校验**：挂角色时校验「不能授出自己没有的节点 / 更宽的数据范围」，堵住 `user:update` 自我提权。
- **匿名接口限流**：登录 20/min、验证码/找回密码 5/min（按 IP 分桶，可配置）；修正「重接口判定永远命中不到 `/api/**`」的问题。
- **`/storage/**` 改为鉴权直出**：按 `sys_file.path` 反查 + `apply_scope()`，匿名 401、不可见 404。
- **凭据枚举与裸入参**：登录时账号不存在也执行一次哈希校验；`sendCode` / `reset` 改走 Pydantic，账号不存在返回统一成功体。
- **`/metrics` 白名单**改用 `ip_allowed()`（支持网段）；导出 CSV 走字段级脱敏管线。
- **存储后端不再谎报**：`CCCMS_STORAGE_DRIVER` 只接受 `local`，其它取值启动即失败。

### 错误码与文案

- **业务码与 HTTP 状态码解耦**：新增 `core/codes.py`（`BizCode`），响应体 `code` 为业务码（认证 101xx / 授权 102xx / 资源 104xx / 服务 105xx），HTTP 状态码保持协议语义。
- **多语言接线**：新增 `lang/zh-CN|en-US/error.json`，`Accept-Language` 命中则翻译、未命中回退原文；中间件 413/504 也带业务码与文案。
- **细分码落位**：登录失败 `10102`、账号停用 `10103`、验证码错误 `10105`、密码策略 `10106`、令牌过期 `10107`、CSRF 失败 `10108`、委派越权 `10203`、体积超限 `10413`。

### 数据与性能

- **不再用「全列子查询」做 count**：新增 `count_query()` 把派生表收敛到主键一列，替换 15 处热点（日志/用户/公告/岗位/字典/导出/定时任务/租户/规则/角色/工作台）。
- **列表索引补齐**：`sys_log(tenant_id,id)`、`sys_log(path,create_time)`、`sys_log(row_hash)`、`sys_crontab_log(crontab_id,id)`、`sys_notice(tenant_id,pinned,publish_at,id)`、`sys_file(tenant_id,path)`。
- **分页封顶**：`PageLimit ≤ 200` 覆盖 log/dict/notice/post/export/online 与 `UserQuery`；角色列表从"全表捞出后切片"改为 SQL 分页。
- **鉴权上下文短缓存**：Redis 版本化缓存（TTL 120s），权限类写请求成功后 bump 版本；字典下拉 300s、工作台统计 60s。
- **批量操作去 N+1**：用户批量启停/删除/授权改为一次 `IN` 查询；公告「全部已读」改为批量 INSERT + 一条 UPDATE；`read_count` 改原子自增。
- **秒传按租户去重**：显式 `tenant_id + sha1 + size`，不再被「仅本人」数据范围收窄。
- **连接池**：新增 `pool_timeout=5s`、`pool_use_lifo`、可配 `pool_recycle`。

### 运维

- **Alembic 迁移体系**：`alembic.ini` + `migrations/`（0001 基线 / 0002 热索引 / 0003 附件路径索引 / 0004 日志归档）；`cli init-db` 与新增的 `cli migrate` 都走 `upgrade head`。
- **容器与流水线**：多阶段 `backend/Dockerfile`（非 root + HEALTHCHECK）、根 `docker-compose.yml`（mysql/redis/migrate/api/scheduler）。
- **请求守卫**：全局 30s 超时（未开始响应时 504）与 `Content-Length` 体积上限（413）。
- **探针分级**：`/healthz` 把 Redis 降级为 `degraded` 信号，不再让 Redis 抖动摘掉全部实例。
- **导出转后台**：接口立即返回 `task_id`，后台流式生成（`session.stream` + 分块写盘）；启动期把重启遗留的任务标记失败，关闭时取消在途任务。
- **导出并发保护**：进程内闸门 + 单用户未完成任务上限（`CCCMS_EXPORT_MAX_CONCURRENCY` / `CCCMS_EXPORT_MAX_ACTIVE_PER_USER`）。
- **调度器心跳**：写 `cccms:scheduler:heartbeat`，`/metrics` 暴露 `cccms_scheduler_heartbeat_age_seconds`。
- **清理任务补齐**：`cccms.crontabLog.clean`（30 天）、`cccms.noticeRead.clean`（90 天），均按 5000 行分批。
- **日志归档**：新增 `cccms.log.archive` 与迁移 `0004_log_archive`，把 90 天前未封存日志搬进 `sys_log_archive`（先 INSERT 再 DELETE，5000 行一批）。
- **未读判定改 `NOT EXISTS`**：公告未读列表与角标不再用 `NOT IN (子查询)`，避免物化整张已读表。
- **RED 指标接入 `/metrics`**：`cccms_http_requests_total`、`cccms_http_request_duration_seconds`、`cccms_http_requests_in_flight`，路由标签用模板避免基数爆炸；另加 `cccms_db_pool_checked_out`。
- **HTTP 契约测试**：新增 `tests/test_http_contract.py`，锁住 fail-closed 401、`/storage` 鉴权、业务码与 HTTP 解耦、`/metrics` 伪装 404、安全响应头（不需要 MySQL/Redis）。
- **API 版本化**：业务路由同时挂 `/api` 与 `/api/v1`（旧前缀保留一个发布周期）。
- **死代码清理**：删除未使用的 `PageParams`（排序能力在 0.3.1 以 `core/sorting.py` 重新引入）。

### 前端性能

首屏关键路径（入口 JS + vue + CSS）**504KB → 185KB（gzip，-63%）**，产物总体积 7.84MB → 3.16MB。

- **挂载不再等配置接口**：去掉 `Promise.race([configUi, 2.5s]) → mount` 的阻塞（该接口一度能把 LCP 拖满 2.5s），改为「缓存同步回填 + 接口静默校正」，首屏 loader 跟随 `router.isReady()` 收起。
- **Element Plus 真按需引入**：`unplugin-vue-components` + `unplugin-element-plus`，删除 `app.use(ElementPlus)` 与全量 CSS。注意 `manualChunks` 不能再给 `element-plus` 指定固定 chunk——那会把 109 个组件全部打进产物（`vite.config.ts` 里有注释）。
- **图标字体只产 woff2**：构建期删掉 remixicon 的 eot/ttf/svg/woff 引用与文件，dist 减少 4.2MB。
- **echarts 懒加载**：从工作台模块顶层静态 import 改为数据到达后再取（`utils/echarts.ts` 用具名导入保证 tree-shake），登录后首屏少下 523KB。
- **英文语言包按需**：`en-US` 改动态 import（入口 -48KB），切换语言先中文兜底。
- **工作台 CLS**：指标卡与图表骨架改为「按权限同步渲染 + 固定高度占位」，消除数据到达时的整块下推。
- **导航预取**：侧边栏 `mouseenter/focus` 即预取对应路由 chunk；路由过渡 0.18s→0.11s 并支持 `prefers-reduced-motion`。
- **重复访问走 Service Worker**：`public/sw.js` 对带哈希的 `/assets/*` 做 cache-first（HTML 不入缓存，升级不受影响）。
- **交互细节**：`useTable` 最小 loading 300ms→120ms；NProgress 延迟 120ms 出现；表格/图表 `resize` 合并到单帧。
- **Nginx 参考配置补齐**：gzip/brotli、`/assets/` 一年 `immutable`、`index.html` 与 `sw.js` `no-cache`，见 [02-安装部署](02-安装部署.md) §5.1。

### 升级注意

- **响应体 `code` 语义变了**：错误时不再等于 HTTP 状态码。前端只看 `code === 0`，已适配；**外部集成若比较过 `code == 401/403`，必须改成看 HTTP 状态码或新业务码**。
- 多角色用户的可见数据可能变少（最严合并），需要放宽请显式调整角色档位。
- `/storage` 不再匿名可读；纯 Bearer 客户端与第三方外链改用带令牌的下载入口。
- 生产新增启动门槛（CORS / SECRET_KEY / 管理员口令 / 存储驱动），升级前核对 `.env`。
- 存量库升级：`alembic stamp 0001_baseline` → `cli migrate` → `cli seed`（写入新增的清理任务）。

## 0.2.0（2026-10-22）— 越权与契约修复

围绕多租户/平台边界做的一轮加固，外加把数据规则、分片上传等"前端点不动"的契约修好。

### 安全

- **导出目录移出静态资源**：新增 `CCCMS_EXPORT_LOCAL_ROOT`（默认 `shared/exports`），导出文件不再落在 `/storage` 下，只能经 `/api/export/task/download` 下载。
- **菜单写入收口**：`sys_menu` 是全平台共享表，增删改要求「超管 + 平台租户」。
- **阻止伪造超管角色**：创建或复制编码为 `super_admin` 的角色直接拒绝。
- **在线会话租户隔离**：会话记录加 `tenant_id`，列表与强制下线只作用于当前租户。
- **日志清理租户隔离**：清理任务注入执行租户，租户任务只清本租户，平台租户才可跨租户。
- **回收站越权修复**：还原/彻底删除统一走 `apply_scope()`，并保护超管账号、`super_admin` 角色与平台菜单。
- **部门越权修复**：详情、选择器、写操作统一做数据范围校验，避免"看不到却能改"。
- **字段解密收口**：解密密钥只下发给超管与持有 `cccms:data_rule:save/update` 的角色，只读审计角色不再拿明文。
- **已封存日志禁止删除**：参与哈希链的日志行不允许后台删除，避免审计链断裂。
- **阻止平台租户内提权**：非超管不能授予 `super_admin`，也不能改超管账号、重置其密码或停用；批量操作会跳过。
- **角色授权最小委派**：非超管只能授出自己拥有的节点，`data_scope` 不得比自身更宽。
- **系统刷新限平台超管**：`/api/system/refresh` 触发菜单重建时要求「超管 + 平台租户」。
- **维护模式按租户隔离**：租户级维护不再提升全局会话水位，不会把其他租户踢下线。
- **附件软删除隔离**：删除时移入 `shared/quarantine/`，旧 URL 立即 404；还原移回，彻底删除清理文件；隔离失败则回滚并返回 503。
- **操作日志不再存认证/配置响应体**：登录、切租户、找回密码、配置保存即使进审计也强制 `result=NULL`；`redact()` 改为按键名包含 password/secret/token/code 脱敏（覆盖 `mail.smtp_password` 这类复合键）。
- **开发密钥跨进程共享**：dev 首次启动生成的 JWT/数据加密/审计签名密钥写入 `.dev-secrets.env`（已 gitignore），API、调度器、CLI 不再各生成一套。
- **找回密码冷却与生产边界**：生产无可用通道时在写 Redis 前直接 503；验证码改 `GETDEL` 原子消费，比较用 `compare_digest`。
- **登录锁定按租户隔离**：失败计数 key 加入 `tenant_id`，避免跨租户锁死同名账号。
- **在线升级限平台超管**：除 dev + 开关外，还要求平台租户且操作者是超管。
- **租户域名缓存主动失效**：改/删租户后清旧域名与新域名缓存，不再等 300 秒 TTL。

### 功能

- **分片上传契约**：`/file/upload/chunk` 接受 `file` 字段（兼容前端 FormData）；`save_chunk` 校验 `index < total_chunks`，不能再为一个声明 2GB 的文件写 10 万个分片。
- **数据规则契约**：受控表出参补 `label` / `field_count` / `exists`；`options.tables` 返回表名、显示名与字段列表；仍被规则引用的受控表禁止删除。
- **字段级规则真正生效**：用户、部门、附件、操作日志的出参应用 `hidden` / `mask`（`encrypt` 暂按掩码展示）；写入侧过滤只读/掩码字段，避免掩码值回填。
- **数据规则 fail-closed**：字段/操作符/取值非法时返回空集，不再静默放行整表。
- **用户名复用**：唯一性校验排除已软删行，删除后可重建同名账号。
- **批量操作**：批量删除用户跳过超管；未提交的字段保持原样（不再被空数组清空）；先整体校验角色/部门/岗位归属，非法 id 直接拒绝。
- **关联写入租户校验**：保存角色/部门/岗位时只接受当前租户且未删除的 ID。
- **字典校验**：字典数据必须属于当前租户类型；分类不允许跨模块修改、不允许挂到自己的子孙下；删除分类校验模块。
- **配置覆盖**：租户保存不再改写全局默认行，而是生成租户覆盖行；`secret` 空值可显式清空。
- **通知**：未提交 `expire_at` 时保留原值；重复标记已读幂等；列表补标题/级别/范围/时间筛选；无 `cccms:notice:update` 的角色只能读已发布且在投放范围内的通知。
- **密码重置**：成功后吊销该用户全部令牌与在线会话；生产无通道时返回 503，不再「假成功」把验证码写日志。
- **导出**：下载前校验 `expires_at`，过期返回 404。
- **租户**：创建用户校验 `max_users`（平台租户与 0 值不限）；`is_platform` 只能由初始化脚本写入；域名识别与缓存命中都检查到期时间；列表补名称/编码/联系人/时间筛选。
- **在线用户接口**：返回设备/系统/浏览器/登录时间/到期时间/是否当前会话，支持用户名、IP、时间范围筛选与排序。
- **代码生成器**：表结构查询/预览/生成限制在 dev/test；修正生成代码的 `get_current_user` 导入位置。
- **定时任务**：立即执行加 Redis 锁，避免与调度执行并发；调度执行注入租户上下文。
- **在线升级**：git 调用改 `asyncio.to_thread()`，不阻塞事件循环。
- **审计链校验分批**：`verify_chain()` 按 ID 分页，`from_id` 从上一个已封存哈希续接，避免误报 broken。
- **Argon2 移出事件循环**：新增 `hash_password_async` / `verify_password_async`，信号量限制同时 4 个哈希；登录后按需 `needs_rehash` 自动升级旧哈希。
- **上传 MIME**：以扩展名推导为准，客户端 `Content-Type` 仅兜底；图片类型移除 `svg`。
- **默认配置初始化**：`seed` 写入 18 个全局 `sys_config` 默认项；保存未知配置项返回 422。
- **工作台权限收口**：统计项先判权限再查询，日志趋势与文件类型按权限裁剪；菜单可见性父节点查找改用 `by_parent` 索引。
- **新增命令**：`python -m cccms.cli audit-verify`（校验审计链）、`python -m cccms.dev`（同时起 API 与调度器）。
- **新增清理任务**：平台租户的「清理过期导出文件」「清理未完成分片」。
- **测试**：新增 `backend/tests/test_helpers.py`，覆盖文件名清洗、字段掩码、CSV 注入防护、租户到期、生成器命名、角色最小委派、错误码与缓存失效范围。
