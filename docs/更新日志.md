# 更新日志

> 只记录**已交付的变更**与**已决策不做的事项**。
> 计划中的工作见 [开发计划](开发计划.md)；机制与用法见对应专题文档（索引见 [README](README.md)）。
> **不设版本号、不区分已发布 / 未发布**：按日期倒序，前后端分列。
> 每条固定三段：`【分类】功能名称` → `问题内容` → `修复内容`；分类只有 `安全 / 新增 / 变更 / 修复 / 移除 / 性能与可观测 / 工程化 / 文档` 八类。
> 已决策不做的事项集中在文末 [附录 · 明确不做](#附录--明确不做)。

## 分类口径

| 分类 | 用于 | 问题内容写什么 | 修复内容写什么 |
|------|------|----------------|----------------|
| 安全 | 漏洞、暴露面、权限收口 | 原风险与触发条件 | 拦截点、生效前提 |
| 新增 | 新能力 / 新接口 / 新页面 | 原来缺什么、痛在哪 | 落地形态与边界 |
| 变更 | 既有行为、结构、默认值调整 | 原行为 | 新行为 + 存量兼容动作 |
| 修复 | 缺陷 | 现象 + 根因 | 改了哪几处 |
| 移除 | 下线能力 / 删代码 | 为什么留不住 | 删了什么 + 存量怎么清 |
| 性能与可观测 | 缓存、索引、指标、探活 | 原瓶颈或盲区 | 实现要点 |
| 工程化 | CI、静态分析、测试、构建、脚本 | 原缺口 | 接入方式 |
| 文档 | docs 与代码同步 | 原漂移点 | 补了哪篇 |

## 2026-10-22

### 后端

- **【安全】代码生成器仅限本地开发环境**
  - 问题内容：`tables` / `columns` / `preview` / `generate` 四个接口只挂 `#[Permission]`，生成器直接写 `server/` 与 `frontend/` 下的 PHP / TS / Vue 文件，与在线升级同级风险——生产环境只要角色授权配错就能写文件。
  - 修复内容：
    - 新增 `GeneratorLogic::ensureAvailable()`，两道闸：① 目录自检（`Environment::isDevLayout()`，仓库根存在 `frontend/package.json` 才算开发态）；② 开关 `plugin.cccms.generator.enable`（环境变量 `CCCMS_GENERATOR_ENABLE`，**默认 `false`**）。
    - 四个接口任一闸不过一律返回 `403`，**与权限节点无关**。

- **【安全】生产启动硬门槛扩容**
  - 问题内容：`DB_USERNAME` / `DB_PASSWORD` 缺失时回退到仓库里公开的默认口令（`root/123456`）；`APP_DEBUG=true` 会把异常详情（含 SQL 片段与绝对路径）返回给客户端；`CORS_ORIGIN=*` 意味着任何站点都能代表用户发起请求。
  - 修复内容：
    - 三项改为生产环境**拒绝启动**（`support/SecurityBootstrap.php`）。
    - `DATA_ENCRYPT_KEY` 保持**仅告警**：换密钥会让历史加密字段永久不可解，硬失败代价不可逆，与本组区别对待。
    - 「生产」判定走 `Environment::isDevLayout()`，与在线升级同口径。

- **【修复】导出任务僵死回收**
  - 问题内容：`ExportTask` 认领时置 `running`，`download()` 只兜底 `pending`、`cleanup()` 只管 `done` 过期，无人处理 `running`；生成进程被 kill / 重启后任务永久停在「导出中」，前端顶栏角标永不归零。
  - 修复内容：新增 `ExportTask::reconcileStale()`，`running` 超过 `DEFAULT_STALE_MINUTES`（30 分钟）即判定「生成进程已中断」并置为失败；在 `consume()` 开头与 `download()` 两处调用。

- **【变更】应用版本号单一定义**
  - 问题内容：后端没有版本号字面量（复核确认「`config/app.php` 已有 version」是误报），前端 `package.json` 为 `0.1.0`，两者无从对齐、必然漂移。
  - 修复内容：
    - `server/config/app.php` 新增 `version`（当前 `0.1.0`）作为后端唯一字面量，发布时只改这一处。
    - 新增 `tests/cases/VersionTest.php`：断言版本号为 `x.y.z` 且与 `frontend/package.json` 一致。
    - `LogChain::VERSION` 是**哈希算法版本**，与产品版本无关，不要混用。

### 前端

## 2026-10-18

### 后端

- **【安全】JWT 密钥不再回退默认值**
  - 问题内容：`JWT_SECRET` 未配置时静默回退硬编码默认值，任何人拿到源码即可伪造令牌；`.env` 从未被加载（缺 `vlucas/phpdotenv` 依赖），配置全部静默回落默认值。
  - 修复内容：`JWT_SECRET` 未配置或不足 32 字节时，`support/SecurityBootstrap.php` 在启动期直接失败；补齐 `vlucas/phpdotenv` 依赖。

- **【安全】消除同域存储型 XSS**
  - 问题内容：上传白名单放行 `svg`，同域直链可执行脚本，等于把 `/storage` 变成任意 JS 托管点。
  - 修复内容：
    - 上传白名单移除 `svg`。
    - `StorageDriver` 增加危险扩展名硬拒绝名单（`svg` / `html` / `xml` / `mhtml` 等）与魔数校验。
    - 新增中间件 `app/middleware/StorageGuard.php`：`/storage/` 下非图片 / PDF 强制 `Content-Disposition: attachment`，全局下发 `X-Content-Type-Options: nosniff`。

- **【安全】附件匿名可读改为「单个附件开关 + 后台总开关」**
  - 问题内容：`/storage/*` 直链对所有人可读，私有附件没有任何收口手段。
  - 修复内容：
    - `sys_file` 新增 `is_public`（默认 `1`，兼容存量）：关闭后该附件的 `/storage` 直链**立即 403**，只能登录后经 `GET /file/download` 读取（登录态 + 数据权限；越权 403、不存在 404）。
    - 后台配置新增「允许匿名访问附件」（`upload.anonymous`，默认开）：关掉后**所有**附件都必须登录后读取，不受单个附件状态影响。
    - `StorageGuard` 在**读盘前**判定：总开关 → 按路径反查 `is_public`（新增索引 `idx_path`），拒绝时 `403` + `Cache-Control: no-store`。
    - ⚠️ 生效前提不变：`/storage/*` 必须反代到后端；Nginx 直接 `root` 托管会绕过开关与响应头加固（见 [02-安装部署 §5.2](02-安装部署.md#52-publicstorage-安全硬要求)，样例 [deploy/nginx.conf.example](../deploy/nginx.conf.example)）。

- **【安全】定时任务执行身份统一**
  - 问题内容：「立即执行」继承操作者的租户与行级范围，cron 走任务属主身份，同一任务两条路径看到两份数据、写到两个租户。
  - 修复内容：
    - `CrontabRunner::run()` / `execute()` / `writeLog()` 统一按「**任务属主租户**」执行。
    - 新增 `DataScope::runAs()` / `TenantContext::runAs()`：执行期覆盖身份，`try/finally` 恢复（常驻进程不允许泄漏）。
    - 操作者只体现在 `sys_crontab_log.source = manual`；已知取舍：租户账号手动触发本租户任务时，任务内行级范围不再按该操作者收窄（与 cron 一致），这是刻意的。

- **【安全】数据权限检查新增 R3 / R4**
  - 问题内容：业务插件表默认既不参与租户隔离、数据规则也不生效，界面上却完全正常（静默放行）；模型声明 `$tenantScope = true` 的表若不在 `TenantContext::TABLES` 里，模型查询（带租户条件）与 `Db::name` 直查（不带）会出现两种结果。
  - 修复内容：
    - R3：业务插件表（`plugin/{name}/db/schema.sql` 声明、不带 `sys_` 前缀）必须满足其一 —— 登记受控表 / 自带 `tenant_id` 列 / 显式豁免，否则 `cccms:data-scope-check` 退出码 1。
    - R4：声明 `$tenantScope = true` 的表必须在 `TenantContext::TABLES` 内。
    - 豁免：新增 `config/data_scope.php` 的 `exempt_tables`（环境变量 `DATA_SCOPE_EXEMPT_TABLES`，逗号分隔完整表名）。
    - 只判定库中**真实存在**的插件表，同库其它系统的表不参与（避免误报）。

- **【安全】登录失败限流拆为账号 + IP 双维度**
  - 问题内容：单一账号维度限流无法挡住撞库——攻击者换用户名即可无限试；反之锁账号又会被用来恶意锁死他人。
  - 修复内容：键改为 `cccms:login_fail:user:{用户名}` 与 `cccms:login_fail:ip:{IP}`；IP 维度达阈值只限流该 IP、不锁账号；新增配置 `security.login_fail_ip_limit`（默认 20）。

- **【安全】全站接口限流**
  - 问题内容：此前只有登录失败限流，其余接口（含导出、导入、生成器）可被无限并发调用。
  - 修复内容：
    - `support/RateLimiter.php`（Redis 固定窗口）+ 中间件 `app/middleware/RateLimit.php`，按「每用户每路由」计数。
    - `export` / `import` / `generate` 单独更严；超限返回 `429` 与 `Retry-After` / `X-RateLimit-*`；Redis 不可用时 fail-open。

- **【安全】密码策略强化**
  - 问题内容：只有长度下限，无弱口令黑名单、无字符类别要求、不校验与账号信息的关系；`UserLogic::update` 还漏了校验。
  - 修复内容：长度上限 64、内置弱口令黑名单、字符类别数要求、不得与用户名 / 昵称 / 邮箱相同或包含；补上 `UserLogic::update` 的校验；新增 `security.password_max_length` / `security.password_strength`。

- **【安全】CORS 白名单可配置**
  - 问题内容：来源校验写死，无法按部署环境放行指定前端域名，只能整体放开。
  - 修复内容：新增 `config/cors.php`（`CORS_ORIGIN`，默认留空 = 仅同源）；命中白名单才下发整组 CORS 头并回显 Origin，带 `Origin` 时无条件 `Vary: Origin`。

- **【安全】令牌 TTL 7 天 → 2 小时 + 滑动续期**
  - 问题内容：令牌有效期 7 天且不可撤销窗口长，泄露后的可利用期过长。
  - 修复内容：
    - 剩余有效期不足 TTL 的 1/3 时签发新令牌，经 `X-Refresh-Token` 下发，前端 `api/request.ts` 静默替换。
    - `OnlineSession::rotate()` 同步迁移会话 `jti`；旧令牌不入黑名单（避免并发请求被判 401）。

- **【安全】收敛 `crypto_key` 下发范围**
  - 问题内容：`/auth/me` 对所有登录用户下发 `crypto_key`，解密能力等于绕开字段级权限。
  - 修复内容：仅持有 `cccms:data_rule*` 节点的管理员与超管可获取（`AuthLogic::mayDecryptFields()`）；规则配置页选择 `encrypt` 时提示「存储加密不等于访问控制」。

- **【安全】真实 IP 溯源**
  - 问题内容：直接采信 `X-Forwarded-For` 最左值，客户端可伪造 IP，登录限流与审计里的 IP 全不可信。
  - 修复内容：新增 `support/ClientIp.php`：仅当直连来源命中 `security.trusted_proxies`（CIDR）时才解析转发头，采用「取最右非可信 IP」算法；6 处调用点统一改走 `ClientIp::resolve()`：登录限流 / 登录日志 / 在线会话 / 操作日志 / 慢接口告警 / 找回密码限流。部署要求见 [02-安装部署 §5.4](02-安装部署.md#54-反向代理下的真实-ip-溯源必配)。

- **【安全】写入口字段白名单（防 Mass Assignment）**
  - 问题内容：Logic 写方法直接吃请求体，客户端可越权写入 `status` / `dept_id` / `role_ids` 等非表单字段。
  - 修复内容：新增 `FilterInput::only()`，13 个 Logic 的 22 个写方法显式声明 `FIELDS` 并在入口过滤；新增 `cccms:write-guard-check`（已入 CI），允许一跳委托，逃生口为 `// @write-guard-ignore`（须写理由）；代码生成器同步产出该常量，生成即合规。

- **【安全】审计日志链式哈希**
  - 问题内容：操作日志可被直接改写且无痕；即使加链，无密钥的 sha256 也挡不住有库权限的人——他改完一行可以把后续行全部重算，链校验照样通过。
  - 修复内容：
    - `sys_log` 增 `prev_hash` / `row_hash` / `hash_version`；新增单行表 `sys_log_chain` 记录链尾与校验起点。
    - 写入统一走 `support/LogChain.php`（同一事务内锁链尾，防并发分叉），操作日志与登录日志不再直接 `INSERT`。
    - **v2 起算法改为 HMAC-SHA256**（`hash_version = 2`，密钥 `AUDIT_SIGNING_KEY`）：密钥不在库里，改行后无法重算后续链。
    - 未配密钥时**写入降级**为普通插入（日志不丢、该行不入链），降级次数由 `/metrics` 的 `cccms_logchain_degraded_total` 暴露；生产环境缺密钥直接拒绝启动。
    - `cccms:log-verify` 与归档自校验按**行上记录的版本**选算法，v0/v1 历史行仍可校验。

- **【新增】审计链校验与归档协同**
  - 问题内容：归档把日志搬走后链就断了，且没有工具能定位断点是「内容被改」还是「链路残缺」。
  - 修复内容：
    - 新增 `support/LogVerifier.php` + `cccms:log-verify`（`--from` / `--to`）。
    - 可区分并定位 `content_modified` / `link_broken` / `tail_stale` / `chain_missing`，退出码非 0 即发现断点。
    - 归档额外产出 `<文件>.chain.json` 并在归档、清理后 `reanchor()`；链表缺失或库不可用时 fail-open 降级为普通插入。

- **【新增】附件公开状态接口**
  - 问题内容：附件只能整体公有，无法按单个文件收紧；也没有鉴权读取入口，私有附件前端拿不到图。
  - 修复内容：
    - `POST /file/public`：切换单个附件是否允许匿名读取（权限节点 `cccms:file:public`）。
    - `GET /file/download?id=`：私有附件的鉴权读取入口。`raw=1` 按扩展名 inline 输出（供前端 blob 预览），默认带原始文件名下载；`Content-Disposition` 同时给 ASCII 兜底名与 RFC 5987 `filename*`，中文名不乱码。

- **【新增】自动升级新增 `--force-all`**
  - 问题内容：下游落后过多时逐个文件确认代价极高，且没有「整体对齐上游」的选项。
  - 修复内容：覆盖本地已改 / 恢复本地已删 / 删除上游已移除文件，均先备份；命令行、后台页面与 `Upgrader::apply()` 三处同步支持。

- **【新增】自动升级兼容老版本 git**
  - 问题内容：依赖 `git -C`，CentOS 6/7 自带 1.7.x 报 `Unknown option: -C`，升级流程直接中断。
  - 修复内容：去掉 `git -C`，改用 `proc_open` 工作目录参数；注入 `GIT_TERMINAL_PROMPT=0`；失败时自动附本机对该源的 HTTP 探测结果与 git 版本，URL 凭据一律打码。

- **【安全】在线升级限定本地开发环境**
  - 问题内容：在线升级默认开启，任何能进后台的人都能拉取远端代码覆盖生产文件。
  - 修复内容：`upgrade.enable` 默认改为 `false`，另加目录自检（仓库根须存在 `frontend/package.json`）；被拦截时页面禁用全部升级按钮并给出原因，`cccms:update` 退出码 2；同时删除从未被 seed 注册的 `UpgradeCheckTask`。

- **【新增】导出异步化与任务中心**
  - 问题内容：导出在请求内同步生成，大表直接把请求拖到超时，且并发导出互相抢资源。
  - 修复内容：
    - 新增 `sys_export_task` 表，`GET /log/export` 及各模块导出改为一律异步。
    - 内置任务 `ExportTaskConsumer`（默认每 10 秒，消费前 `UPDATE ... WHERE status=pending` 抢占防重复）用 keyset 分页流式写 CSV。
    - 归档落在 `runtime/exports/`（不进 `public/storage`），`export.keep_minutes`（默认 60）到期清理；下载按 `user_id` 归属校验。

- **【新增】附件分片上传 / 秒传**
  - 问题内容：单请求上传大文件必撞 `upload_max_filesize` / `memory_limit`，断网即从头再来。
  - 修复内容：
    - 同一个上传按钮按体积分流，`> 10MB` 走 `init → chunk → complete` 三阶段（节点 `cccms:file:upload:chunk`），单片上限 8MB。
    - 支持断点续传与 SHA-1 秒传（≤ 64MB 由 WebCrypto 计算）；合并后校验大小与哈希，流式合并避免大文件撞 `memory_limit`。
    - 会话存 Redis（TTL 24h），`ChunkCleanTask` 每小时回收残留。

- **【新增】列表批量操作**
  - 问题内容：用户 / 岗位 / 字典只能逐条启停与删除，运维批量调整（如整批分配角色）没有入口。
  - 修复内容：用户 / 岗位 / 字典支持批量启停与删除；用户额外支持批量分配角色 / 部门 / 岗位（传哪个键就重设哪个关联）。新增 9 个接口与 9 个权限节点，统一语义为「只作用于可见行 + 跳过并回报 + 不整批失败」（`{affected, skipped[]}`）。

- **【新增】角色复制**
  - 问题内容：新建相似角色只能逐项重新勾选节点，且容易漏掉 `data_scope`。

| 事项 | 原因 |
|------|------|
| 前端 E2E（Playwright）、UI 自动化基线 | 用例随 UI 变动长期维护的成本高于收益；主链路回归由后端集成测试 + `lint` / `build` 覆盖 |
| 多因素认证 TOTP | 现有「口令策略 + 登录限流 + 图形验证码 + 2h 令牌 + 滑动续期」已覆盖，收益与改造量不成比 |
| 导入导出增强 | 用户 / 规则导入导出已下线，仅保留日志导出，不再扩展 |
| 连续失败升级为强制验证码 | 需前端登录页联动改造，成本高于收益 |
| 后端解密 + 按数据权限 mask 下发 | 改造量 5 pd+，`decryptField` 与 `cryptoKey` 目前无调用方 |
| HttpOnly 刷新令牌 | 需服务端 refresh 接口 + CSRF 防护，5 pd+；现有短 TTL + 滑动续期已缓解 XSS 面 |
| 密钥轮换（`data_encrypt_key`） | 历史加密字段将无法解密，轮换须先设计密文版本号方案 |
| 兼容老 CCCMS（ThinkPHP 8）数据 | 本仓库为全新工程 |
| 在 `plugin/cccms` 内放业务功能 | 基础与业务必须分离，业务一律新建插件 |
| `sys_config` / 关联表 / 日志的软删除 | 配置无归属、日志按天数清理 |
| 站内消息实时推送（WebSocket / SSE） | 需常驻进程 + 多实例广播 + 断线重连，现有未读角标已够用 |
| SSO 单点登录（OIDC / 企微 / 钉钉 / 飞书） | 单个 provider 3~5 pd 且需长期回归，现有账号密码链路已闭环 |
| 工作流引擎（轻量审批流） | 产品级模块，15 pd 起步，暂无落地场景 |
| 数据权限铺开到 `post` / `notice` / `dict_*` | 这些表本质是全局共享配置，加行级范围会让管理员看不到自己建的数据 |
| 前端骨架屏 | 路由切换已有 NProgress，hash 路由 + keep-alive 下白屏窗口很短 |
| 云存储直传（预签名 / STS） | 需逐驱动实现签名与前端改造；分片上传已覆盖大文件与断点续传 |
| 附件私有化 + 预签名下载 | 需签名接口 + 时效控制 + 前端全量替换 URL（4~6 pd），仅合规场景才值得 |
| API 签名防重放（timestamp + nonce + sign） | 已有 HTTPS + 短 TTL JWT + 全站限流 + `jti` 黑名单 |
| 密码历史校验 / 首次登录强制改密 / 密码过期 | 无对应场景；NIST SP 800-63B 亦不推荐强制定期改密 |
