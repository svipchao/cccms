# 文件与导出

> 附件上传（普通/分片/秒传）、存储布局、访问控制，以及导出任务的生成、下载与过期策略。

---

## 一、存储模型

| 类型 | 目录 | 访问方式 |
|------|------|----------|
| 附件 | `CCCMS_STORAGE_LOCAL_ROOT`（默认 `shared/uploads`） | `/storage/**` 需登录 + 数据权限校验 |
| 分片临时目录 | `shared/uploads/chunks/<upload_id>/` | 不对外 |
| 导出文件 | `CCCMS_EXPORT_LOCAL_ROOT`（默认 `shared/exports`） | 仅 `/api/export/task/download` |

> ⚠️ **注意**：导出目录必须在静态目录之外。导出内容含日志、业务数据，不能通过 URL 直接猜测下载。

---

## 二、附件记录

`sys_file` 关键字段：

| 字段 | 说明 |
|------|------|
| `storage` | `local` / `oss` / `cos` / `qiniu` / `s3` |
| `path` | 存储相对路径 |
| `url` | 访问地址 |
| `original_name` | 原始文件名（经过安全清洗） |
| `ext` / `mime` / `size` | 类型与大小 |
| `sha1` / `sha256` | 秒传与去重 |
| `create_by` | 上传人 |

数据权限：`owner=create_by`，部门维度经创建人所属部门推导。

## 三、普通上传

`POST /api/file/upload`，`multipart/form-data`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `file` | File | 文件 |
| `category_id` | int | 可选分类 |

流程：

1. 清洗文件名（去路径、去空字节）。
2. 校验扩展名白名单 `CCCMS_UPLOAD_EXT_ALLOW`。
3. 校验分类属于当前租户且模块为 `file`。
4. 流式写入，边写边算 SHA1/SHA256，超过 `upload_max_mb` 立即中止并删除临时文件。
5. 按 `(sha1, size)` 在当前可见范围内去重；命中则删除新文件、返回已有记录（秒传）。
6. 落库并返回 `url`。

MIME 以扩展名推导为准，客户端 `Content-Type` 仅兜底，避免伪造 `text/html`。

## 四、分片上传

### 4.1 初始化

`POST /api/file/upload/init`

```json
{
  "filename": "big.zip",
  "size": 104857600,
  "sha1": "可选的整文件 SHA1",
  "category_id": null
}
```

返回：

| 字段 | 说明 |
|------|------|
| `upload_id` | 会话 ID；秒传时为空串 |
| `instant` | 是否秒传 |
| `received` | 已上传分片序号 |
| `chunk_size` | 建议分片大小（默认 4MB） |
| `total_chunks` | 总分片数 |
| `file` | 秒传命中的文件记录 |

- 总大小受 `upload_chunk_max_mb` 限制。
- 会话元数据存 Redis，TTL 24 小时；分片文件落临时目录。
- 携带 `sha1` 时先尝试秒传。

### 4.2 上传分片

`POST /api/file/upload/chunk`，`multipart/form-data`：

| 字段 | 说明 |
|------|------|
| `upload_id` | 会话 ID |
| `index` | 从 0 开始的分片序号 |
| `file` | 分片二进制 |

- 单个分片不超过 `chunk_size + 1MB`。
- `index` 必须小于会话声明的 `total_chunks`，超出直接拒绝。
- 重复上传同一序号会覆盖。
- 会话必须属于当前用户与租户。

### 4.3 完成

`POST /api/file/upload/complete`

```json
{ "upload_id": "…", "sha1": "可选的最终校验值" }
```

流程：

1. 校验分片序号连续（0..n-1）。
2. 合并后总大小必须等于声明大小。
3. 计算 SHA1/SHA256，若声明了 SHA1 则比对。
4. 任一校验失败：删除分片目录并报错。
5. 成功：写入正式目录、落库、清理临时目录与 Redis 会话。

### 4.4 中断与清理

- Redis 会话 24 小时过期。
- 平台租户内置任务「清理未完成分片」每天 04:15 删除超过 48 小时的分片目录；非平台租户执行时会直接跳过。
- 升级已有环境后需重新执行 `seed` 才会写入该任务，或在「定时任务」页手动新增。

## 五、下载与访问控制

### 5.1 附件

- 通过 `/storage/<path>` 读取，由 `api/storage.py` 按 `sys_file.path` 反查记录并走 `apply_scope`；未登录返回 401，不可见返回 404。
- 全局响应头包含 `X-Content-Type-Options: nosniff`。
- 扩展名白名单排除了 `html` / `svg` 等可执行内容类型。
- 图片等内联资源依赖同站 Cookie 鉴权；**纯 Bearer 客户端或需要"另存为"时改用 `GET /api/file/{id}/download`**（登录即可，可见性仍由 `apply_scope` 决定，不可见与不存在同为 404；文件名取 `original_name`）。
- 附件读取仍按静态资源跳过操作日志（避免图片请求刷满 `sys_log`），审计依赖网关访问日志。
- **软删除会把文件移入 `shared/quarantine/`**（静态目录之外），旧 URL 立即 404；回收站还原时移回原路径，彻底删除时清理隔离文件。
- 秒传去重是**租户级**的：命中他人上传的同一份文件只复用存储，不返回对方的记录字段；下载/列表仍受数据范围约束。

### 5.2 导出

`GET /api/export/task/download?id=<task_id>`：

1. 任务必须属于当前用户与租户。
2. 状态必须为完成。
3. 路径必须在导出根目录内（防路径穿越）。
4. 文件不存在或过期返回 404。
5. `Content-Disposition` 使用 `type-id.ext` 作为下载名。

## 六、导出任务

### 6.1 生命周期

```text
请求导出 → 写 sys_export_task(status=0) → 后台协程流式生成(status=1→2) → 前端轮询/下载
                                                     ↓
                                               expires_at 到期
                                                     ↓
                                               文件可被清理
```

- 生成在**后台协程**里完成（`asyncio.create_task`），接口立即返回 `task_id`，不再阻塞请求。
- 后台协程复用**请求内构建好的 SQL 与字段脱敏快照**：没有 `RequestContext` 时现场调用 `apply_scope()` 会 fail-open，绝不能那样做。
- 流式读取（`session.stream(yield_per=1000)`）+ 分块写盘，不再把 10 万条 ORM 对象塞进内存。
- 并发受两道闸门保护：进程内 `CCCMS_EXPORT_MAX_CONCURRENCY`（默认 2），以及单用户未完成任务数 `CCCMS_EXPORT_MAX_ACTIVE_PER_USER`（默认 2），超限返回 409。
- 失败会把 `status` 置为 3 并在 `error` 里留下原因，不会静默无结果。
- 前端「导出任务」面板展示进度与下载入口；任务按用户隔离，列表只返回自己的任务。

### 6.2 日志导出

- 最多 `EXPORT_MAX_ROWS=100000` 行。
- 列固定：ID、用户名、状态、消息、方法、路径、节点、标题、链路 ID、IP、状态码、耗时、时间。
- CSV 注入防护：以 `= + - @` 开头的单元格前加单引号。
- 文件名由服务端生成，避免用户输入进入路径。

### 6.3 过期与清理

- 下载前校验 `expires_at`，到期返回 404。
- 平台租户内置任务「清理过期导出文件」每天 04:00 删除过期任务记录与物理文件。
- 任务文件删除前会再次校验路径必须位于导出根目录内。
- 升级已有环境后需重新执行 `seed` 才会写入该任务。
- 另有两个保留期任务：`cccms.crontabLog.clean`（任务日志 30 天）、`cccms.noticeRead.clean`（已读回执 90 天），都是按 5000 行分批删除，避免长事务锁表。

## 七、安全要点

| 风险 | 防护 |
|------|------|
| 路径穿越 | 文件名清洗 + 导出路径必须位于根目录内 |
| 可执行文件 | 扩展名白名单 + nosniff |
| MIME 伪造 | 以扩展名推导为准 |
| 磁盘打满 | 单文件上限 + 分片总量上限 + 磁盘健康检查 |
| 已删除附件仍可下载 | 软删除移入隔离区，静态 URL 立即失效 |
| 越权下载 | 导出任务校验用户/租户与过期时间；附件按数据范围查询 |
| CSV 注入 | 危险前缀加单引号 |
| 秒传信息泄露 | 去重按 `tenant_id + sha1 + size` 复用存储，不回显他人记录字段 |
| 分片会话劫持 | 会话绑定用户与租户，不匹配返回 403 |

---

## 八、运维建议

- 分片与导出由内置任务自动清理；`shared/quarantine` 可在确认回收站不再需要还原后人工清理。
- 监控磁盘使用率，`/healthz` 低于阈值会返回 503。
- 大文件上传建议走分片，并在前端计算 SHA1 以启用秒传。
- 备份时同时备份 `shared/uploads`；`shared/exports` 可按需备份。
- 切换到对象存储时，`storage` 字段记录驱动类型，URL 由驱动生成；下载鉴权逻辑不变。
