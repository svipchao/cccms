# 身份安全

> 从账号、口令、令牌、会话到租户边界，说明身份相关的安全默认值与可运营手段。接口清单见 [07-功能模块](07-功能模块.md)，机制细节见 [05-鉴权与权限](05-鉴权与权限.md)。

---

## 一、威胁模型

| 威胁 | 防护 |
|------|------|
| 口令爆破 | Argon2id、登录失败限流、图形验证码 |
| 弱口令 | 长度 + 复杂度 + 弱口令字典 + 账号关联校验 |
| 令牌窃取 | 短 TTL、HttpOnly Cookie 可选、吊销水位、在线会话可见 |
| 会话固定 | 登录签发新 `jti`，续期轮换 `jti` |
| CSRF | Cookie 会话写请求校验 `X-CSRF-Token` |
| 跨租户 | `tenant_id` 硬边界 + 域名锁定 + 超管切换审计 |
| 内部越权 | 权限节点 + 数据范围 + 字段级规则 |
| 凭据泄露 | 密钥环境变量、生产启动校验、日志脱敏 |
| 账号残留 | 软删除、令牌吊销、在线会话清理 |

## 二、账号生命周期

```text
创建（管理员） → 启用 → 登录 → 改密/重置 → 停用 → 软删除 → 回收站还原/彻底删除
```

### 2.1 创建

- 用户名在租户内唯一（唯一键含 `active_flag`）。
- 口令必须通过复杂度校验。
- 至少分配一个启用角色，否则无法登录。
- 创建人、创建时间入库，操作日志记录。

### 2.2 停用

- `status=0` 后无法登录，已签发令牌在下一次请求加载用户上下文时失效。
- 在线会话可能仍短暂存在，建议同时「强制下线」。

### 2.3 删除

- 软删除写 `delete_time`，`active_flag` 置 NULL，释放用户名/邮箱。
- 非超管不能删除超管账号；批量删除会跳过超管与自己。
- 彻底删除在回收站执行，物理删除用户与关联表。

### 2.4 密码重置

- 管理员重置：生成新口令，吊销目标用户全部令牌与在线会话。
- 用户自助找回：验证码 → 重置 → 吊销全部令牌。
- 两种方式都写操作日志，记录操作者与目标用户。

## 三、口令

| 项 | 值 |
|----|-----|
| 哈希算法 | Argon2id |
| 参数 | `time_cost=3`、`memory_cost=64MB`、`parallelism=4`、`hash_len=32` |
| 最小/最大长度 | 8 / 128 |
| 复杂度 | 大写、小写、数字、符号至少两类 |
| 弱口令 | 内置字典直接拒绝 |
| 账号关联 | 不能等于或包含用户名/昵称/邮箱 |
| 重哈希 | 登录时检测参数升级 |

> ⚠️ **注意**：`validate_password()` 只做规则校验，不负责通知用户；前端应同步提示规则，避免提交后才报错。

## 四、令牌安全

### 4.1 签发

- HS256，`iss=cccms`，包含 `sub/tid/hid/iat/nbf/exp/jti`。
- 默认 TTL 7200 秒。
- 登录成功后同时写在线会话。

### 4.2 校验

每次请求：

1. 解析令牌（签名、过期、生效时间、必需字段）。
2. 检查 `jti` 黑名单。
3. 检查用户签发水位（改密后旧令牌失效）。
4. 检查租户与域名是否匹配。
5. 加载用户、角色、权限、数据范围。
6. 维护模式检查（超管豁免）。
7. 限流。

### 4.3 吊销

| 场景 | 行为 |
|------|------|
| 退出登录 | 当前 `jti` 入黑名单，移除在线会话 |
| 踢下线 | 指定 `jti` 入黑名单 |
| 踢用户 | 该用户全部令牌入水位，清空会话 |
| 修改/重置密码 | 同上 |
| 停用/删除用户 | 上下文加载失败，令牌自然失效 |

### 4.4 存储

- SPA 默认 `localStorage`，请求头 Bearer。
- 同域部署可改用 HttpOnly Cookie；此时必须启用 CSRF 校验。
- 不要把令牌写进 URL、日志、错误上报。

## 五、会话可见性

- 用户可在「个人中心 → 我的登录设备」查看自己的会话：IP、UA、登录时间、最后活跃、过期时间。
- 管理员可在「在线用户」查看当前租户会话，并按用户/用户名/IP/时间筛选。
- 在线列表按租户隔离，踢人只能踢本租户会话。
- 会话数据存 Redis，TTL 与令牌一致。

> **提示**：会话里的 `device` / `os` / `browser` 由 User-Agent 推导，仅用于展示，不参与安全判断。

## 六、租户边界

| 场景 | 规则 |
|------|------|
| 域名绑定 | Host 命中 `sys_tenant.domain` 即锁定租户 |
| 手动选择 | 未绑定域名时登录页可选 |
| 默认租户 | 未选择时用 `CCCMS_LOGIN_DEFAULT_TENANT` |
| 切换租户 | 仅超管；重新签发令牌 |
| 跨租户访问 | 域名与令牌租户不一致直接拒绝 |
| 平台能力 | 租户管理、菜单写入要求平台租户 + 超管 |

详见 [18-平台与运维](18-平台与运维.md#一多租户运营)。

## 七、登录风控

| 手段 | 说明 |
|------|------|
| 图形验证码 | 按租户配置 `security.login_captcha` |
| 失败计数 | 按「租户 + 用户名」与 IP 双维度 |
| 限流 | Redis 计数，窗口内超过阈值拒绝 |
| 登录分析 | 失败趋势、异常 IP、登录时段 |
| 审计 | 登录成功/失败都写 `sys_log` |

> **提示**：限流与验证码依赖 Redis。Redis 不可用时系统降级放行，但启动日志会告警；生产必须保证 Redis 高可用。

## 八、密钥管理

| 密钥 | 用途 | 轮换影响 |
|------|------|----------|
| `CCCMS_JWT_SECRET` | 令牌签名 | 轮换后所有令牌失效，用户需重新登录 |
| `CCCMS_DATA_ENCRYPT_KEY` | 配置与字段加密 | 轮换前必须解密再重新加密 |
| `CCCMS_AUDIT_SIGNING_KEY` | 审计链签名 | 轮换后旧批次用旧 key_id 校验 |
| `CCCMS_SECRET_KEY` | 通用密钥 | 视使用点而定 |

要求：

- 生产启动校验长度与非空。
- 不写入代码仓库、不通过接口回显。
- 备份时单独加密保管。
- 轮换需停机窗口与回滚预案。

## 九、MFA 现状

`sys_user` 已预留 `mfa_enabled`、`mfa_secret_enc` 字段，依赖中也包含 `pyotp`，但**当前没有启用 MFA 登录流程**。

> 待补充：MFA 绑定、验证、恢复码、管理员强制策略。接入前不要在任何界面宣称已支持。

## 十、安全基线检查

- [ ] 初始管理员密码已修改
- [ ] 超管数量 ≤ 2 且启用登录告警
- [ ] 生产 `CCCMS_COOKIE_SECURE=true`
- [ ] 令牌 TTL 与业务风险匹配（默认 2 小时）
- [ ] 离职/转岗账号及时停用并踢下线
- [ ] 定期检查 `sys_log` 的失败登录与高危操作
- [ ] 找回密码通道已接入真实网关（否则生产会 503）
- [ ] 审计链定期校验
- [ ] 密钥备份可用、轮换有记录
