# 数据模型

> 28 张表的字段语义、枚举、约束与软删除约定。模型源码在 `backend/src/cccms/models/`，公共基类在 `db/base.py`。

---

## 一、公共约定

### 1.1 基类

| Mixin | 字段 | 说明 |
|-------|------|------|
| `BaseModel` | `id`、`create_time`、`update_time` | 主键 BIGINT 自增，时间 DATETIME |
| `TenantMixin` | `tenant_id` | 租户硬边界；全局表除外 |
| `SoftDeleteMixin` | `delete_time` | 非空表示已删除 |
| `ActiveFlagMixin` | `active_flag` | 未删除为 1，软删后置 NULL |

### 1.2 为什么唯一键包含 `active_flag`

MySQL 唯一索引把 `NULL` 视为互不相等。软删除时把 `active_flag` 置 `NULL`，即可让同一租户下重复使用编码/用户名，同时保留历史行。

典型约束：

```sql
UNIQUE KEY uq_dict_type (tenant_id, type, active_flag)
UNIQUE KEY uq_user_username (tenant_id, username, active_flag)
```

> ⚠️ **注意**：业务代码做唯一性校验时也必须加 `delete_time IS NULL`，否则会把已删除行当成冲突。

### 1.3 枚举

| 字段 | 值 |
|------|-----|
| 通用 `status` | `1` 启用 / `0` 停用 |
| `sys_menu.type` | `1` 目录 / `2` 菜单 / `3` 按钮 |
| `sys_role.data_scope` | `1` 全部 / `2` 本部门及以下 / `3` 本部门 / `4` 仅本人 / `5` 自定义 |
| `sys_notice.type` | `1` 通知 / `2` 公告 / `3` 提醒 |
| `sys_notice.level` | `1` 普通 / `2` 重要 / `3` 紧急 |
| `sys_notice.scope` | `1` 全员 / `2` 部门 / `3` 角色 / `4` 用户 |
| `sys_log.status` | `1` 成功 / `0` 失败 |
| `sys_export_task.status` | `1` 处理中 / `2` 完成 / `3` 失败 |
| `sys_crontab.overlap` | `skip` 跳过 / `allow` 允许并发 |
| `sys_data_rule.action` | `row` / `hidden` / `readonly` / `mask` / `encrypt` |
| `sys_data_rule.bind_mode` | `or` / `and` |
| `sys_data_rule.value_type` | `static` / `dynamic` |

## 二、租户与账号

### 2.1 `sys_tenant`

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | VARCHAR(64) | 唯一编码 |
| `name` | VARCHAR(128) | 名称 |
| `domain` | VARCHAR(255) | 绑定域名，唯一 |
| `is_platform` | SMALLINT | 平台租户标记，仅初始化脚本写入 |
| `status` | SMALLINT | 启用/停用 |
| `expire_at` | DATETIME | 到期时间 |
| `contact` | VARCHAR(128) | 联系人 |
| `max_users` | SMALLINT | 用户上限，0 表示不限 |

### 2.2 `sys_user`

| 字段 | 说明 |
|------|------|
| `username` / `password_hash` | 登录名与 Argon2 哈希 |
| `nickname` / `avatar` / `email` / `phone` | 资料 |
| `status` | 启用/停用 |
| `last_login_at` / `last_login_ip` | 最近登录 |
| `password_changed_at` | 改密时间，用作令牌失效水位 |
| `mfa_enabled` / `mfa_secret_enc` | 预留 MFA 字段（当前未启用） |
| `remark` | 备注 |

约束：`(tenant_id, username, active_flag)` 与 `(tenant_id, email, active_flag)` 唯一；索引 `(tenant_id, status)`。

### 2.3 关联表

| 表 | 字段 | 说明 |
|----|------|------|
| `sys_user_role` | `user_id`、`role_id` | 用户角色 |
| `sys_user_dept` | `user_id`、`dept_id` | 用户多部门 |
| `sys_user_post` | `user_id`、`post_id` | 用户岗位 |
| `sys_role_node` | `role_id`、`node` | 角色权限节点 |
| `sys_dept_role` | `dept_id`、`role_id` | 部门默认角色（数据权限扩展） |

## 三、组织与权限

### 3.1 `sys_dept`

| 字段 | 说明 |
|------|------|
| `parent_id` | 上级部门，自引用 `RESTRICT` |
| `name` / `leader` / `phone` / `email` | 部门信息 |
| `sort` / `status` | 排序与状态 |
| `path` | 祖先路径，如 `/1/3/`，用于子树查询 |
| `level` | 层级，从 1 开始 |

### 3.2 `sys_post`

`code`、`name`、`sort`、`status`、`remark`；`(tenant_id, code, active_flag)` 唯一。

### 3.3 `sys_role`

| 字段 | 说明 |
|------|------|
| `code` | 唯一编码，`super_admin` 保留 |
| `name` | 角色名 |
| `parent_id` | 父角色，继承权限节点 |
| `data_scope` | 数据范围，默认 4 |
| `is_system` | 系统内置角色 |
| `status` / `sort` / `remark` | 状态、排序、备注 |

### 3.4 `sys_menu`

| 字段 | 说明 |
|------|------|
| `parent_id` | 父节点 |
| `type` | 1 目录 / 2 菜单 / 3 按钮 |
| `title` / `path` / `component` / `icon` | 展示与路由 |
| `sort` / `status` / `keep_alive` | 排序、状态、缓存 |
| `node` | 权限节点，按钮必填 |

全局共享表，不参与租户隔离；写操作要求平台租户 + 超管。

## 四、字典与配置

### 4.1 `sys_category`

| 字段 | 说明 |
|------|------|
| `module` | 归属模块：`dict` / `file` |
| `parent_id` | 上级分类 |
| `name` / `sort` / `status` | 名称、排序、状态 |

索引：`(tenant_id, module)`。

### 4.2 `sys_dict_type`

`category_id`（`SET NULL`）、`type`、`name`、`status`、`remark`。

唯一：`(tenant_id, type, active_flag)`。

### 4.3 `sys_dict_data`

`type_id`（`CASCADE`）、`value`、`label`、`tag`、`sort`、`status`、`remark`。

唯一：`(tenant_id, type_id, value, active_flag)`；索引 `(tenant_id, type_id)`。

### 4.4 `sys_config`

| 字段 | 说明 |
|------|------|
| `tenant_id` | 可空：NULL 为全局默认 |
| `scope_key` | 生成列 `coalesce(tenant_id, 0)`，参与唯一键 |
| `group_key` | 分组，默认 `system` |
| `name` / `title` | 键与显示名 |
| `type` | `input` / `number` / `switch` / `select` / `json` / `secret` 等 |
| `value` | 值；`secret` 存 `enc:` 前缀密文 |
| `options` | 下拉选项等 JSON |
| `sort` / `status` / `remark` | 排序、状态、备注 |

唯一：`(scope_key, name)`；索引 `(group_key, sort)`。

## 八、日志与审计

### 8.1 `sys_log`

| 字段 | 说明 |
|------|------|
| `tenant_id` / `user_id` / `username` | 归属 |
| `status` / `message` / `status_code` | 结果 |

## 十、索引与级联

| 表 | 关键索引 | 级联 |
|----|----------|------|
| `sys_user` | `(tenant_id, username, active_flag)` | 关联表 `CASCADE` |
| `sys_role` | `(tenant_id, code, active_flag)` | 关联表 `CASCADE` |
| `sys_dept` | `(tenant_id, parent_id)` | 父部门 `RESTRICT` |
| `sys_dict_type` | `(tenant_id, type, active_flag)` | 分类 `SET NULL` |
| `sys_dict_data` | `(tenant_id, type_id, value, active_flag)` | 类型 `CASCADE` |
| `sys_config` | `(scope_key, name)` | 租户 `CASCADE` |
| `sys_file` | `(tenant_id, create_by)`、`(tenant_id, sha1)` | 分类 `SET NULL` |
| `sys_log` | `(tenant_id, create_time)`、`trace_id` | — |
| `sys_notice_read` | `(notice_id, user_id)` | 通知 `CASCADE` |

> ⚠️ **注意**：`sys_dict_data.type_id` 为 `CASCADE`，删除字典类型会连带删除其数据；删除前请确认影响范围。
