# 框架介绍

> 讲清楚一次请求从进入到返回经历了什么，以及 `api / services / models / core` 四层各自负责什么。

---

## 一、应用装配

入口在 `backend/src/cccms/main.py`：

```python
app = create_app()
```

`create_app()` 依次完成：

1. 读取 `Settings`（环境变量 + `backend/.env`）。
2. 创建 `FastAPI`，生产环境关闭 `/docs`、`/redoc`、`/openapi.json`。
3. 注册中间件（注册顺序与执行顺序相反）。
4. 安装统一异常处理器。
5. 挂载公共路由（`/ping`、`/healthz`、`/metrics`）与业务路由（同时挂 `/api` 与 `/api/v1`，旧前缀保留一个发布周期）。
6. 挂载附件读取路由 `/storage`（需登录 + `apply_scope()` 数据权限校验，不再是静态目录）。
7. 执行 `assert_route_declarations(app)`，任何缺少权限声明的路由都会导致启动失败。

### 1.1 生命周期

`lifespan` 负责：

- 生产环境密钥校验（不合格直接拒绝启动）。
- 创建 `shared/uploads` 与 `shared/exports`。
- Redis 连通性探测（失败只告警，不阻断启动）。
- 启动/停止操作日志后台写入协程。
- 关闭时释放 Redis 与数据库连接池。

## 二、请求生命周期

```text
请求
 │
 ├─ CORS（最外层，按需）
 ├─ GZip
 ├─ RequestGuardMiddleware（请求超时 / 请求体体积守卫，在上下文之外先挡）
 ├─ RequestContextMiddleware
 │    ├─ 解析 Host → 租户
 │    ├─ 生成 trace_id，读取 X-Action-Id / X-Session-Id
 │    ├─ CSRF 校验（仅 Cookie 会话的写请求）
 │    ├─ 写入安全响应头
 │    └─ 绑定 ContextVar
 ├─ OperationLogMiddleware
 │    ├─ 读取请求体（JSON ≤ 64KB）
 │    ├─ 记录状态码、耗时、响应摘要
 │    └─ 投递到异步日志队列
 ├─ 路由依赖
 │    ├─ load_user()：解析令牌、加载用户与权限、续期、在线会话
 │    └─ permission_dependency()：登录态 + 权限节点 + 方法白名单
 ├─ 路由函数（api）
 │    └─ 调用 services
 ├─ services
 │    ├─ apply_scope() 数据权限
 │    ├─ 领域校验
 │    └─ commit()
 └─ 响应封装 ApiResponse
```

### 2.1 中间件顺序

Starlette 的中间件按**注册的逆序**包裹，因此代码中最后注册的 `CORSMiddleware` 在最外层，最先注册的 `OperationLogMiddleware` 最靠近路由。

> ⚠️ **陷阱**：调整 `add_middleware` 顺序会改变 CSRF、日志、CORS 的相对位置。新增中间件时先确认它需要读取请求体还是响应体。

### 2.2 请求上下文

`core/context.py` 用 `ContextVar` 保存 `RequestContext`：

| 字段 | 说明 |
|------|------|
| `trace_id` | 每次请求生成，响应头 `X-Trace-Id` |
| `action_id` | 前端一次页面动作，多个请求共享 |
| `session_id` | 一次浏览器会话 |
| `tenant` | 当前租户（域名识别或令牌携带） |
| `tenant_locked` | 是否由域名锁定 |
| `user` | 登录后由 `load_user()` 填充 |
| `plan` | 权限集合、数据范围、自定义部门 |
| `auth_error` | 认证失败原因，供 401 文案使用 |
| `response_headers` | 需要附加到响应的头 |
| `extra` | 令牌下发/清除、CSRF 等临时标记 |

业务代码通过 `current_context()` / `require_context()` 读取，不通过函数参数层层传递。

## 三、分层职责

### 3.1 路由层 `api/`

只做四件事：

1. 声明路径、方法、`response_model`。
2. 声明访问策略：`@permission` / `@no_auth` / `@no_login`。
3. 声明入参（`Query` / `Body` / `Path` / `File`）。
4. 调用服务并包 `ok(...)`。

禁止在路由层写 SQL、事务、跨表校验。

### 3.2 业务层 `services/`

- 事务边界：一个业务动作一次 `commit()`。
- 数据权限：查询前 `apply_scope()`。
- 领域规则：唯一性、父子关系、租户归属、状态机。
- 复杂查询：分页、排序白名单、聚合。

服务函数签名统一把 `session` 与 `actor: UserContext` 放前面，便于测试与审计。

### 3.3 模型层 `models/`

- 纯声明，不写业务方法。
- 公共字段来自 `db/base.py` 的 mixin。
- 关系和级联策略在 `__table_args__` / `ForeignKey(ondelete=...)` 中声明。

### 3.4 基础设施 `core/`

与业务无关的横切能力：认证、权限、范围、缓存、限流、审计、导出、配置、时间、网络、脱敏。

## 四、数据库会话

`db/session.py` 提供：

| 对象 | 用途 |
|------|------|
| `get_engine()` | 进程级 async engine，连接池大小由 `CCCMS_DB_POOL_SIZE` 控制 |
| `get_session()` | FastAPI 依赖，每请求一个 `AsyncSession` |
| `session_scope()` | 后台任务/脚本用上下文管理器，自动提交或回滚 |

约定：

- 路由不调用 `commit()`。
- 服务内部完成事务；跨服务组合时由最外层服务提交。
- 只读查询不需要显式事务，避免长事务占用连接。

## 五、统一响应与异常

### 5.1 响应信封

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "trace_id": "…",
  "action_id": "…",
  "session_id": "…"
}
```

- `code=0` 表示成功，非 0 为业务错误。
- 分页数据统一为 `{ "total": n, "list": [...] }`。
- 时间统一 `YYYY-MM-DD HH:MM:SS`。

### 5.2 异常

`core/errors.py` 定义业务异常基类：

| 异常 | HTTP | 场景 |
|------|------|------|
| `ValidationFailed` | 422 | 参数或业务校验失败 |
| `Unauthorized` | 401 | 未登录、令牌失效 |
| `Forbidden` | 403 | 权限不足、租户不匹配 |
| `NotFound` | 404 | 资源不存在或不可见 |
| `Conflict` | 409 | 唯一键冲突、状态冲突 |
| `MethodNotAllowed` | 405 | 路由方法不在声明白名单 |
| `ServiceUnavailable` | 503 | 外部依赖不可用 |

未捕获异常由统一处理器转为 500，并写入日志；生产环境不返回堆栈。

## 六、配置管理

两层配置：

| 层 | 来源 | 变更方式 |
|----|------|----------|
| 进程配置 | 环境变量 / `.env` | 修改后重启 |
| 业务配置 | `sys_config` 表 | 后台「系统配置」页面，Redis 缓存 |

业务配置支持租户覆盖：

- `tenant_id IS NULL` 的行为全局默认值。
- 租户保存时不会修改全局行，而是复制一份 `tenant_id` 覆盖行。
- 读取时先取租户行，再回退全局行。

详见 [18-平台与运维](18-平台与运维.md#二配置中心)。

## 七、后台任务

| 任务 | 载体 | 说明 |
|------|------|------|
| 操作日志落库 | 进程内异步队列 | `core/audit.py`，批量写入，避免阻塞请求 |
| 定时任务 | `cccms.scheduler` 独立进程 | 扫描 `sys_crontab`，Redis 锁 |
| 审计封存 | 内置定时任务 | 每 10 分钟封存一批日志摘要 |
| 日志清理 | 内置定时任务 | 默认保留 30 天，按租户隔离 |
| 导出生成 | 进程内后台协程 | `asyncio.create_task` + 信号量（`export_max_concurrency`），`shutdown_exports()` 挂在 lifespan 关闭阶段 |

> **提示**：导出不在请求内生成，调用方拿到任务 id 后轮询状态。正常重启会把在跑的任务标为失败（`CancelledError` 分支）；进程被强杀则记录停在「处理中」，等 `expires_at` 到期后由内置任务「清理过期导出文件」一并删除。

## 八、扩展点

| 需求 | 扩展位置 |
|------|----------|
| 新增业务模块 | `models` → `schemas` → `services` → `api` → `api/__init__.py` 注册 |
| 新增存储驱动 | 实现 `services/storage/base.py` 的协议 → 在 `services/storage/__init__.py` 的 `_BUILDERS` 注册 → 加进 `config.IMPLEMENTED_STORAGE_DRIVERS`（不在白名单里的取值启动即失败） |
| 新增通知通道 | 见 [15-通知与集成](15-通知与集成.md) |
| 新增权限节点 | 在路由上加 `@permission`，执行 `seed` 同步菜单 |
| 新增定时任务 | `services/crontab.py` 的 `TASKS` 注册表 |
| 新增审计动作 | 无需改代码，中间件按路由元数据自动记录 |
