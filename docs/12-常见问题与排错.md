# 常见问题与排错

> 按现象查。每条给「原因 → 定位 → 处理」，机制细节链接回专题文档。

---

## 一、登录与会话

### 1.1 登录一直提示「账号或密码错误」

- 确认租户选择正确；同名账号可能存在于多个租户。
- 确认用户未被软删除且 `status=1`。
- 确认 `CCCMS_LOGIN_DEFAULT_TENANT` 指向的租户存在。
- 直接查库：

```sql
SELECT id, tenant_id, username, status, delete_time FROM sys_user WHERE username = 'admin';
```

- 若密码被重置过，使用 `cli seed` 不会覆盖已有用户密码，需要管理员重置。

### 1.2 登录成功但立刻 401

- 用户没有任何**启用**角色：`load_user_context()` 要求至少一个直连角色。
- 角色被停用或软删。
- 令牌被吊销（改密、重置密码、强制下线）。
- 检查 Redis `cccms:token:cut:<user_id>` 是否大于令牌 `iat`。

### 1.3 刷新页面后跳登录

- 前端令牌存在 `localStorage.cccms_token`，检查是否被浏览器清理。
- 后端返回 401 时前端会清令牌并跳转。
- 多标签页同时退出会互相影响，属于预期。

### 1.4 一直提示「验证码错误」

- 租户配置 `security.login_captcha` 与验证码接口的租户不一致（当前实现已统一按租户读取）。
- 验证码已过期或被重复使用。
- Redis 不可用导致验证码写入失败，看启动日志的 Redis 告警。

## 二、权限

### 2.1 菜单不显示

1. 菜单 `status=1`、`delete_time IS NULL`。
2. 角色是否授权了菜单节点。
3. 用户是否直接拥有该角色。
4. 前端是否已刷新菜单（登出重进或「刷新菜单」）。

### 2.2 按钮不显示

- `v-auth` 的节点拼写与后端 `@permission` 不一致。
- 角色只有菜单节点，没有按钮节点。
- 执行 `seed` 同步节点后，到角色管理重新勾选。

### 2.3 接口 403「权限不足」

- 节点未授权。
- 用户的角色继承链超过 5 层。
- 父角色被停用，继承链断开。
- 非超管访问平台级接口（租户管理、菜单写入）。

### 2.4 接口 405

- 路由声明了 `methods=["POST"]`，但前端用了 GET（或相反）。
- 看响应 `Allow` 头确认允许的方法。

### 2.5 切换租户失败

- 只有超管可以切换。
- 域名锁定的租户不能通过切换绕过；请用对应域名访问。

## 三、请求与参数

### 3.1 422 参数错误

- 看响应 `detail` / `message` 定位字段。
- 常见原因：数字传成字符串、必填为空、`status` 不在 0/1、日期格式不是 `YYYY-MM-DD HH:MM:SS`。
- `StrictModel` 会忽略未声明字段，不会因为多传字段报 422。

### 3.2 前端传了筛选条件但后端不生效

- 检查后端接口是否声明了该查询参数。
- 检查参数名是否一致（如 `original_name` / `keyword`）。
- 列表接口是否把 `params` 原样传给服务。

### 3.3 上传大文件 413

- Nginx `client_max_body_size` 太小。
- 普通上传受 `CCCMS_UPLOAD_MAX_MB` 限制，大文件请用分片上传。
- 分片接口字段名是 `file`，`upload_id` 与 `index` 用表单字段。

### 3.4 分片上传 422

- `index` 必须是数字。
- `upload_id` 必须来自 `/file/upload/init`。
- 分片字段名必须是 `file`。
- 分片大小不能超过 `upload_chunk_size`（默认 4MB）。

## 四、文件与导出

### 4.1 附件 404

- `/storage` 未代理/未挂载。
- 文件在磁盘上被清理，但数据库记录还在。
- 附件属于其他租户，URL 被手改。

### 4.2 导出下载 404

- 导出任务已过期或被清理。
- 记录存在但文件被删除。
- `CCCMS_EXPORT_LOCAL_ROOT` 指向了错误目录。

### 4.3 导出文件能被匿名下载

- 检查是否把 `shared/exports` 配成了 Nginx 静态目录；必须移除该配置。
- 导出文件只能通过 `/api/export/task/download` 下载。

### 4.4 导出内容为空

- 筛选条件过严。
- 数据权限把结果收窄为 0 行。
- 日志导出有行数上限，超出部分不会写入。

## 五、数据权限

### 5.1 列表看不到数据，但数据库有

- 角色档位是 4（仅本人）或 5（自定义）且没有命中规则。
- 用户没有部门，档位 2/3 会生成 `false()`。
- 查询没有调用 `apply_scope()`，或调用了但模型未声明 `__data_scope__`。
- 检查规则 `status`、`table_name` 是否已登记受控表。

### 5.2 能看到别人的数据

- 查询漏了 `apply_scope()`。
- 写操作只按 `id + tenant_id` 查询，没有做可见性校验。
- 字段级规则未接入该模块的 `_to_out()`。

### 5.3 掩码值被保存回数据库

- 该模块的写操作没有过滤 `blocked_write_fields()`。
- 检查规则动作是否为 `readonly` / `mask` / `hidden`。

## 六、租户

### 6.1 访问提示「租户不存在或已停用」

- `sys_tenant.status=0` 或已软删。
- 域名绑定错误。
- 令牌中的 `tid` 对应的租户被删除。

### 6.2 提示「当前域名与登录租户不匹配」

- 域名锁定了租户 A，但令牌是租户 B 签发的。
- 使用对应域名重新登录，或由超管在平台租户下切换。

### 6.3 平台租户看不到业务菜单

- 平台租户只用于运营，业务菜单按角色授权；给超管角色授权即可。
- 但菜单写入仍要求平台租户 + 超管。

## 七、定时任务

### 7.1 任务不执行

1. `cccms-scheduler` 进程是否在运行。
2. `sys_crontab.status=1`、`delete_time IS NULL`。
3. `next_run_time` 是否已到。
4. Redis 是否可用（锁与选主依赖 Redis）。
5. 多实例时确认只有一个调度器持有 `cccms:scheduler:lock`。

### 7.2 任务一直「运行中」

- 上次执行进程崩溃，`running` 标记未复位。
- 锁 TTL 到期后会自动恢复；也可手工把 `running` 置 0。
- 立即执行与调度执行共用锁，重复点击会提示「任务正在运行」。

### 7.3 任务失败没有重试

- 检查任务的重试配置与 `sys_crontab_retry`。
- 目标函数抛出的异常会被记录到执行日志。

## 八、审计与日志

### 8.1 操作日志没有记录

- 请求路径在跳过列表：`/ping`、`/healthz`、`/metrics`、`/auth/login`。
- 成功的 GET 默认不记录，需开启 `CCCMS_LOG_RECORD_READ`。
- 日志写入协程异常，检查应用日志。

### 8.2 审计链校验失败

- 日志被物理删除或改写。
- 清理任务误删了已封存日志（当前实现只允许清理未封存行）。
- 从中间批次开始校验会因缺少前序哈希而误报，需从链头开始。

### 8.3 日志删除被拒绝

- 该行已封存（`row_hash` 非空），参与哈希链，不允许删除。
- 请使用归档/清理任务，或联系平台管理员。

## 九、部署与环境

### 9.1 启动报密钥错误

生产环境要求：

- `CCCMS_JWT_SECRET` ≥ 32 字节
- `CCCMS_DATA_ENCRYPT_KEY` 非空
- `CCCMS_AUDIT_SIGNING_KEY` 非空
- `CCCMS_COOKIE_SECURE=true`

开发环境留空会自动生成，但重启后变化，导致旧令牌失效。

### 9.2 `init-db` 报生成列错误

- 需要 MySQL 8.0：唯一键依赖 STORED 生成列（`active_flag`、`scope_key`），MariaDB 与 5.7 以下写法不兼容。
- 生成列**不能参与级联外键**，所以 `sys_config` 的租户外键是 `RESTRICT`；把 DDL 手工改成 `CASCADE` 会失败。
- 升级数据库版本，不要手改 DDL。

### 9.3 时间显示差 8 小时

- 数据库连接时区与进程时区不一致。
- 统一使用东八区，容器设置 `TZ=Asia/Shanghai`。
- 后端统一输出 `YYYY-MM-DD HH:MM:SS`，前端不要二次 `toLocaleString()`。

### 9.4 `/metrics` 返回 404

- 请求来源 IP 不在 `CCCMS_METRICS_ALLOW_IPS`。
- 反向代理后未配置 `CCCMS_TRUSTED_PROXIES`，拿到的是代理 IP。
- 这是刻意的「伪装 404」，不是路由缺失。

### 9.5 在线升级不可用

- `CCCMS_ENV` 不是 `dev`。
- `CCCMS_UPGRADE_ENABLE=false`。
- 当前账号不是**平台租户的超管**（最常见，报 403「仅平台超级管理员可执行在线升级」）。
- 工作区有未提交改动、分支不匹配、游离 HEAD。
- `CCCMS_UPGRADE_SOURCES` 写成非法格式：下拉会为空，日志里有「配置格式错误：<项>」；正确格式是 `name=url,name=url`。
- 选中 gitee 后 fetch 失败：先确认 `https://gitee.com/<账号>/cccms` 真实存在——远端会在选中时自动 `git remote add`，但仓库不存在只有 fetch 才会报错。
- 生产环境请使用发布流程。

## 十、性能

### 10.1 列表很慢

- 检查是否缺索引（`tenant_id` + 业务字段）。
- 是否 N+1 查询（列表里逐行查关联）。
- 是否对 `sys_log` 做了无条件全表扫描。
- 看慢请求日志中的 `cost`。

### 10.2 页面高度无限增长

- `ArtTable` 的 `height` 与父布局不匹配。
- `.art-fill` 用默认 `'100%'`；`.art-scroll` 或 `el-card` 内用 `'auto'`。

### 10.3 导出卡住

- 导出在进程内后台协程生成，单进程并发受 `export_max_concurrency` 限制，排队时状态会长时间停在「待处理」。
- 同一用户同时只允许有限个任务（`export_max_active_per_user`），超了直接报「已有导出任务在执行中」。
- 缩小筛选范围，或按时间分批导出；先看任务记录的状态与 `progress`。
- 检查磁盘空间与 `shared/exports` 写权限。
