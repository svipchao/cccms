### A1 · `/storage/**` 对所有人生成 401，附件整体不可用
- 位置：[storage.py](../backend/src/cccms/api/storage.py#L28)、[test_http_contract.py](../backend/tests/test_http_contract.py#L59)
- 改了什么：
  1. `make_router(prefix="/storage", tags=["storage"], auth=False)` → `auth=True`，让 `load_user` 进入该路由的依赖链；
  2. 模块 docstring 中"Bearer-only 客户端应改用 `/api/file` 列表里返回的鉴权下载入口"改为事实描述：`load_user` 同时读 Cookie 与 `Authorization: Bearer`，跨站 `<img>` 不带凭据仍不可读（原文指向的端点并不存在）；
  3. 新增两条契约测试：登录态读到自己的文件 → 200 + `Cache-Control: private, max-age=300`；路径不在数据权限内 → 404（业务码 10401）。用 `dependency_overrides` 伪造 `load_user`/`get_session` + `monkeypatch` 替换 `_blob_path`，不依赖 MySQL/Redis。
- 为什么这么改：`GuardedRoute` 只在 `meta.no_login` 时跳过权限依赖（`permissions.py#L115-L116`），而 `permission_dependency` 第一件事是 `ctx.user is None → Unauthorized`；`ctx.user` 只由 `load_user` 写入。`auth=False` 使该路由永远拿不到用户，`apply_scope` 也随之形同注释。
- 验证：
  - 红态：临时改回 `auth=False` → `2 failed, 1 passed`（两条新用例失败，匿名 401 用例保持通过）；
  - 绿态：`uv run pytest -q` → **45 passed**（原 43 + 2）；`uv run ruff check src tests` → All checks passed；`uv run mypy src` → no issues in 109 files。
- 风险与遗留：`/storage` 请求现在会执行 `load_user` 的 Redis 查询与 `enforce_api_rate_limit`（60/min/用户），附件缩略图密集的列表页可能触及限流；真实 MySQL/Redis 环境下的端到端读取未验证（本机无 DB）。`/api/file/{id}/download` 仍未提供（轨道 B）。
- 回滚方式：`storage.py#L28` 改回 `auth=False`，并删除 `tests/test_http_contract.py` 中 `_FakeSession` / `storage_reader` / 两条 `test_storage_*` 用例。
