# 功能模块

> 本文逐个模块说明：功能是什么、涉及哪些表、有哪些接口、前端在哪个页面、对应哪些权限节点、有哪些坑。接口路径均为前端 `baseURL`（`/api`）之后的真实后端路径。

---

## 〇、阅读约定

> 本文按模块讲「功能 / 接口 / 页面 / 权限节点」；**表结构与字段语义统一见 [13-数据模型](13-数据模型.md)**，本文不再重复字段定义。

- **权限节点**列只列 `#[Permission]` 的 slug；未列出的方法为 `#[NoAuth]` / `#[NoLogin]`。
- 所有写操作接口都带 `#[Restrict(methods: ['POST'])]`。
- 所有接口返回统一信封 `{code, message, data}`，成功 `code = 0`。
- 前端页面统一位于 `frontend/src/pages/cccms/{模块}/index.vue`。

## 一、工作台（Dashboard）

| 项 | 内容 |
|----|------|
| 功能 | 欢迎卡 + 统计卡（用户 / 角色 / 部门 / 岗位 / 菜单 / 今日日志 / 在线用户 / 未读消息 / 字典 / 定时任务 / 数据规则 / 租户）+ 7 天日志趋势折线 + 附件类型分布饼图 + 「我的收藏」宫格（可拖拽排序） |
| 表 | 只读聚合，不新增表 |
| 接口 | `GET /dashboard/stats`（`#[NoAuth]`，登录即可） |
| 前端 | `pages/cccms/dashboard/index.vue`，组件名 `dashboard`，静态路由 `/dashboard` |
| 权限节点 | 无（登录即可）；**每张统计卡按各自模块权限节点条件下发** |

**权限只有两层**（以「能不能进对应列表页」为准）：

| 层 | 看到什么 |
|----|----------|
| 超级管理员 | 全部统计卡与全部数据（`UserContext::hasPermission()` 直通） |
| 其他账号 | 只有持有权限节点的模块才有对应卡片，其余键**不下发**；数字本身再按数据范围收窄 |

注意事项：

- **统计口径与列表页一致**：`user` / `dept` / `file` / `log` 的计数按当前用户数据范围聚合，避免「列表只能看到 3 条、工作台显示 1000 条」的绕行泄漏。
- **卡片按权限节点逐项下发**：13 个计数项各自登记了「能进列表页」所需的权限节点
  （如 `user → cccms:user:index`、`dept → cccms:dept:tree`、`log / today_log → cccms:log:index`），
  无权限时该键**不存在**，前端按「键是否存在」决定是否渲染卡片 ——
  避免「进不去列表页、却能从工作台读出该模块数据量」的越权信息泄露。`notice_unread` 是本人消息数，恒返回。
- **图表同样按权限**：拿不到日志列表页时 `log_trend.dates` 为空数组（不渲染趋势卡），
  拿不到附件列表页时 `file_types` 为空数组。
- **「我的收藏」宫格**取 `menuStore.favoriteMenus`，与顶栏快捷导航、标签栏收藏按钮**共用同一份收藏**（改一处三处同步）；
  顺序即收藏顺序，卡片上可直接**拖拽排序**（原生 HTML5 拖拽，未引入第三方库）。数据源是当前账号可见菜单，天然不含无权限入口；未收藏任何菜单时显示引导文案。
- 用户 / 角色 / 部门 / 岗位只统计 `status = 1`；菜单只统计 `type = 2`；字典 / 定时任务只统计 `status = 1`。
- 日志趋势逐天补 0；附件类型按扩展名分组取前 6；单个模块计数异常时按 0 兜底，不因某张表故障导致整个工作台报错。
- ECharts 按需引入（`echarts/core`），主题切换时重渲染。

## 二、认证（Auth）

| 项 | 内容 |
|----|------|
| 功能 | 健康检查、登录、图形验证码、当前用户信息、登出 |
| 表 | `sys_user`、`sys_role`、`sys_user_role`、`sys_role_node`、`sys_tenant`（校验租户可用性） |
| 前端 | `pages/cccms/login/index.vue` |

| 方法 | 接口 | 注解 | 说明 |
|------|------|------|------|
| `ping` | `GET /ping` | `#[NoLogin]` | 健康检查，返回 `pong` + 时间 |
| `login` | `POST /auth/login` | `#[NoLogin]` | 账号密码（+ 可选验证码）登录，返回 token + 用户信息 |
| `captcha` | `GET /auth/captcha` | `#[NoLogin]` | 图形验证码；未开启时返回 `null` |
| `me` | `GET /auth/me` | `#[NoAuth]` | 当前用户信息（含 `crypto_key`） |
| `logout` | `POST /auth/logout` | `#[NoAuth(title:'注销')]` | 注销：服务端把当前 `jti` 写入黑名单并移除在线会话 |
| `tenants` | `GET /auth/tenants` | `#[NoAuth]` | 可切换的租户下拉：超管返回全部租户，其他账号只返回当前租户 |
| `switchTenant` | `POST /auth/switchTenant` | `#[NoAuth(title:'切换租户')]` | 超管显式切换租户：重签带 `tid` 声明的令牌 + 迁移在线会话 `jti` |

登录校验顺序（`AuthLogic::login`）：

1. `LoginThrottle::assertNotLocked()`（锁定 → 429）。
2. `security.login_captcha` 开启才校验验证码。
3. `User::withoutAllScopes()` 查账号（**用户名全局唯一 + 回收站账号不可登录**）+ `password_verify`。
4. 状态 `status !== 1` → 403。
5. `AuthService::buildContext()` 失败 → 「账号角色异常」。
6. 维护模式下仅超管可登录。
7. 成功后清失败计数、更新 `login_time` / `login_ip`。

注意事项：

- 登录成功后返回的 `user.permissions` 是前端 `v-auth` 的数据来源。
- 登出**已做服务端失效**：把当前 `jti` 写入 Redis 黑名单（TTL = 剩余有效期）+ 移除在线会话，
  `CheckLogin` 每次校验；令牌损坏 / 已过期时按「登出成功」处理，保证接口幂等。
- 登录成功 / 失败都会写入操作日志（`sys_log`，`path='/auth/login'`），见 [十三、操作日志](#十三操作日志log)。
- **租户可用性逐请求校验**：`AuthService::buildContext()` 每次都会检查 `tid` 对应租户是否存在 / 未删除 /
  已启用 / 未过期 —— 租户被停用或到期后，该租户下所有账号**下一次请求即 401**，与「禁用用户立即生效」同一口径。
  详见 [二十一、租户管理](#二十一租户管理tenant)。

## 三、个人中心（Profile）

| 项 | 内容 |
|----|------|
| 功能 | 查看本人资料、修改本人基本资料、修改本人密码、查看与注销本人登录设备 |
| 表 | `sys_user`、`sys_role`、`sys_user_dept`、`sys_dept` |
| 接口 | `GET /profile`、`POST /profile/update`、`POST /profile/password`、`GET /profile/sessions`、`POST /profile/sessions/revoke`（全部 `#[NoAuth]`） |
| 前端 | `pages/cccms/profile/index.vue`，**静态路由** `/profile`（不进左侧菜单，入口在右上角用户下拉） |
| 权限节点 | 无 |

注意事项：

- 目标**始终是 `$user->id`**，不接受外部传入 id（防越权）。
- 可改字段白名单：`nickname` / `avatar` / `email` / `phone`（不含 username / status / 角色 / 部门 / 岗位）。
- 改密需校验原密码 + `PasswordPolicy` + 新旧不能相同。
- 走 `User::withoutGlobalScope()` 逃生口，否则「本部门档 + 未分配部门」的用户会被数据权限 fail-closed 挡住读自己资料。
- **登录设备**：`GET /profile/sessions` 通过 `OnlineSession::listOfUser()` 仅返回 `user_id = 当前用户`
  的会话（含 `current` 标记）；`POST /profile/sessions/revoke` 用 `OnlineSession::ownerOf()` 校验归属，
  失败统一返回 404「会话不存在或已失效」（**不区分不存在 / 不是我的**，避免探测他人会话）；
  禁止注销当前会话（422，改用「退出登录」）；注销时 `TokenBlacklist::revoke()` + `OnlineSession::remove()`
  **两处同时生效**。设备 / 系统 / 浏览器由 UA 派生，口径与 `GET /online` 一致。

## 四、用户管理（User）

| 项 | 内容 |
|----|------|
| 功能 | 用户增删改查、分配角色 / 部门（多选）/ 岗位（多选）、重置密码 |
| 表 | `sys_user`、`sys_user_role`、`sys_user_dept`、`sys_user_post` |
| 前端 | `pages/cccms/user/index.vue`，组件名 `cccms:user` |

| 接口 | 权限节点 | 说明 |
|------|----------|------|
| `GET /user` | `cccms:user:index` | 分页列表（安全字段，不含 password） |
| `GET /user/read` | `cccms:user:read` | 详情（含 `role_ids` / `dept_ids` / `post_ids`） |
| `POST /user/save` | `cccms:user:save` | 新增（密码必填 + 密码策略） |
| `POST /user/update` | `cccms:user:update` | 更新（密码留空则不改） |
| `POST /user/delete` | `cccms:user:delete` | 软删除（不能删自己、不能删超管） |
| `POST /user/resetPassword` | `cccms:user:reset_password` | 重置密码 |
| `POST /user/batchStatus` | `cccms:user:batch_status` | 批量启用 / 禁用（`{ids, status}`） |
| `POST /user/batchDelete` | `cccms:user:batch_delete` | 批量软删除 |
| `POST /user/batchAssign` | `cccms:user:batch_assign` | 批量分配角色 / 部门 / 岗位（整体替换语义） |

注意事项：

- 数据权限全由模型层承担（行级范围 + 出参字段规则 + 入参剔除）。
- 唯一性 / 存在性校验显式 `withoutGlobalScope()`（含 `withTrashed`，**回收站账号仍占用用户名**）。
- 删除为软删，关联表（user_role / user_dept / user_post）保留。
- **批量操作**统一语义：**只作用于可见行 + 跳过并回报 + 不整批失败**。先经
  `User::newScopedQuery()->whereIn('id', $ids)` 取可见交集，再剔除「超管账号」与「操作者自己」，
  返回值固定为 `{affected, skipped[]}`；`skipped` = 越权 / 受保护 / 不存在的 id。
  批量禁用后对方**下一次请求即 401**（鉴权每请求查库）。
  `batchAssign` 为**整体替换**：传了哪个键就重设哪个关联，三个键都没传抛 422。
- **不提供导入 / 导出**：用户模块的 CSV 导入导出已下线（含模板下载），需要时用「操作日志」页的导出。

## 五、角色管理（Role）

| 项 | 内容 |
|----|------|
| 功能 | 角色增删改查、角色树、节点授权（含继承展示）、数据范围设置 |
| 表 | `sys_role`、`sys_role_node`、`sys_user_role` |
| 前端 | `pages/cccms/role/index.vue`，组件名 `cccms:role`（树形页：`ArtSplitView` + `ArtTreePanel`） |

| 接口 | 权限节点 | 说明 |
|------|----------|------|
| `GET /role` | `cccms:role:index` | 列表（可按 `node_id` 取子树） |
| `GET /role/tree` | `cccms:role:tree` | 角色树 |
| `GET /role/read` | `cccms:role:read` | 详情 + 节点（`own` / `inherited` 分开返回） |
| `POST /role/save` | `cccms:role:save` | 新增 |
| `POST /role/update` | `cccms:role:update` | 更新 |
| `POST /role/delete` | `cccms:role:delete` | 软删 |
| `POST /role/copy` | `cccms:role:copy` | 复制角色（含档位与自身节点授权，不复制子角色） |

注意事项：

- 超管角色（`code = super_admin`）**禁止编辑 / 删除**，`code` 不可改。
- 有子角色的角色不可删除。
- 保存节点授权时剔除 `nodes` / `own` / `inherited` 键（避免 `fields_strict` 报错）。
- 授权界面上，从父角色继承来的节点**只读**。
- 删除角色时 `role_node` / `user_role` 保留（彻底删除时才清）。
- **复制角色**：只复制角色本体与**自身** `role_node` 授权（不含继承来的祖先节点，避免源角色调整后副本失效），
  不复制子角色。**必须显式复制 `data_scope`** —— 档位刻意不继承（见 [05-鉴权与权限](05-鉴权与权限.md)），
  漏复制会让副本静默落到默认「仅本人」。`name` 缺省「源名 + 副本」，`code` 自动派生 `_copy` / `_copy2`…；
  父角色做存在性 + 深度 ≤5 校验（同时兜住历史脏数据中的环）；传 `status=0` 即「另存为模板」，
  **不传 `status` 时沿用源角色的状态**（不覆盖）。

## 六、部门管理（Dept）

| 项 | 内容 |
|----|------|
| 功能 | 无限级部门树的增删改查；用户可多部门 |
| 表 | `sys_dept`、`sys_user_dept`、`sys_dept_role` |
| 前端 | `pages/cccms/dept/index.vue`，组件名 `cccms:dept`（树形页） |

| 接口 | 权限节点 |
|------|----------|
| `GET /dept/tree` | `cccms:dept:tree` |
| `POST /dept/save` | `cccms:dept:save` |
| `POST /dept/update` | `cccms:dept:update` |
| `POST /dept/delete` | `cccms:dept:delete` |

注意事项：

- 部门模型**参与**数据权限：「本部门及以下」档下部门管理页只见自己子树。
- **作用域过滤后树的根节点处理**：可见节点的父节点可能不在集合内（例如只看自己所属的二级部门），这类节点会被**提升为顶层**，否则整棵树会因为找不到 `parent_id = 0` 的根而变空。
- 删除前检查子部门与成员（**看全量**，不受数据范围影响），软删。
- 「绑定部门」候选项用 `DeptLogic::treeAll()`（全量）：规则是配置动作，不能因为看不见某个部门就绑不了。

## 八、菜单管理（Menu）

| 项 | 内容 |
|----|------|
| 功能 | 菜单 / 目录 / 按钮节点树的管理；图标选择 |
| 表 | `sys_menu`、`sys_role_node` |
| 前端 | `pages/cccms/menu/index.vue`，组件名 `cccms:menu`（树表，`pagination=false`） |

| 接口 | 权限节点 | 说明 |
|------|----------|------|
| `GET /menu/tree` | `cccms:menu:tree` | 全量菜单树（`trashed=1` 平铺已删） |
| `GET /menu/userTree` | `#[NoAuth]` | 当前用户可见菜单树（前端动态路由数据源） |
| `POST /menu/save` | `cccms:menu:save` | 新增 |
| `POST /menu/update` | `cccms:menu:update` | 更新 |
| `POST /menu/delete` | `cccms:menu:delete` | 软删（**保留 role_node 授权**） |

注意事项：

- `type`：`1` 目录 / `2` 菜单 / `3` 按钮；按钮节点由 `perm-scan` 生成，**不手工维护**。

- 标题 i18n：库里的 `title` 是中文兜底值，`MenuLogic::localizeTitles()` 会按 `menu.{slug}` 命中才覆盖为当前语言；**管理员自建菜单没有对应 slug，原样返回**（用户录入数据不翻译）。

- **不提供导入 / 导出**：数据权限规则的 CSV 导入导出已下线（含模板下载）。
- 机制细节见 [06-数据权限](06-数据权限.md)。

## 十、数据字典与通用分类（Dict / Category）

### 12.1 分片上传（P2-9）

- **前端自动分流**：同一个「上传」按钮，`file.size > upload.max_size`（默认 10MB）时改走分片，
  否则单请求直传（`el-upload` 的 `http-request` 自定义上传器，统一走 axios 实例）。
- **三阶段**：`init`（校验类型 / 总大小 → 尝试**秒传** → 建会话）→ `chunk`（逐片落盘，幂等可重传，
  每片上限 8MB）→ `complete`（校验片齐 → 合并 → 校验声明大小 / 哈希 → 交回 `FileLogic::upload` 入库）。
- **秒传**：前端对 ≤ 64MB 的文件用 WebCrypto 算 SHA-1（与服务端 `sha1_file` 同口径），
  `init` 命中「内容 hash + size 相同且**在数据范围内可见**」的记录时直接复用，连字节都不传；
  非 HTTPS 环境算不出哈希则跳过秒传（不影响续传）。
- **断点续传**：`init` 返回 `received` 已收分片列表，前端只补缺的那几片。
- **完整性**：合并后总字节数必须等于声明大小；声明了哈希的还要 `sha1_file` 对得上，
  否则拒绝 —— 挡住「漏传一片生成损坏附件」与「伪造秒传」。
- **四种驱动行为一致**：分片只暂存本地 `runtime/chunks/{uploadId}/`，`complete` 时把合并文件当成
  普通上传交给驱动（本地是 `rename`、云驱动是整体上传）。云厂商原生分片接口本轮不做
  （四种驱动各一套、需真账号联调，见 [开发计划](开发计划.md) 的取舍）。
- **大小上限**：分片走 `upload.chunk_max_size`（默认 2048MB），通过 `FileLogic::upload(..., $maxBytes)`
  **显式传参**而非可变状态（驱动实例被 `StorageManager` 静态缓存，可变状态会跨请求串味）。
- **清理**：会话放 Redis（TTL 24h），磁盘目录由内置任务 `ChunkCleanTask`（每小时）与
  `init` 的顺带清理（每小时节流一次）按 mtime 回收；`complete` 后无论成败都清分片目录。
- 升级：`cccms:db-upgrade` 补 `upload.chunk_max_size` 配置项；新装 seed 内置清理任务。
  存量库在「定时任务」页新增一条 `plugin\cccms\command\task\ChunkCleanTask`（目标列表自动扫描到）。

更多存储机制见 [11-常用命令与运维](11-常用命令与运维.md#六存储与附件)。

| 接口 | 权限节点 |
|------|----------|
| `GET /log` | `cccms:log:index` |
| `GET /log/export` | `cccms:log:export` |
| `GET /log/action` | `cccms:log:action` |
| `GET /log/session` | `cccms:log:session` |
| `GET /log/trace` | `cccms:log:trace` |
| `GET /log/login/analysis` | `cccms:log:analysis` |

| `GET /export/task/list` | `#[NoAuth]`（登录即可，只列本人任务） |
| `GET /export/task/download` | `#[NoAuth]`（登录即可，校验归属） |

注意事项：

- 写入侧在 `OperationLog` 中间件：`POST/PUT/DELETE/PATCH` 必记；**已登录用户的失败请求（含 GET）也记**
  （否则 GET 报错在链路视图里是空白）；`log.record_read` 打开后所有 GET 都记。匿名失败请求不记。
- 记录内容：`node`（slug）+ `title`（注解操作名）、请求参数（query + body，body 优先）、执行结果、
  IP、UA、方法、路径、耗时、状态码，以及三层 ID（见下）。
- **三层 ID 的分工（排障 / 审计分离）**：
  | ID | 边界 | 生成方 | 用途 |
  |---|---|---|---|
  | `trace_id` | 一次 HTTP 请求 | 后端 `Cors` | 报错定位到具体一条记录；响应头 `X-Trace-Id`、失败响应体都会带 |
  | `action_id` | 一次用户操作 | 前端 `utils/trace.ts`，`X-Action-Id` | 链路视图：本次操作发了哪些请求、哪步失败 |
  | `session_id` | 一次页面会话（**刷新即换**） | 前端 `utils/trace.ts`，`X-Session-Id` | 审计：这段时间先后做了什么 |
  前端边界规则：路由进入 / 切换开新操作；**每次写请求**开新操作；读请求跟随当前操作。
  后端只做格式校验（字母/数字/`.`/`_`/`-`，≤32 字节），不合法则该字段留空，不影响日志写入。
  失败响应体同时返回三个 ID，前端把 **`action_id`** 拼进报错提示。
- **操作链路（P2-6）**：`GET /log/action?action_id=xxx` 返回该操作**全部记录按 `id` 升序**
  + 汇总 `{action_id, session_id, total, failed, cost, truncated}`。走同一份 `newScopedQuery()`，
  **看不见的日志不出现**（越权行不泄露）；`action_id` 为空抛 422（避免无条件下捞全表）；
  单次上限 500 条（达到上限时 `truncated=true`）。前端以时间线展示，参数 / 结果就地展开，
  支持刷新、复制操作 ID、`/log?action_id=xxx` 直达（keep-alive 下再次跳入也会跟上查询参数）。
- **会话轨迹（审计）**：`GET /log/session?session_id=xxx&after_id=&limit=` 用**游标**分页
  （日志持续写入，页码分页在「加载更多」时会漂移），返回 `{session_id, total, next_cursor, has_more, list}`；
  前端按**操作分组**展示（同一操作的请求相邻合并），支持「加载更多」与 `/log?session_id=xxx` 直达。
  独立权限节点 `cccms:log:session`（审计能力），与排障用的 `cccms:log:action` 分开授权；
  数据范围仍由模型作用域兜住。
- **请求级查询**：`GET /log/trace?trace_id=xxx` 保留，返回单条记录（`truncated` 上限 200），
  供「拿到响应头 / 失败响应体的 trace_id 直接查」使用。
- **登录安全分析（P2-13）**：`GET /log/login/analysis?days=7`（或 `start` / `end`，显式区间优先；
  `days` 收敛到 `[1, 90]`）返回聚合视图，前端日志页顶部标签页「登录分析」展示（复用 ECharts）；
  **无 `cccms:log:analysis` 权限时不渲染该标签页入口**。
  - `summary`：登录次数 / 成功 / 失败 / 失败率 / 失败账号数 / 失败 IP 数
    （用**一条**聚合语句取全，`COUNT(DISTINCT ...)` 直接在 field 里算）；
  - `trend`：窗口 <= 48 小时按**小时**分桶，否则按**天**分桶；**补齐空桶**
    （否则「某天没有任何登录」会在图上表现为直接跳过去，看不出异常），桶按时间升序；
  - `top_users` / `top_ips`：失败次数 TOP 10（不含空用户名 / 空 IP）；
  - `ip_changes`：同一账号两次**成功**登录之间 IP 发生变化（异地登录），按 id 升序逐账号比较相邻两次，
    忽略空 IP，取最近 10 条；一个账号来回切换网络会记多次（这正是想看到的信号）。
  - ⚠️ **数据范围对聚合同样生效**：走同一份 `newScopedQuery()`，
    「仅本人」档的管理员只统计得到自己的登录记录，不会从聚合视图里越权看到全站账号。
    这也回答了开发计划里那条「**待确认**：`sys_log` 是否参与数据权限」——`sys_log` 按模型声明
    **参与**数据权限（见 [06-数据权限 §3.1](06-数据权限.md#31-各表现状)），聚合沿用同一口径。
- **审计链**：`sys_log` 每行带 `prev_hash` / `row_hash` 链式哈希，校验命令见
  [11-常用命令与运维 §1.12](11-常用命令与运维.md#112-cccmslog-verify--校验审计日志链定位篡改--删除)；
  只有 `create_time` 没有 `update_time`，改动日志会破坏链（这正是设计意图）。
- **导出（P2-7，一律异步）**：`GET /log/export` 不区分数据量，**落一条 `sys_export_task` + 投递一条
  `ExportJob`** 就返回 `{async, task_id, total}`；作业进程（`job_queue`，1 秒 tick）拿到即生成，不必等轮询。
  `ExportTaskConsumer`（默认每 10 秒）与「下载时补生成」是兜底：队列不可用、或 Windows 上没有常驻进程时
  仍能出文件（投递失败只记日志，**不影响导出请求成功**）；作业用 `export:{task_id}` 作幂等键，重复投递
  只生成一次。生成用 keyset 分页流式写
  归档文件（含操作 ID / 请求 ID / 会话 ID 列）到 `runtime/exports/`（**不进 `public/storage`**，导出含敏感日志，
  下载必须走带归属校验的接口）。**全局顶栏「消息中心」**（右上角铃铛图标，角标 = 未读消息 + 未完成
  导出任务，抽屉内「导出任务」tab）统一查看各模块导出状态并下载；归档文件保留 `export.keep_minutes`
  （默认 60 分钟），过期即删并置为「已过期」。
- 敏感字段递归脱敏（password 系列、token 系列、secret 等），**深度上限 3**（规则抽到
  `support/LogRedactor.php`，归档冷数据时复用同一份，避免两处漂移）。
- 上传接口 body 为空时会补 `_files`（形如 `file:报告.pdf`）。
- 文本长度上限 8000 字符。
- **日志写入失败绝不影响业务**。
- **慢接口告警**：请求耗时超过 `log.slow_threshold`（毫秒，默认 3000，0 = 关闭）时额外写一条
  告警日志到 `runtime/logs/slow.log`；覆盖**所有**请求（含 GET），与是否记操作日志无关。
- **归档到对象存储**：`php webman cccms:log-archive` 把早于 N 天的记录序列化为 JSONL(gzip)
  上传后删主库（**先存后删**，可重入）；内置任务「日志归档到对象存储」默认**停用**。
  用法见 [11-常用命令与运维](11-常用命令与运维.md#一cli-命令)。
- 模型参与数据权限：删除 / 清空**只影响自己可见范围内的日志**。
- **登录日志已并入本表**：登录成功/失败由 `AuthLogic` 写 `path='/auth/login'` 的记录（登录接口是
  `#[NoLogin]`，中间件拿不到操作人），失败原因记在 `message`，用「请求路径」筛 `/auth/login` +
  「结果」即可定位；登录接口本身不再由 `OperationLog` 中间件重复记录。
- 日志表没有软删列，删除即物理删除；按 `log.keep_days` / `log.auto_clean` 由定时任务清理（需自行配置任务，种子未预置）。

### 14.1 增强项（重叠 / 超时 / 重试 / 分组）

| 字段 | 说明 |
|------|------|
| `group_name` | 任务分组，仅用于归类与筛选（**不是并发队列**） |
| `overlap` | `skip`（默认）：上次未结束则本次跳过；`allow`：允许并发 |
| `timeout` | 超时秒数，`0` = 不限；超时会**释放运行锁并写一条 `status=3` 日志** |
| `retry_times` / `retry_interval` | 失败后重试次数（0~10）与间隔（秒） |
| 重试投递 | 失败后投递 `CrontabRetryJob`（队列 `crontab`），`available_at = 现在 + retry_interval`，幂等键 `crontab-retry:{任务}:{第几次}` |
| `running` / `running_at` | 运行时字段：运行锁 |

调度顺序：**调度进程只管 cron 到期**；失败重试是作业队列的事（`process/Queue` 每秒认领到期作业），
**两者不共用 tick** —— 长任务只顺延自己的调度，不会把重试一起拖后。
重试链：首次失败投递第 1 次，每轮执行完仍失败才投递下一轮，用完 `retry_times` 即停（次数账只记在任务配置里，
不与作业的 `max_attempts` 混用）。任务停用 / 进回收站后排队中的重试直接作废，删除任务时一并撤销
（`JobQueue::discard()`）；执行记录仍是 `source = retry` 的普通日志。

> ⚠️ **超时的能力边界**：任务在调度进程**同一个进程内**执行，PHP 无法从外部强杀正在执行的调用。
> 因此「超时」只能做到「解锁 + 留痕 + 让后续调度恢复」，**不能真正中断卡住的代码**。
> 需要硬超时的任务请自行在代码里做分段 / 协作式检查，或改用独立进程执行。

### 14.2 执行日志状态

`sys_crontab_log.status`：`1` 成功 · `0` 失败 · `2` 跳过（上次未结束）· `3` 超时释放；
`source`：`cron` / `retry` / `manual` / `timeout`。
「跳过」日志按任务**每 60 秒最多一条**（避免每秒任务 + 长执行把日志表刷爆）。

日志抽屉支持**点击行查看运行详情**：宽屏为「左表格 + 右详情」分栏，窄屏（≤1200px）
自动改为上下排列；详情包含结果 / 来源 / 耗时 / 日志 ID、任务配置（表达式、目标、超时、重试）与参数、完整输出。
抽屉宽度 `min(1280px, 94vw)`，≤768px 时铺满全屏。

### 14.3 其他约定

- 调度进程 `plugin/cccms/process/Crontab` **每秒 tick**；**仅 Linux / macOS 生效**（Windows 无自定义进程）。
- 刷新表达式为**六段**（秒 分 时 日 月 周），与 Linux 五段不同。
- **执行白名单**：只执行实现 `CrontabTask` 接口的类（杜绝 RCE）；`targets` 扫描 `plugin/*/command/task` 下的实现类。
- 日与周同时限定时按 **AND**；不做月份实际天数回绕（31 号在 2 月不触发）。
- 同一秒按 key 去重，避免重复执行。
- 任务在调度进程内**串行**执行，长任务会顺延后续 tick。
- 「立即执行」也走重叠保护：若该任务正在执行中，手工触发会被跳过（返回 `status=2`）；
  手工执行**不改变失败重试状态**。
- **执行身份只由任务归属决定**（P1-2）：任务在「任务属主租户」下执行（平台任务的 `tenant_id = 0`
  → 平台身份），且不继承操作者的行级数据范围。否则同一个任务「手动成功、定时失败」或把数据写到
  不同租户，排查时因为代码是同一份而极难定位。操作者只体现在执行日志的 `source = manual` 上。
- 删除为软删，执行日志保留。
- 内置任务：`plugin/cccms/command/task/LogCleanTask`（清理历史操作日志，读取
  `log.keep_days` / `log.auto_clean`）；`seed.sql` 已预置「每天 03:00 执行」的任务。

### 14.4 作业队列 tab（F5）

页面顶部与「定时任务」并列，`v-if` 判断 `cccms:job:index`：无权限时不渲染入口（避免点进去 403）。
进入 tab 才挂载面板（`v-if` 而非 `v-show`），每次切换都拿最新数据。

- **统计卡**：待执行 / 执行中 / 待重试 / 死信 / 总数 + **消费者心跳**。心跳超过 60 秒未更新即标红 ——
  它说明 `job_queue` 进程没在跑（Windows 上没有自定义进程），此时作业只会堆积，导出会回落到下载时补生成。
- **列表**：队列 / 状态 / 目标类 / 尝试次数 / 最早执行 / 创建时间 / 最近失败，列头筛选走后端（`useTable` 零接线）；
  「尝试次数」达到 `max_attempts` 且未成功时标红。
- **执行日志抽屉**：作业本身（完整类名、队列、幂等键、认领 / 结束时间、payload）+ 每次尝试的结果与输出。
- **重试**：打回待执行并**重置 attempts**（已成功的作业后端直接拒绝，前端也不给按钮）。
- **删除**：只允许「成功 / 死信」；勾选里混有待执行 / 执行中时后端整批拒绝并说明原因（不做静默部分成功）。

> 作业表是**平台级**的，不做数据权限：一条作业不属于某个部门，按范围裁剪只会让排障时看不到真正卡住的那条。
> 访问控制完全由 `cccms:job:*` 节点决定。

新增一个任务类：

```php
namespace plugin\cccms\command\task;

use plugin\cccms\support\CrontabTask;

class MyTask implements CrontabTask
{
    public function run(array $params = []): string
    {
        // 业务逻辑
        return '执行完成：处理 10 条';
    }
}
```

然后在「定时任务 → 新增」中从「执行目标」下拉选择它（类名带插件前缀）。

## 十六、回收站（Recycle）

| 项 | 内容 |
|----|------|
| 功能 | 对软删除的业务主数据执行「还原」与「彻底删除」 |
| 表 | 跨表操作（注册表见下） |
| 接口 | `POST /recycle/restore`、`POST /recycle/delete`（**无独立列表接口**） |
| 前端 | 不是单独页面：各模块列表页表格右上角的 `RecycleToggle` 切换 |
| 权限节点 | `cccms:recycle:restore`、`cccms:recycle:delete`（`group = cccms:setting`） |

内置类型（`RecycleLogic::TYPES`，共 12 类）：

```
user / role / dept / post / dict_type / dict_data / category / crontab / data_rule / file / menu / notice
```

业务插件可在 `plugin/{插件}/db/recycle.php` 声明额外类型，会被自动合并。

注意事项：

- **列表数据源切换**：列表接口带 `trashed=1`，而不是单独的回收站接口。
- 回收站视图 = `Model::onlyTrashed()`。
- 恢复前校验：
  1. 唯一键表（`user.username` / `role.code` / `post.code` / `dict_type.type` / `menu.node`）的唯一值是否**被占用**（已排除待恢复行自己）；
  2. 上级是否仍在回收站（`dept` / `category` / `dict_data` / `menu`，防止恢复出孤儿节点）。
- 彻底删除：`file` 先删物理文件，`menu` 先清 `role_node` 授权，再真删。
- 要操作已删行**必须 `withTrashed()`**，否则静默 0 行。

前端使用顺序（`useRecycle` 必须在 `useTable` 之前）：

```ts
const { recycle, toggle, onRestore, onForceDelete } = useRecycle('user', { reload, ids, clear })
// 1) 列表 api 注入 trashed: recycle.value ? 1 : 0
// 2) <ArtTable :recycle="recycle" @restore="onRestore" @force-delete="onForceDelete" />
// 3) <RecycleToggle :active="recycle" :label="t('user.recycleLabel')" @toggle="toggle" />
```

## 十九、在线用户（Online）

| 项 | 内容 |
|----|------|
| 功能 | 查看当前在线会话（用户、设备类型、操作系统、浏览器、IP、登录时间、最后活跃、会话过期）；按**会话**或按**用户**强制下线 |
| 存储 | Redis（`support/OnlineSession.php`），不落库。设备类型 / 系统 / 浏览器由 UA 在读取时派生，不单独落库 |
| 前端 | `pages/cccms/online/index.vue`，组件名 `cccms:online` |

| 接口 | 权限节点 |
|------|------|
| `GET /online` | `cccms:online:index` |
| `POST /online/kick` | `cccms:online:kick` |
| `POST /online/kickUser` | `cccms:online:kick_user` |

实现要点：

- 会话索引：`cccms:online:s:{jti}`（Hash，会话明细）+ `cccms:online:index`（ZSet，按活跃度排序）。
- **两个口径**：工作台「在线用户」卡片是**去重后的用户数**（`OnlineSession::countUsers()`，
  同一账号多端登录只算 1 个、僵尸会话不计入）；本列表与 `/metrics` 的 `cccms_online_sessions`
  仍是**会话数**（`OnlineSession::count()`，一个会话一条）。两者不是一回事。
- 登录时 `register()`；`CheckLogin` 每次请求 `touch()` 刷新活跃时间（**60 秒节流**，避免每请求写 Redis）；
  登出时 `remove()`。
- **同一终端只保留一条**：`register()` 会先退掉该用户在同一终端（IP + UA 相同）上的旧会话并写令牌黑名单。
  浏览器只保存一个令牌，同一浏览器重登后旧令牌取不到，留着只会让列表出现「同一设备两条记录」。
- 索引 ZSet **不设 TTL**（比单条会话活得久），过期成员由列表查询与 `prune()` 惰性清理。
- **下线必须在两处同时生效**：`OnlineSession::remove*()`（从列表移除）+ `TokenBlacklist`
  （作废已发出的令牌）。只做前者属于「假下线」—— 对方手里的 token 依然能用。
- 不允许下线自己（按会话 / 按用户都会校验），否则操作者会被立刻踢出去。
- **量级**：列表为**服务端分页 + 服务端过滤**，索引 ZSet 按 `SCAN_BATCH = 200` 分段扫描
  （不再有「单次最多 2000 条」的内存过滤上限），在线数上万也可用。
- **黑名单 TTL 精确化**：会话 Hash 里存了令牌 `exp`，`kick()` 按真实剩余有效期写黑名单，
  不会因为 `security.token_ttl` 调大而长期驻留。
- **滑动续期会迁移会话**：令牌续期后 `jti` 变了（见 [05-鉴权与权限 §5.2](05-鉴权与权限.md#52-tokenservicejwt)），
  `OnlineSession::rotate()` 把会话迁到新 `jti` —— 不迁移的话，这里踢掉的是已经废弃的旧令牌，
  对方手里的新令牌依然有效，形成「假下线」。

注意事项：

- 字段：`type`（1 通知 / 2 公告）、`level`（1 普通 / 2 重要）、`status`（1 发布 / 0 草稿）、
  `publish_at`、`expire_at`（为空则不过期）。
- 已发布但未填 `publish_at` → 视为「立即发布」。
- 「已读人数」是 `read_count` 冗余计数，**只在首次已读时 +1**。
- 模型声明**不参与数据权限**：公告是广播内容，没有「归属人」语义。
- 支持回收站：`RecycleLogic` 已登记 `notice` 类型（软删时同时清理已读记录）。
- 阅读侧为 `#[NoAuth]`（登录即可）是恰当的：它只返回**当前用户自己的**数据，不涉及全量查询。
- 定向投放范围由 `sys_notice_target` 落库（部门 / 角色 / 指定用户三类），候选数据由
  `GET /notice/options` 提供，已读回执由 `GET /notice/report` 提供。

## 二十二、接口文档（OpenApi）

| 项 | 内容 |
|----|------|
| 功能 | 由路由表 + 权限注解自动生成 OpenAPI 3.1；后台提供分组树、单接口详情、Try it out、导出 JSON |
| 存储 | **不落库**：每次实时反射生成。路由表就是接口清单，静态 spec 文件会立刻过期 |
| 前端 | `pages/cccms/apidoc/index.vue`，组件名 `cccms:apidoc`；左侧导航为**插件 → 分组 → 接口**三层树（首层默认展开） |
| 可见性 | **仅本地开发环境**：`MenuLogic::DEV_ONLY_PREFIXES` 在非开发布局（`Environment::isDevLayout()` = 仓库根无 `frontend/package.json`）下把菜单与按钮节点从 `userTree` 过滤掉 |

| 接口 | 权限节点 |
|------|------|
| `GET /apidoc` | `cccms:apidoc:index` |
| `GET /apidoc/detail` | `cccms:apidoc:detail` |
| `GET /apidoc/spec` | `cccms:apidoc:spec` |

实现要点：

- **入口是路由表不是控制器**：`OpenApi::operations()` 遍历 `Route::getRoutes()` 反查控制器方法。
  反过来扫控制器的话，「写了方法但没挂路由」的接口会出现在文档里，但它本来就调不到 —— 文档会骗人。
- **参数是静态推断**：从方法体读 `$request->get('x')` / `->post('x')`，拿名字 + `(int)` 之类的强转 +
  「有没有默认值」（有默认值 = 非必填）。`$request->get()` 无参（整包透传给 Logic）标记 `unbounded`，
  再顺着控制器方法体里的 `XxxLogic::method()` 读业务层的 `$params['x']`（含 `self::helper($params)`
  两跳、`PageInput::of()` 隐含的 page / limit），前端提示「可能不全」，不假装精确。
- **枚举值取自库表**（`support/SchemaMeta`）：值集合来自 `CHECK (col IN (...))` / `between a and b` /
  `enum(...)`，标签取列 `COMMENT` 里紧跟在值后面的说明（`'1目录 2菜单 3按钮'`）；请求参数按「该接口
  主表 + 同名列」匹配，拿不到主表时只用跨表口径一致的列（`status` / `type` 各表不同 → 不写）。
  读不到元数据（无库 / 权限不足）时自动退化为「只有名字与类型」。
- **返回字段按主表推断**：控制器 → `XxxLogic::method()` → 方法体里的模型类 / `Db::name()` → 表名；
  命中多张表（看板、统计）视为聚合接口，**不猜**。只对 GET 生效（写接口返回 id / null），
  详情里 `response.inferred` 为真时前端提示「按表结构推断」；口令 / 密钥类列一律不列出。
  spec 中 `data` 用 `oneOf` 指向 `Table.{表名}` schema（只注册实际引用到的表），参数 `schema.enum`
  给值集合、`x-enum-labels` 给 `值 => 说明`。
- **分组跟随注解 `group`**：`groupKey()` 优先取 `#[Permission(group:)]`（按钮归属菜单，与
  `PermScanner::resolveParent()` 同口径），没写才回落到权限 slug 前两段。否则 `cccms:job:*`
  会单独成组、标题只能退回 key 原文 `cccms:job` —— 语言包里只有菜单节点（`cccms:crontab`、
  `cccms:setting`）的词条。
- **接口标题跟随语言**：注解里的 `#[Permission(title:)]` 是中文原文（写库与操作日志的兜底值），
  `summaryOf()` 在 `menu.{slug}` 命中语言包时按当前请求语言覆盖，口径与 `MenuLogic::localizeTitles()`
  一致 —— 详情页标题与 spec 的 `operation.summary` 因此不会在英文界面里冒出中文。
- **`/apidoc/spec` 不套信封**：外部工具（Apifox / Postman / 代码生成器）要直接吃 spec。
  这是继 `/metrics`、`/healthz` 之后第三类「非信封」响应，导入时注意。
- **左侧按插件分层**：`tree()` 的每个分组带 `plugin` / `pluginTitle`（控制器 FQCN 的 `plugin\{插件}` 段），
  前端只做归并、不重排 —— 排序在服务端定：cccms 优先，其余按插件名、分组 key。
  插件显示名依次取语言包 `apidoc.plugin_{插件}` → `plugin/{插件}/config/app.php` 的 `title` →
  `plugin/{插件}/db/menu.php` 首个菜单标题 → 插件目录名，全部取不到时也不会空着。
  多插件（业务插件由生成器产出）因此能看出接口归属，而不是所有模块平铺成一层。
- **一致性门禁 `cccms:openapi-check`**：路由指向不存在的方法、声明了 `#[Permission]` 却无路由可达、
  非 `#[NoLogin]` 缺鉴权属性、slug 重复或格式非法 → 退出码 1。fail-closed 口径与
  `PermScanner::pluginScanners()` 一致（无 `db/menu.php` 的公开前台插件豁免），避免两套标准打架。
- **权限**：文档含全部路径与权限节点，等于一份攻击面清单，因此不做 `#[NoLogin]`；
  `spec` 单独一个节点，便于只给少数人开导出。
- **菜单只在本地开发环境出现**：菜单树是前端动态路由的唯一来源，`userTree()` 在非开发布局下
  过滤 `cccms:apidoc*`（前缀匹配，按钮节点一并藏掉）→ 线上既不注册路由也不显示入口，
  手敲 URL 落 404。节点仍由 `menu-sync` 写入 `sys_menu`，菜单管理里可见，便于排查。
  接口本身仍按权限节点鉴权（未额外加环境闸），CLI 的 `cccms:openapi-check` 不受影响。

## 二十三、接口监控（Monitor）

| 项 | 内容 |
|----|------|
| 功能 | 窗口内请求量 / 错误率 / 分位耗时 / 在线会话 / 依赖状态；每分钟趋势；状态码分布；按接口聚合的明细表 |
| 存储 | 不落库、不加缓存：**读的就是 `Metrics` 派生自 `sys_log` 的那份数据**，与 `/metrics` 同源 |
| 前端 | `pages/cccms/monitor/index.vue`（`cccms:monitor`）+ `ServerPanel.vue`（`cccms:monitor-server`），同一页面用 tab 切换 |

| 接口 | 权限节点 |
|------|------|
| `GET /monitor` | `cccms:monitor:index` |
| `GET /monitor/paths` | `cccms:monitor:paths` |
| `GET /monitor/trend?minutes=` | `cccms:monitor:trend` |
| `GET /monitor/server` | `cccms:monitor:server` |

实现要点：

- **path 维度必须归一化**：`sys_log.path` 来自客户端 URL，属不受控输入（扫描器、手输错误地址）。
  `Metrics::normalizePath()` 把数字段 / uuid / 长 hex 压成 `{n}` / `{uuid}` / `{id}` 并截断超长，
  导出条数再由 `PATH_LIMIT = 20` 兜一层 —— 不这么做会让 Prometheus 侧 label 基数爆炸。
  注意每个正则都锚定**整段**（`(?=/|$)`），否则 `/9f8e7d...` 会被 `/9` 抢先命中，越归一化越碎。
- **两次查询，不做 N+1**：精确计数走 `GROUP BY path`；P95 需要窗口内每条的 `cost`，复用
  「最近 2 万条」采样后按归一化路径分组排序，而不是对每个 path 各查一次。
- **趋势要补零**：按分钟分组后，没有数据的分钟补 0。否则折线图把「中间三分钟没数据」画成一条直线，
  看起来像流量平稳 —— 与事实相反。
- **`record_read` 提示**：`sys_log` 默认只记写操作与登录，读接口不落库。不提示的话，
  运维会把「请求量很少」误判成流量异常。
- **权限拆三个节点**：页面首屏只要 `index`；明细表与趋势可分别授权，避免「看一眼趋势」就得放开全部明细。
  前端用 `Promise.allSettled` 独立加载，缺某个权限时只隐藏对应区块，不做整页报错。

### 23.1 服务器资源（F6）

CPU / 负载 / 内存 / 磁盘 / 进程数 / 运行时长 / PHP / Redis / MySQL 连接，同一 tab 内切换。

- **与接口监控不同权限**：看接口流量 ≠ 有资格看主机负载，`cccms:monitor:server` 单开一个节点；
  前端 `hasAuth('cccms:monitor:server')` 不通过时连 tab 都不渲染（避免「点进去 403」）。
  按钮节点按最长 slug 前缀挂在「接口监控」菜单下，**不新增菜单**。
- **采集不依赖 shell**：`ServerMetrics` 只读 `/proc`（`stat` / `meminfo` / `cpuinfo` / `uptime` / 进程目录）、
  `Redis::info()`、`SHOW GLOBAL STATUS|VARIABLES`。容器里常没有 `top` / `free` / `nproc`，
  `exec` 还可能被 `disable_functions` 关掉。
- **拿不到的项返回 `null` 而不是 0**：Windows 没有 `/proc`，CPU 占用率 / 负载 / 进程数 / uptime 都是 `null`，
  页面显示「—」。在告警语境里「未知」与「零」含义完全不同。
- **CPU 两处口径**：`/metrics` 导出累计计数器 `cccms_node_cpu_seconds_total`（抓取端 `rate()`）；
  看板接口现场隔 200ms 采两次求差值得出百分比 —— 这一步**只放在看板里**，放进 `/metrics` 会让每次抓取都阻塞 200ms。
- **阈值只有一处**：`monitor.cpu_threshold` / `memory_threshold` / `disk_threshold` / `connections_threshold`
  同时供后端 `warn` 标记与 [Prometheus 告警规则](11-常用命令与运维.md#112-接入-prometheus) 使用；
  前端只按后端返回的 `warn` 上色，**不自己比阈值** —— 两份阈值必然漂移成「页面红了但告警没响」。
- **`/monitor/server` 响应带 `thresholds` 与 `warn`**：前端不需要知道默认值，改配置即改看板表现。

> 另有两类**非模块**文件不在此表：`request.ts`（axios 实例 + 拦截器 + 文件下载）、
> `types.ts`（通用类型）。前端 `pages/` 目录与 `api/` 一一对应（`pages/cccms/{module}/`）。
> 新增模块的三步：`db/menu.php` 声明菜单 → 控制器注解声明 slug → `route.php` 显式加路由
> （再跑 `cccms:menu-sync` + `cccms:perm-scan`）。

## 二十五、数据库备份 / 还原（Backup / F3）

| 项 | 说明 |

| 前端 | `pages/cccms/backup/index.vue`，组件名 `cccms:backup`，菜单挂在「开发运维」下 |
| 备份任务 | `command/task/DbBackupTask`（`sys_crontab` 种子默认停用，启用后每天 02:30） |
| 保留策略 | `backup.keep_count`（定时备份留几份，默认 10）、`backup.keep_days`（所有备份按天清理，默认 30） |

| 接口 | 权限节点 |
|------|----------|
| `GET /backup` | `cccms:backup:index` |
| `POST /backup/create` | `cccms:backup:create` |
| `POST /backup/delete` | `cccms:backup:delete` |
| `GET /backup/download` | `cccms:backup:download` |
| `GET /backup/tables` | `cccms:backup:tables` |
| `POST /backup/restore` | `cccms:backup:restore` |

### 25.1 两种导出引擎

| 引擎 | 何时用 | 一致性 |
|------|--------|--------|
| `mysqldump` | 安装了 mysqldump（生产推荐） | `--single-transaction --quick`：InnoDB 一致性快照，**不锁表** |
| `pdo` | 没装 mysqldump（Windows 开发机 / 精简镜像） | 逐表 `SHOW CREATE TABLE` + 分批 `SELECT`；**没有跨表快照**，写入高峰可能自相矛盾 |

引擎记在 `sys_db_backup.engine` 里，列表对 `pdo` 打黄色标记 —— 拿到一份「不自洽」的备份而不自知，
比没有备份更危险。两种引擎产出的文件格式一致（同一套 `-- Table structure for table` 分节骨架），
可以互相还原。视图 / 触发器 / 存储过程 / 事件**不备份**（需要 `DELIMITER` 或依赖 DEFINER 账号）。

### 25.2 还原的四道护栏

1. **手输数据库名**：`confirm` 必须等于当前库名，否则 422 —— 这是防误触的最后一步；
2. **先自动备份**：`kind = pre_restore` 的快照失败就**不开始**还原（MySQL 的 DDL 无法整体回滚，
   没有退路的覆盖比不还原更危险）；
3. **文件锁互斥**：`runtime/backups/.restore.lock`（`flock` 非阻塞），并发还原直接 409；
4. **sha256 校验**：下载与还原前都校验，文件被截断/替换立即拒绝，而不是还原到一半报语法错。

还原**按表**可选：留空 = 全量（整库覆盖），只勾几张表则只换那几张表，其它表不受影响 ——
这才是「误删一张表，从昨天的备份里捞回来」的日常救火姿势。

### 25.3 为什么备份是同步的

备份是管理员主动发起的一次性运维动作，通常几秒到几十秒；同步执行能立刻看到成功/失败与文件大小。
**几十 GB 的库请用定时任务**（独立进程 + 超时预算），别占在线请求。

> ⚠️ 备份与还原都只建议在**维护窗口**内做：全量还原会把整库覆盖，期间写入的数据会丢；
> 备份会持续读库，大库上会明显抢占 IO。

## 二十六、在线命令终端（Terminal / F2）

| 项 | 说明 |
|----|------|
| 功能 | 在后台执行**登记过的**运维命令、看输出、留执行记录；不是自由 shell |
| 命令表 | `config/terminal.php`（`key` / `risk` / `argv` 模板 / 参数白名单） |
| 执行 | 投递到 `terminal` 队列，由现有队列进程消费（`JobQueue`），输出进 `sys_job_log` |
| 前端 | `pages/cccms/terminal/index.vue`，组件名 `cccms:terminal`，菜单挂在「开发运维」下 |
| 互斥 | `unique = terminal:{key}`：同一命令同时只有一条在跑，连点得到同一条作业 |
| 重试 | `max_attempts = 1`：失败直接进死信，人工确认后在任务中心重试 |

| 接口 | 权限节点 |
|------|----------|
| `GET /terminal` | `cccms:terminal:index` |
| `GET /terminal/history` | `cccms:terminal:history` |
| `GET /terminal/logs?job_id=` | `cccms:terminal:logs` |
| `POST /terminal/run` | `cccms:terminal:run` |

### 26.1 为什么不做成「输入框里敲命令」

那等于把后台当成一台 SSH 客户端：面板被撞库、XSS、内鬼的任何一种方式拿到，攻击面就从
「某个接口」扩大到「整台机器」。这里能做的只有三件事：

1. **选**一条登记过的命令（`key`）；
2. **填**声明过的参数（类型 / 范围 / 正则三选一必过）；
3. **看**输出。

`argv` 在 PHP 配置里以**数组**给出，`proc_open()` 也传数组（不经 `sh -c`），参数值即使含
`;` `|` 反引号也只是一个普通字符串。测试里有一条防回归断言：命令表不得出现
`sh -c` / `cmd /c`。

### 26.2 风险等级与二次确认

| risk | 含义 | 权限要求 | 确认方式 |
|------|------|----------|----------|
| 1 | 只读 / 幂等同步 | `cccms:terminal:run` | — |
| 2 | 删数据、归档 | 额外 `cccms:terminal:danger` | 手输命令 `key` |
| 3 | 改库结构 | 同上 | 手输命令 `key` |

`confirm` 由后端校验（`TerminalLogic::run()`），前端弹窗只是提醒。当前表里
`log_archive = 2`、`db_upgrade = 3`，`db_upgrade` 与 `log_archive` 在测试里被钉死 ——
防止有人为了「少点一次确认」把它们改成 1。

### 26.3 队列消费与超时

命令执行在队列进程里，HTTP 请求只负责投递并拿到 `job_id`；前端轮询
`GET /terminal/logs` 取输出（90 秒后停止，避免队列进程没起时页面一直转）。

- 单条命令超时 `terminal.timeout`（默认 120s），超时 `proc_terminate` 并记退出码 `124`；
- 输出上限 `terminal.output_limit`（默认 8000 字节），超出部分丢弃并标注截断，
  避免一条刷屏的命令把作业日志表写爆；
- 退出码非 0 视为失败：作业进死信，输出（截 1800 字）落在 `last_error` 与作业日志里。

### 26.4 新增一条命令

```php
[
    'key'     => 'my_task',           // 小写标识符，同时是二次确认要手输的字符串
    'label'   => 'terminal.my_task',  // 语言包 key
    'group'   => 'data',
    'risk'    => 1,
    'argv'    => ['{php}', '{root}/webman', 'cccms:my-task'],
    'params'  => [['name' => 'days', 'label' => 'terminal.param_days', 'type' => 'int', 'min' => 1, 'max' => 365]],
]
```

配套：在 `lang/{zh-CN,en-US}/terminal.php` 补 `my_task` / `my_task_desc` / 参数名；
改完执行 `php webman reload`（配置在进程启动时读入）。

## 二十七、实时推送（Realtime / F9，SSE / WebSocket 双通道）

| 项 | 说明 |
|----|------|
| 用途 | 公告发布后顶栏角标立刻变、作业完成后任务中心立刻刷新、管理员踢人后对方立刻退出 |
| 通道 | SSE（`text/event-stream`）`process/Sse.php`，默认端口 8788；WebSocket `process/Websocket.php`，默认端口 8789 |
| 事件总线 | `support/Realtime.php`：Redis List（`LPUSH` / `LTRIM` / `EXPIRE`），按用户分频道；**两条通道共用** |
| 前端 | `composables/useRealtime.ts`，在 `BasicLayout` 启动，全后台一条连接；driver 由 `VITE_REALTIME_DRIVER` 选择 |
| 部署 | 端口要在内网可达；Nginx 反代见 `nginx.conf.example` 的 `/sse/stream` 与 `/ws/stream` |
| 不做 | 离线消息存储、IM / 聊天室；**落库优先**，推送只加速 |

### 27.1 为什么是独立进程 + 裸 TCP

SSE 是长连接：一条连接要在几十分钟里持续吐字节。webman 的 HTTP worker 是
「请求 → 响应 → 释放」，控制器返回后没有句柄能继续写入 —— 硬挂长连接等于用业务 worker
的数量换在线人数。所以推送单独起一个 workerman 进程。

这个进程用 `tcp://` 而不是 `http://`：workerman 的 HTTP 协议每次 `send()` 都会补一整套响应头，
第二帧就成了「另一个 HTTP 响应」，浏览器不会当成同一条事件流。裸 TCP 下握手时自己写一次头，
之后按 `id/event/data` 帧发文本即可（`Content-Length` 缺席 + `keep-alive` 正是 SSE 的语义）。

### 27.2 鉴权与频道隔离

- 令牌走 query（`GET /stream?token=`）：`EventSource` 不能带自定义请求头；
  代价是可能进代理访问日志，样例配置对 `/sse/stream` 关掉了 access log。
- 验签之后还要查 `TokenBlacklist`：登出 / 被踢的令牌**签名仍然有效**，不查黑名单会让
  「强制下线」在实时通道上失效 —— 被踢的人还能继续收推送。
- 一个用户一个频道（`user:{id}`），没有全局广播频道。群发公告时按**当前在线用户**逐个写，
  给全库用户各留一条没人读的列表等于用推送制造垃圾。

### 27.3 事件

| 事件 | 触发点 | 前端处理 |
|------|--------|----------|
| `notice` | 公告创建 / 更新为「已发布」（只推在线且属于投放范围的人） | 刷新顶栏未读角标 |
| `job` | 作业完成 / 失败（只推 payload 带 `user_id` 的作业） | 任务中心刷新列表 |
| `logout` | 强制下线（单会话带 `jti`，整用户不带） | 清本地登录态并跳登录页 |

`logout` 带 `jti` 时，前端会比较本地令牌的 `jti`：同账号在别的设备上的会话不该被误登出。

### 27.4 断线重连与「不丢」

- 事件 id 用 Redis `INCR` 生成，全局单调递增；前端把收到的最大 id 记住，
  重连时以 `last_id` 传给后端，后端只发更大的。
- 每个频道只留最近 `retention`（默认 100）条、`ttl`（默认 600s）：**超出窗口就补不回来**了，
  这是刻意的 —— 真正的数据在 `sys_notice_read` / `sys_job` 里，断线久了应当重新拉接口，
  而不是靠推送补一份可能已经过期的副本。
- 前端重连用指数退避（1s → 2s → 4s … 最多 30s），不用 `EventSource` 自带的：
  自带重连无法传 `last_id`，也无法在登出时彻底停掉。

### 27.5 部署与排查

1. 端口 8788（SSE）/ 8789（WS）对内网可达（Docker 要 `-p`，多实例每台各一个进程）；
2. Nginx 反代 `/sse/stream`，**必须** `proxy_buffering off` 且 `proxy_read_timeout` 调到 1h；
3. 前端 `VITE_SSE_URL=/sse/stream`（https 页面直连 8788 会被当混合内容拦掉）；
4. 走 WS 通道时：反代 `/ws/stream`（`Upgrade` / `Connection` 头不能少），前端
   `VITE_REALTIME_DRIVER=ws` + `VITE_WS_URL=/ws/stream`；
5. 连不上时先看进程：`php webman status` 里应有 `realtime_sse` / `realtime_ws`；
   再 `curl -N 'http://127.0.0.1:8788/stream?token=...'` 看是否立刻返回 `: connected`。

> 推送不可用时**功能仍然完整**：未读数、任务状态本来就有接口拉取，前端只是少了一次「立刻」。

### 27.6 WebSocket 通道（可选 driver）

后台场景都是服务端单向下行，SSE 已经够用；WebSocket 只在需要**客户端上行**时才开
（协作、终端输出流式回传等）。两条通道**共用同一个事件源**（`Realtime`）与同一套事件名 /
载荷，切换 driver 后页面代码零改动。

| 项 | 说明 |
|----|------|
| 进程 | `process/Websocket.php`，`websocket://`，默认端口 **8789**（`CCCMS_WS_PORT` 可覆盖） |
| 鉴权 | 握手 query `?token=...&last_id=...`，验签后同样查 `TokenBlacklist` |
| 协议 | 一条 JSON：`{id, event, data, at}`（SSE 把 `id` / `event` 放协议层，WS 没有这一层） |
| 上行 | 目前只有 `{"type":"ping"}` → `pong`；扩展时**不要在消息里接受身份字段**，身份只认握手令牌 |
| 前端 | `VITE_REALTIME_DRIVER=ws`；地址 `VITE_WS_URL`（生产建议 `/ws/stream`） |
| 部署 | Nginx 需 `Upgrade` / `Connection` 头，见 `nginx.conf.example` 的 `/ws/stream` |

两个实现细节值得记住：

- **握手回调里不能让异常逃出去**：workerman 对 `onWebSocketConnect` 抛出的异常执行
  `Worker::stopAll()`，一条坏令牌就能把整个推送进程停掉 —— 鉴权失败一律 `close()`。
- **主动断开不能触发重连**：`disconnectRealtime()` 先把 `socket` 置空再 `close()`，
  `onclose` 里据此判断「这是主动断开」；否则登出后会在 1 秒后自己连回来。
