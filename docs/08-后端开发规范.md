# 后端开发规范

> 本文是后端开发的**必守约定**：分层职责、命名、代码风格、数据访问规则、异常处理，以及「新增接口 / 新增插件」的标准步骤与提交前检查清单。

---

## 一、分层职责

```
Controller  →  Logic  →  Model
   薄           厚         薄
```

| 层 | 目录 | 职责 | 明确禁止 |
|----|------|------|----------|
| **Controller** | `app/controller/` | 解析请求、声明权限注解、调用 Logic、`return $this->ok(...)` | ❌ 写业务逻辑 ❌ 直连数据库 |
| **Logic** | `app/logic/` | 业务规则、校验、事务、编排；**数据访问唯一收口** | ❌ 感知 HTTP（不读 `Request`） |
| **Model** | `app/model/` | 表结构映射、数据权限声明、软删除 / 时间戳 | ❌ 写业务分支 |
| **support** | `support/` | 框架级基础设施（可直查库） | ❌ 放业务逻辑 |

> **控制器直连数据库会被 `cccms:data-scope-check` 直接拦下**（R1），因为那等于悄悄关掉数据权限。

---

## 二、命名与文件

| 对象 | 规范 | 示例 |
|------|------|------|
| 命名空间 | `plugin\{插件}\{子目录}` | `plugin\cccms\app\logic` |
| 控制器 | `{模块}Controller.php` | `UserController.php` |
| 逻辑层 | `{模块}Logic.php`，`final class`，方法 `static` | `UserLogic.php` |
| 模型 | 单数大驼峰 | `User.php`、`CrontabLog.php` |
| 表名 | 模型 `$name` 省略 `sys_` 前缀 | `protected $name = 'user';` |
| 权限节点 | `{插件}:{模块}:{动作}` | `cccms:user:save` |

## 三、PHP 代码风格

每个 PHP 文件头部：

```php
<?php

declare(strict_types=1);

namespace plugin\cccms\app\logic;
```

约定：

- 全部开启 `declare(strict_types=1)`。
- 类的 PHPDoc 写明**职责边界**与**关键设计原因**（尤其是有意为之的反直觉行为）。
- Logic / support 工具类用 `final class`；方法能 `static` 就 `static`。
- 类型尽可能显式（参数、返回值、数组形状用 PHPDoc `@param array{...}` / `@return array<int,array{...}>`）。
- 抛业务错误统一 `throw new ApiException('消息', code)`；不要 `return ['code' => ...]`。
- JSON 字段走 ORM 的 `$json` 声明（如 `protected $json = ['params'];`；**列本身是 `text` 存 JSON 字符串**，
  不用 MySQL 原生 `json` 类型，见 [13-数据模型](13-数据模型.md)），**不要逗号字符串拼接**。
- 时间戳交给数据库默认值（`$autoWriteTimestamp = 'datetime'`），业务层不手写 `date()`。
- 数组键顺序、导入顺序（`use` 按字母序）保持一致。

> **本节由工具兜底**：`.php-cs-fixer.dist.php` 以 `@PSR12` 为基线（另含短数组、单引号、
> `use` 排序去重、多行数组尾逗号），`composer cs:check` 在 CI 里阻断不合规提交，
> 本地 `composer cs:fix` 一键修复。校验范围是 `plugin/` 与 `tests/`，
> **不含** `server/config`、`server/support`、`server/app` 这些 Webman 模板自带文件
> （理由见 [11-常用命令与运维 §1.9](11-常用命令与运维.md#19-composer-cscheck--csfix--后端代码风格)）。
>
> 类型层面的问题由 `composer analyse`（PHPStan level 5 + baseline）兜底，
> baseline **只准减不准增**。

## 四、控制器规范

```php
#[Permission(slug: 'cccms:user:save', title: '用户保存')]
#[Restrict(methods: ['POST'])]
public function save(Request $request): Response
{
    return $this->ok(UserLogic::create($request->all(), $request->user));
}
```

- 必须继承 `plugin\cccms\basic\BaseController`。
- **必须声明权限注解**（否则 500，fail-closed）。
- 写操作补 `#[Restrict(methods: ['POST'])]`。
- 给 `#[Permission]` / `#[NoAuth]` / `#[NoLogin]` 写 `title`，它会作为操作日志的操作名。
- 只做「取参 → 调 Logic → 返回」，不写分支判断。
- 新增方法后**记得在 `config/route.php` 注册路由**（默认路由已禁用）。

## 五、Logic 规范

```php
final class UserLogic
{
    /** 可写字段白名单 */
    private const FIELDS = ['username', 'nickname', 'email', 'phone', 'status'];

    public static function create(array $data, UserContext $user): array
    {
        PasswordPolicy::assertValid((string)($data['password'] ?? ''));
        // ...
        return ['id' => $id];
    }
}
```

- **数据访问一律走模型**（`User::where(...)`），尽量避免 `Db::name()`。
- 确实需要查询构造器（跨表聚合、原生 SQL、元数据反射）时，注意：
  - 软删场景用 `SoftDelete::apply()` / `onlyTrashed()`；
  - 涉及**受控表**的裸查询会被 `data-scope-check` 报错，应改模型。
- 字段白名单显式列出，不整体 `$data` 落库。
- 唯一性 / 存在性校验用 `withoutAllScopes()`（唯一键**全局唯一**，必须连租户一起绕过），回收站占用一并检查（`withTrashed()`）。
- 单条读写入口统一 `assertInScope()`：越权 403、不存在 404。
- 事务用 think-orm 的 `Db::transaction()`。

## 六、模型规范

```php
final class User extends BaseModel
{
    protected $name = 'user';
    protected $hidden = ['password'];

    /** 数据权限：仅本人 = 自己这个账号；本部门经 sys_user_dept */
    protected $dataScope = [
        'owner' => 'id',
        'dept'  => [self::class, 'deptScope'],
    ];

    public static function deptScope($query, array $deptIds): void
    {
        $userIds = UserDept::whereIn('dept_id', $deptIds)->column('user_id');
        $userIds ? $query->whereIn('id', $userIds) : $query->whereRaw('1 = 0');
    }
}
```

必守：

| 项 | 约定 |
|----|------|
| 表名 | `protected $name = 'user';`（无 `sys_` 前缀） |
| 软删 | 有 `delete_time` 的什么都不用做；**没有的必须** `protected $deleteTime = false;` |
| 时间戳 | 没有 `update_time` 的模型声明 `protected $updateTime = false;`；纯关联表声明 `protected $autoWriteTimestamp = false;` |
| JSON 列 | `protected $json = ['dept_ids'];` |
| 数据权限 | 参与就声明语义；**不参与必须显式** `protected $dataScope = false;` |
| 租户隔离 | 表有 `tenant_id`（见 `TenantContext::TABLES`）就声明 `protected $tenantScope = true;`；**默认关闭**——代码生成器产出的 `ks_*` 插件表没有该列。写入侧 `tenant_id` 由 `ScopedQuery` 自动盖，业务代码**不要**自己赋值 |

> ⚠️ **陷阱**：模型参与数据权限但表没有 `create_by` / `dept_id` 列且未声明语义，查询会报「列不存在」——这是刻意的，逼你把语义写清楚。

## 七、数据访问规则

优先级：**能用模型就用模型**。

| 场景 | 正确写法 |
|------|----------|
| 普通查询 | `User::where(...)->select()` |
| 列表（参与数据权限） | `User::newScopedQuery()->paginate(...)` |
| 回收站列表 | `Model::onlyTrashed()` |
| 恢复 / 彻底删除 / 复用回收站节点 | `Model::withTrashed()` |
| 唯一性 / 存在性校验（唯一键**全局唯一**） | `Model::withoutAllScopes()` + `withTrashed()`（必须连租户一起绕过，否则漏判并写出脏索引） |
| 只看本租户的候选项（如「绑定部门」下拉） | `Model::withoutGlobalScope()`（跳出档位收窄，**保留**租户） |
| 查询构造器直查**受控表** | `TenantContext::table('user')` / `applyToQuery()` / `stamp()`（替代 `Db::name()`，自动叠加租户条件） |
| 查询构造器直查（基础设施 / 元数据） | `Db::name()` + 必要时 `SoftDelete::apply()` |

`support/SoftDelete.php` **只服务查询构造器直查场景**（回收站模块、`AuthService`、`DataScope`、调度进程等），能用模型的地方不要用它。

> 逃生口**语义不同，必须能从代码上看出来并注明理由**：
> `withoutGlobalScope()` 只跳出**数据权限**（租户条件仍生效），`withoutAllScopes()` 连**租户**一起跳出
> （仅登录链路 / CLI / 迁移 / 全局唯一性查重）。详见 [06-数据权限 §十二](06-数据权限.md#十二多租户租户是硬边界档位是租户内的软范围)。

### 列表排序（SortInput）

前端列头排序统一下发 `sort`（列的 `prop`）+ `order`（`asc` / `desc`），后端由
[`support/SortInput.php`](../../server/plugin/cccms/support/SortInput.php) 统一解析：

```php
// SORTABLE 是显式白名单：前端 prop => 真实列名
// 只登记有实际排障 / 运营价值的列：时间、数值、排序号；
// 用户名、标题、编码、IP 之类的标识列不要登记（排了也帮不上找数据）。
private const SORTABLE = [
    'login_time'  => 'login_time',
    'create_time' => 'create_time',
];

$total = $query->count();
SortInput::apply($query, $params, self::SORTABLE);                 // 默认 id desc
// 或：SortInput::apply($query, $params, self::SORTABLE, 'sort', 'asc', 'asc');
$list = $query->page($page, $limit)->select()->toArray();
```

必守：

| 项 | 约定 |
|----|------|
| 后端身份 | **前端字段只用于命中白名单**，绝不能 `order($params['sort'])`；计算列 / 合成列不登记 |
| 默认排序 | 未指定 / 未知列一律回落到页面原有的默认排序（`$defaultField` / `$defaultDir`） |
| 翻页稳定 | 命中排序时自动追加主键排序（`$tieDir` 与页面默认方向一致），避免同值行跨页重复 / 漏行 |
| 固定顺序链路 | 导出、keyset 分页、规则执行等**不要**接 `SortInput`（如日志导出固定 `id asc`） |
| 非 SQL 数据源 | 在线会话（Redis）在 `OnlineSession` 内做内存排序，仍走同一套 `SORTABLE` 白名单 |
| 前端配套 | 列上声明 `sortable: 'custom'`；`useTable` 页面由 `ArtTable` 自动接管，无 `useTable` 的页面自行监听 `sort-change` |

> 新增列表页时，白名单里只放**真实存在的列**；排序字段是否有索引要一并考虑，大数据表避免全表排序。

## 八、异常与响应

- 业务错误：`throw new ApiException('无权操作该用户', 403);`
- 控制器返回：`$this->ok($data)` / `$this->fail($msg, $code)`。
- 不要自己 `return new Response(...)`，统一走 `Result`。
- 异常码约定见 [04-框架介绍](04-框架介绍.md#51-约定俗成的错误码)。

---

## 九、配置读取

- 系统配置（可后台改）→ `SysConfig::getString/getInt/getBool/getList('key', 默认值)`。
- 静态配置（改代码才变）→ `config('plugin.cccms.xxx.yyy')`。
- 环境相关（数据库、密钥、存储凭证）→ `getenv()` 覆盖默认值。
- **不要**把可变配置读进进程内静态属性（长驻进程会不生效）。

## 十、注释规范

- 类注释写「职责 + 关键设计原因 + 陷阱」。
- 反直觉的写法**必须**注明「为什么这样做」，否则后人会「顺手修正」。
- 用 `// TODO:` 标注待办时，同步登记到 [开发计划](开发计划.md)。
- 不要写「这里做了 X」这种重复代码的废话注释，写「为什么是 X 而不是 Y」。

## 十一、新增一个业务插件的完整步骤

以 `plugin/shop`（商品管理）为例。

### 11.1 后端

> **推荐用脚手架一键生成**（见 [11-常用命令与运维 §1.13](11-常用命令与运维.md#113-cccmsplugin-create--生成业务插件骨架并登记菜单)）：
> 它把下面第 1~3 步（骨架 + 示例 Controller + 菜单声明）一次生成，并自动跑完第 7 步的纳管命令。
>
> ```bash
> php webman cccms:plugin-create shop --type=backend --title=商城 --module=goods --module-title=商品
> ```
>
> 公开前台应用（如 `plugin/index`）用 `--type=frontend`，不产 `db/menu.php`、不参与权限体系。
> 下面的手工步骤与之等价，用于理解生成物或按需调整。

1. **建目录**：

   ```
   server/plugin/shop/
   ├── app/controller/  app/logic/  app/model/
   ├── config/  (app.php / route.php / middleware.php / exception.php)
   └── db/      (menu.php / schema.sql / seed.sql)
   ```

2. **配置插件**：`plugin/shop/config/app.php` 返回 `['enable' => true]`；`route.php` 显式声明路由（`Route::disableDefaultRoute()`）。
   中间件：如需登录鉴权，挂上 `CheckLogin` / `CheckAuth` 等；不需要则仅 `Cors`。

3. **声明菜单**：`plugin/shop/db/menu.php` 声明目录与菜单（不声明按钮）：

   ```php
   return [
       [
           'slug' => 'shop', 'title' => '商城管理', 'type' => 1,
           'icon' => 'icon-apps', 'path' => '/shop', 'component' => '', 'sort' => 9,
           'children' => [
               ['slug' => 'shop:goods', 'title' => '商品管理', 'type' => 2,
                'path' => '/shop/goods', 'component' => 'shop/goods/index', 'icon' => 'icon-apps', 'sort' => 1],
           ],
       ],
   ];
   ```

4. **建表脚本**：`plugin/shop/db/schema.sql`（用 `CREATE TABLE IF NOT EXISTS`，幂等）；
   数据权限接入参考第 5 步。

5. **写模型**：参与数据权限就声明 `$dataScope`，否则 `false`。有 `create_by` 的表默认即可。
   表若要参与**租户隔离**：加 `tenant_id bigint unsigned NOT NULL DEFAULT 0` + `KEY idx_tenant(tenant_id)`，
   模型声明 `$tenantScope = true`，并把表名登记进 `TenantContext::TABLES`；**唯一键不要加租户列**。

6. **写 Logic + Controller**：Controller 声明 `#[Permission(slug: 'shop:goods:index', title: '商品列表')]`。
   **写方法必须显式声明可写字段白名单**（防 Mass Assignment）：

   ```php
   private const FIELDS = ['name', 'price', 'status', 'remark'];

   public static function create(array $data): int
   {
       $data = FilterInput::only($data, self::FIELDS);   // 白名单外的键一律丢弃
       ...
   }
   ```

   `cccms:write-guard-check` 会校验这一点（判据：方法体内出现 `FilterInput::only(`，
   或委托给同类中一个调用了它的方法）；确需整数组透传时写 `// @write-guard-ignore` 并说明理由。

7. **执行纳管命令**：

  ```bash
  php webman cccms:menu-sync            # 同步菜单
  php webman cccms:perm-scan            # 生成按钮节点
  php webman cccms:db-upgrade           # 执行插件 schema
  php webman cccms:data-scope-check     # 检查数据权限接入
  php webman cccms:write-guard-check    # 检查写方法是否声明字段白名单
  ```

8. **（可选）登记受控表**：需要配自定义数据规则时，在数据权限页「受控表」添加，或在 `db/seed.sql` 里 `INSERT`。

9. **（可选）扩展回收站类型**：`plugin/shop/db/recycle.php` 声明类型。

### 11.2 前端

10. **页面**：`frontend/src/pages/shop/goods/index.vue`，`defineOptions({ name: 'shop:goods' })`（**必须等于菜单 slug**）。
11. **接口封装**：`frontend/src/api/shop/goods.ts`。
12. 菜单 `component` 填 `shop/goods/index`，与页面路径对应。

> `plugin/index` 是「无 `db/menu.php` 的公开插件」范例，可参考它的最小配置。

## 十三、国际化（i18n）

后端 i18n 由 `plugin/cccms/support/I18n.php` 提供，语言包在 `plugin/cccms/lang/{locale}/{命名空间}.php`。

| 关注点 | 约定 |
|--------|------|
| 语言解析 | `I18n::locale()`：`?lang=` → `Accept-Language` → 静态配置 `plugin.cccms.app.locale` |
| 翻译 | `I18n::t('user.not_found')`；插值写 `{name}`：`I18n::t('auth.locked', ['minutes' => 10])` |
| 存在性判断 | `I18n::has('menu.xxx')`：当前语言或默认语言命中其一即 true，**刻意不写 missing 日志**（「查不到」在菜单 / 配置项场景是正常分支） |
| key 结构 | `{命名空间}.{键名}`；命名空间按**第一个** `.` 切分，故键名本身可再含 `.`（如 `config_item.group.系统`） |
| 语言列表 | `I18n::locales()`，受静态配置 `plugin.cccms.app.locales` 控制，始终包含默认语言 `zh-CN` |
| 缺词回落 | 当前语言缺 key → 回落 `zh-CN` → 仍缺则返回 key 原文并记 `warning` 日志（不返回空串，避免界面空白） |

命名空间按业务归类，**不要往 `common` 里堆**：

| 命名空间 | 内容 |
|-----------|------|
| `common` | 协议级错误（`method_not_allowed` / `encoding_not_acceptable`）、通用结果与批量操作文案 |
| `auth` / `profile` | 登录鉴权、个人中心 |
| `menu` | 权限节点 / 菜单标题，**key 即节点 slug** |
| `config_item` | 配置项名；分组名 `group.{中文分组}`；选项名 `option.{value}` |
| `user` `role` `dept` `post` `dict` `category` | 对应业务模块 |
| `recycle` `data_scope_table` `data_rule` `generator` `file` `log` `notice` `online` `crontab` `maintenance` `upgrade` | 对应业务模块 |

### 13.1 什么要翻，什么不翻

- **要翻**：用户可见提示语（`ApiException` 消息、控制器 / 中间件返回文案）、菜单与权限节点标题、系统配置项名。
- **不翻**：`#[Permission(title:)]` 注解标题（保持中文，运行时由 `menu.{slug}` 覆盖）、注释、`Log::` 日志、CSV 导出内容、**用户录入的业务数据**（自建菜单名、字典项、部门 / 岗位名 —— 那是用户自己的数据）。

### 13.2 内置项按 slug / 配置项名覆盖返回

内置菜单与配置项在库里存中文（作为兜底），返回前端前按 key 覆盖为当前语言：

- `MenuLogic::localizeTitles()`：`title` 命中 `menu.{slug}` 才覆盖 → 管理员自建菜单（无对应 slug）自动原样返回。
- `ConfigLogic::localize()`：`title` 命中 `config_item.{name}` 才覆盖；另额外下发 `group_label`。`group` **原样保留**——它是前端 `?group=` 的过滤值，翻译它会破坏过滤。

### 13.3 新增提示语

```php
// 不要
throw new ApiException('用户不存在', 404);

// 要
throw new ApiException(I18n::t('user.not_found'), 404);
```

新增 key 必须**同时**补 `zh-CN` 与 `en-US`。`server/tests/cases/I18nTest.php` 会校验两个语言包的 key 集合完全一致，以及每个权限节点 slug 都有 `menu` 标题翻译。

## 十四、提交前检查清单

| # | 检查 | 命令 / 方式 |
|---|------|-------------|
| 1 | PHP 语法 | `php -l` 全部改动文件 |
| 2 | 权限节点已声明且合法 | `php webman cccms:perm-scan --check`（只校验不写库） |
| 3 | 菜单声明已同步 | `php webman cccms:menu-sync` |
| 4 | 数据权限接入无错误 | `php webman cccms:data-scope-check` |
| 5 | 数据规则无冲突 | `php webman cccms:data-rule-check` |
| 6 | 写方法已声明字段白名单 | `php webman cccms:write-guard-check` |
| 7 | 静态分析无新增报错 | `composer analyse`（PHPStan level 5 + baseline；**不得往 baseline 加条目**） |
| 8 | 代码风格符合规范 | `composer cs:check`（不符合就 `composer cs:fix`） |
| 9 | 新表 / 新列已写入 `db/schema.sql` | `php webman cccms:db-upgrade`（新装建表；不会给已存在的表补列） |
| 10 | 后端单元测试 | `composer test`（库不可用时相关用例自动跳过） |
| 11 | 前端类型检查与构建 | `cd frontend && npm run build`（含 `vue-tsc --noEmit`） |
| 12 | 前端格式与 lint | `cd frontend && npm run format:check && npm run lint` |
| 13 | 文档与更新日志已同步 | 改动机制 / 接口 / 命令 / 配置则更新 `docs/` 与 [更新日志](更新日志.md) |
| 14 | i18n 文案与语言包 | 新增提示语 / 菜单标题 / 配置项名时同步补 `lang/{zh-CN,en-US}`；前端补 `src/locales/{zh-CN,en-US}` 并跑 `npm run i18n:check` |

> 2 / 4 / 5 / 7 / 8 / 9 / 11（前端 key 一致性部分）都已接入 CI（见 [11-常用命令与运维](11-常用命令与运维.md#十二ci-与质量门禁)）。
