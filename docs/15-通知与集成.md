# 通知与集成

> 站内通知的投放、阅读与回执机制，以及短信/邮件/Webhook 等外部通道的接入边界。

---

## 一、能力范围

| 能力 | 状态 |
|------|------|
| 站内通知/公告 | 已实现 |
| 定向投放（全员/部门/角色/用户） | 已实现 |
| 已读回执与未读数 | 已实现 |
| 消息中心轮询 | 已实现 |
| 邮件（SMTP） | 已接入：仅用于找回密码验证码，`services/mail.py` |
| 短信 | 未接入 |
| Webhook / 企业微信 / 钉钉 | 未接入 |
| 找回密码验证码投递 | 邮件真实投递；dev 未配 SMTP 时写日志；prod 无可用渠道时返回 503 且登录页不显示入口 |

> ⚠️ **注意**：上表「未接入」表示没有可用的投递适配器。邮件只服务找回密码，站内通知不会外发；短信渠道在 prod 永远不可用。

## 二、数据模型

```text
sys_notice           通知主体（标题、正文、级别、时间窗）
sys_notice_target    投放目标（部门 / 角色 / 用户）
sys_notice_read      已读记录（通知 + 用户，唯一）
```

### 2.1 通知字段

| 字段 | 说明 |
|------|------|
| `type` | 1 通知 / 2 公告 / 3 提醒 |
| `level` | 1 普通 / 2 重要 / 3 紧急 |
| `title` / `summary` / `content` | 标题、摘要、正文（富文本） |
| `status` | 0 草稿 / 1 发布 |
| `scope` | 0 全员 / 1 部门 / 2 角色 / 3 用户 |
| `pinned` | 置顶 |
| `publish_at` / `expire_at` | 生效窗口 |
| `read_count` | 阅读计数（冗余） |

### 2.2 可见性规则

用户能看到一条通知，需同时满足：

1. 同租户、未删除。
2. `status=1`。
3. `publish_at` 已到或为空。
4. `expire_at` 未到或为空。
5. `scope=0`，或命中所属部门/角色/用户。

## 三、发布流程

```text
新建草稿 → 选择范围与目标 → 设置发布时间/过期时间 → 发布
        → 写入 sys_notice_target
        → 用户消息中心按可见性查询
        → 打开详情后 markRead
```

### 3.1 目标选择

- 部门：按 `sys_user_dept` 关联，包含该部门用户（不自动展开子部门）。
- 角色：按 `sys_user_role` 关联。
- 用户：直接指定。
- 多类目标取并集。

> **提示**：部门投放目前是「该部门直属成员」，不含下级部门。需要覆盖子树时，请选择多个部门。

### 3.2 发布时间

- 草稿状态不校验发布时间。
- 发布时若未填 `publish_at`，自动取当前时间。
- 修改时未提交 `expire_at`，保留原值，避免「只改标题把过期时间清空」。

## 四、阅读与回执

### 4.1 我的消息

| 接口 | 说明 |
|------|------|
| `GET /api/notice/my` | 分页，支持只看未读 |
| `GET /api/notice/unread` | 未读数 |
| `POST /api/notice/markRead` | 标记单条已读 |
| `POST /api/notice/markAllRead` | 全部已读 |

- 排序：置顶优先，其次发布时间倒序。
- 已读记录唯一键 `(notice_id, user_id)`，重复标记幂等。
- 并发重复标记会命中唯一键，服务按「已读」返回，不会 500。

### 4.2 已读回执

`GET /api/notice/report` 返回：

| 字段 | 说明 |
|------|------|
| `total` | 目标用户数 |
| `read` | 已读人数 |
| `unread` | 未读人数 |
| `list` | 已读用户明细（用户名、昵称、阅读时间） |

> **提示**：`total` 按目标范围实时计算；用户离职/停用后不再计入。

## 五、消息中心

`components/MessageCenterDrawer.vue` + `stores/notice.ts`：

- 顶部铃铛显示未读数。
- 打开抽屉加载消息列表。
- 点击消息标记已读并跳转业务页。
- 轮询间隔由前端控制，页面隐藏时暂停。

> ⚠️ **注意**：轮询不要太频繁。未读数接口会查 `sys_notice` 与 `sys_notice_read`，高频轮询会放大数据库压力。

**实时化决策（2026-10-22）**：**不做 WebSocket**。轮询在页面隐藏时会暂停，当前量级不构成成本项；
而 WebSocket 要额外解决握手鉴权、CSRF 豁免、多实例广播（Redis pub/sub）与连接数上限。
若将来触发（未读数轮询成为成本项，或产品要求实时推送），**先上 SSE**：单向推送即可满足消息场景，
且能复用现有 Cookie 鉴权与中间件链路。详见 [开发计划](开发计划.md#〇已定稿的决策) 与 N-04。

## 六、外部通道接入

### 6.1 现有边界

- `services/mail.py` 提供 SMTP 投递（标准库 `smtplib` + `asyncio.to_thread`，不引入 `aiosmtplib`）。
- `services/password_reset.py` 在验证码生成后：
  - 邮件渠道且 `smtp_ready`：真实投递，**成功之后**才把验证码写进 Redis。
  - 开发环境未配 SMTP、或短信渠道：写日志，便于联调。
  - 生产环境无可用渠道：`deliverable_channels()` 返回空 → 503，登录页也不显示「忘记密码」。
- 顺序要点：**先占冷却位 → 投递 → 落码**。投递失败立即释放冷却位并返回 503，
  用户不会被"发不出去 + 冷却 60 秒"同时卡住。
- 没有任何地方会真正发送短信。
- 已知残余风险：投递是同步的，真实发信比"账号不存在"的假响应慢，响应时间仍可作账号存在性的旁路。
  要彻底消除需改成入队投递（见 6.2 方式 B）。

### 6.2 推荐接入方式

**方式 A：同步发送（简单）**

在 `password_reset.request_code()` 生成验证码后调用 `notify.send_sms(...)`。

- 优点：实现简单。
- 缺点：外部网关抖动会拖慢登录/找回密码接口。
- 要求：设置超时、失败降级、限流。

**方式 B：入队 + 定时任务（推荐）**

1. 新增 `sys_notify_outbox` 表（或复用 `sys_crontab_retry`）。
2. 接口只写入待发送记录，立即返回。
3. 定时任务扫描待发送记录并调用网关。
4. 失败按重试策略回退。

这样外部通道故障不会影响主流程，也便于审计。

### 6.3 适配器接口建议

```python
class NotifyChannel(Protocol):
    name: str

    async def send(self, *, to: str, title: str, content: str) -> None: ...
```

实现：

| 通道 | 依赖 | 配置 |
|------|------|------|
| 邮件（已实现 `services/mail.py`） | SMTP | `CCCMS_SMTP_HOST` / `PORT` / `SECURITY` / `USER` / `PASSWORD` / `FROM` / `FROM_NAME` / `TIMEOUT` |
| 短信 | 云厂商 SDK | access_key / sign / template |
| Webhook | httpx | URL / secret / 重试 |

邮件走**环境变量**而不是 `sys_config`：SMTP 凭据属于部署机密，进数据库会多一份明文风险，
且发信能力要能在启动期就被 `smtp_ready` 判定。`host` 与 `from` 为空即视为没有邮件能力。

### 6.4 安全要求

- 验证码有效期短、一次性消费、失败计数。
- 发送频率限制：同一账号、同一 IP、同一通道。
- 日志不得记录完整手机号/邮箱，使用脱敏（邮件已接入 `core/redact.mask_email`）。
- 回调/Webhook 校验签名与时间戳。

## 七、与其他模块的关系

| 模块 | 关系 |
|------|------|
| 身份安全 | 找回密码验证码、登录异常提醒 |
| 定时任务 | 外部通道异步投递、重试 |
| 操作日志 | 通知发布、删除、已读回执操作可追溯 |
| 数据权限 | 通知按投放对象过滤，不走角色档位 |

## 八、接入检查清单

- [ ] 通道适配器有超时与重试
- [ ] 失败不会阻塞主流程
- [ ] 验证码一次性、有限期、限频
- [ ] 手机号/邮箱脱敏后入库与打日志
- [ ] 配置密钥使用 `secret` 类型
- [ ] 发送失败有可观测指标或告警
- [ ] 生产环境不再依赖「写日志」投递
