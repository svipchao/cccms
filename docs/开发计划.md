## 二、待办详情

### 2.1 安全加固

#### R-12 开发依赖告警处置（Vite / esbuild）

- **现状**：`composer audit --no-dev` 与 `npm audit --omit=dev --audit-level=high` 已进 CI，生产依赖清零；完整 `npm audit` 仍报 2 条中危：`esbuild <= 0.24.2`（GHSA-67mh-4wv8-2f99，开发服务器可被任意站点读取响应）与经它传递的 `vite <= 6.4.2`。
- **问题**：两者不进生产包，但会让「本地 `npm audit`」与「CI 门禁」结论不一致，容易被误读成门禁放水。
- **建议**：`npm audit fix --force` 会把 Vite 从 5 推到 8，牵连 `@vitejs/plugin-vue` / `@tailwindcss/vite` 兼容矩阵，风险远大于暴露面 → **暂不升级**。待 `@tailwindcss/vite` 明确支持 Vite 8 后一次性升级工具链，并回归 `build` / `lint` / `format:check` / `i18n:check`。
- **验收**：生产依赖审计保持 0 告警；开发依赖告警在工具链升级后清零，或判定「不修」转入「明确不做」。

### 2.2 性能与可观测

#### P2-11 性能基线与压测沉淀

- **现状**：性能优化点（数据权限请求级缓存、在线会话分段扫描）均来自设计推断，无实测基线，后续改动无法判断是否回归；N+1 除导出外未系统排查。压测脚本已就绪：[`server/loadtest/baseline.js`](../../server/loadtest/baseline.js)（k6，一条命令跑 6 个接口，支持 TOKEN / 账号密码两种鉴权），运行说明见 [11-常用命令与运维 §9.1](11-常用命令与运维.md#91-性能基线p2-11)。
- **建议**：在**目标数据量 + 目标硬件**的压测环境跑一次，记录 P95 / QPS / DB 查询数，填入 §9.1 的基线表；发现的 N+1 独立立项。
- **验收**：6 个接口有可复现基线且写入文档，脚本一条命令可跑。
- **工作量**：1 pd（脚本已完成，剩余为实测与记录）。

### 2.3 功能补齐

#### P2-3（遗留）生产环境接入真实网关

- **现状**：密码找回链路已通，邮件 / 短信通道为可插拔适配器，未配置真实网关时降级为日志输出。
- **建议**：生产部署前按 [02-安装部署 §5.6](02-安装部署.md#56-接入找回密码真实网关p2-3上线前必配) 在 `sys_config` 填 SMTP / 短信参数并验证送达率；确认找回接口已挂验证码 + IP 限流。
- **验收**：真实环境能收到找回邮件 / 短信。
- **工作量**：按所选网关 1~3 pd（配置动作，非代码改造）。

## 三、维护约定

1. **先登记再动手**：新增功能前先在 §一 登记（含工作量），方案写进 §二；**完成后从本文件移除**，实现与验收结论写入更新日志对应版本。
2. **一个功能只有一个编号**：登记前检索全文，重复的只在原编号下补细节。
3. **判为「不做」**：从本文件移除，写进 [更新日志 · 明确不做](更新日志.md#明确不做) 并写明原因。
4. **依据可核验**：条目须写明 `文件:行号`，无法确认的标「待确认」，不以推测代替事实。
5. **验收口径**：接口可用 + 页面可用 + 权限节点已生成 + 文档已更新 + 通过 [08-后端开发规范 · 提交前检查清单](08-后端开发规范.md#十四提交前检查清单)。
