## 〇、已定稿的决策

同一批议题不重复讨论；本节只留结论与边界。

| # | 议题 | 结论 |
|---|------|------|
| 1 | 附件访问模型 | 登录态直出（`/storage/**` 走 `load_user` + `apply_scope`），`GET /api/file/{id}/download` 是**唯一对外出口**；预签名 URL 推迟到上对象存储时再引入（见 [16-文件与导出](16-文件与导出.md#五下载与访问控制)） |
| 2 | 对象存储的节奏 | 已按"先驱动层、再 S3"落地（0.3.3→0.3.5）：预签名与访问模型一起改完，`/storage` 对 s3 记录 302 到限时直链。剩存量搬迁按需（见 F-01） |
| 3 | 登录闭环先补哪一半 | **通知通道优先**（没通道时找回密码只能整体 503）；MFA 字段与依赖已预留，推迟不产生债务（见 S-01） |
| 4 | WebSocket | **不做**。轮询够用，改造要额外解决握手鉴权、CSRF 豁免、多实例广播三件事（见 N-04） |
| 5 | 缺口池里的「明确不做」 | Excel 导入、MFA、WebSocket、字段级 `encrypt` 解密闭环，四条维持不做，触发信号见 0.1 |

### 0.1 「观察」项的触发信号

| 候选 | 不做的理由 | 满足即启动 |
|------|------------|------------|
| Excel 导入 | 通用导入的隐性成本（逐行校验、错误行回写、部分成功语义）远高于收益，目前只有一个表有诉求 | 出现**第二个**需要导入的业务表 |
| MFA | 半成品不如不做：缺绑定、验证、恢复码、强制策略四件事 | 客户合规要求（等保/ISO）或真实撞库事件 |
| WebSocket 消息中心 | 轮询可用；改造要动鉴权与多实例广播 | 未读数轮询 QPS 进入成本项，或产品要求"实时推送" |
| 字段级 `encrypt` 解密闭环 | 现在接只会让用户看到 base64 | 必须看明文的合规场景，且能接受解密动作单独审计 |
