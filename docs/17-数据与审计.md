# 数据与审计

> 操作日志如何产生、链路 ID 如何串联、审计哈希链如何封存与校验，以及日志的保留与合规读取。

---

## 一、一张表记录两类事件

`sys_log` 同时存放：

| 类型 | 产生方式 | 说明 |
|------|----------|------|
| 业务操作日志 | `OperationLogMiddleware` | 每个非跳过路由的请求 |
| 登录日志 | `services/auth.py` 显式写入 | 登录成功/失败，含失败原因 |

字段见 [13-数据模型 §八](13-数据模型.md#八日志与审计)。

---

## 二、记录流程

```text
请求进入
  → RequestContextMiddleware 生成 trace_id，读取 action_id / session_id
  → OperationLogMiddleware 读取请求体（JSON ≤ 64KB）
  → 路由执行
  → 记录状态码、耗时、响应摘要（≤ 8KB）
  → enqueue(LogEvent)
  → 后台协程逐条写入 sys_log
```

### 2.1 跳过规则

| 路径 | 原因 |
|------|------|
| `/ping`、`/healthz`、`/metrics` | 探针与指标噪音 |
| `/storage/**` | 静态文件 |
| `/auth/login` | 由登录逻辑单独记录，避免重复与密码泄露 |

### 2.2 读请求

成功的 GET 默认不记录（`CCCMS_LOG_RECORD_READ=false`）。失败的 GET 仍会记录。

### 2.3 队列与降级

- 队列容量 5000，满时丢弃并打 warning。
- 写入失败只记应用日志，不影响请求。
- 进程退出时停止写入协程，可能丢失队列中少量日志。

> ⚠️ **注意**：审计日志是「尽力而为」的异步写入，不是数据库事务的一部分。对审计有强一致要求的场景，应在业务事务内显式写入关键事件。

## 三、链路 ID

| ID | 生成方 | 作用 |
|----|--------|------|
| `trace_id` | 后端，每次请求 | 定位单次 HTTP 请求 |
| `action_id` | 前端，一次页面动作 | 聚合一次操作引发的多个请求 |
| `session_id` | 前端，一次浏览器会话 | 聚合一次登录期内的所有操作 |

查询入口：

| 接口 | 说明 |
|------|------|
| `GET /api/log/detail` | 单条详情 |
| `GET /api/log/trace` | 按 `trace_id` |
| `GET /api/log/action` | 按 `action_id` |
| `GET /api/log/session` | 按 `session_id` |

前端报错提示会带操作 ID，用户复制后可直接在日志页检索。

## 四、脱敏

`core/redact.py` 在写入前处理：

- 密码、口令、验证码、令牌、密钥等字段替换为 `***`。
- 请求体超过 8000 字符截断。
- 响应摘要超过 8KB 不记录完整内容。

> ⚠️ **注意**：脱敏是兜底，不是替代。新增敏感字段时，优先在业务层避免把明文放入请求体或响应。

## 五、审计哈希链

### 5.1 目标

让「删改日志」可被发现：

- 每条已封存日志的 `row_hash = sha256(prev_hash + canonical_json(row))`。
- 每个批次写一条 `sys_audit_seal`，记录首尾 ID、链头哈希、前序哈希、HMAC 签名。

### 5.2 封存

内置定时任务「封存审计日志链」每 10 分钟执行一次：

1. 取 `row_hash IS NULL` 的日志，按 ID 升序，`FOR UPDATE SKIP LOCKED`。
2. 逐条计算 `prev_hash` 与 `row_hash`。
3. 写入一条 seal 记录，`signature = HMAC-SHA256(audit_signing_key, head_hash)`。

### 5.3 校验

入口有两个，走同一段校验逻辑：

- `POST /api/log/audit/verify`（权限节点 `cccms:log:audit`）。
- CLI `python -m cccms.cli audit-verify`。

链是**全局**的（`prev_hash` 跨租户连续），只按本租户切一片会让校验必然报 broken，所以接口**仅平台租户超级管理员**可调用，其余账号返回 403。

`verify_chain()` 按 ID 升序做 keyset 分页（每批 1000 行），不把整表读进内存。`from_id` 用于分段校验：会先取该 ID 之前最近一条已封存行的 `row_hash` 作为起始 `prev_hash`，因此不需要从链头开始，也不会因为缺前序哈希误报 `broken`。

接口返回：

| 字段 | 含义 |
|------|------|
| `ok` | 见下方判定 |
| `total` | 扫描行数 |
| `unchained` | 尚未封存的行数（`row_hash IS NULL`） |
| `broken_count` / `broken_ids` | `prev_hash` 不连续的行数，以及前 20 条样本 ID |
| `modified_count` / `modified_ids` | 内容被改、哈希不匹配的行数，以及前 20 条样本 ID |
| `tail_stale` | 最后一条 seal 的链头与当前链不一致；分段校验（`from_id`）时恒为 `false`，因为局部扫描无权对链尾下结论 |
| `seal_ok` | 最后一条 seal 的签名是否有效 |
| `duration_ms` | 本次校验耗时 |

`ok` = `broken_count == 0` 且 `modified_count == 0` 且 `tail_stale == false` 且 `seal_ok == true`；**`unchained`（尚未封存的行）不影响它**——封存任务滞后是正常状态。

> **提示**：命中 ID 只返回前 20 条样本，因为链断了通常一次就是一大片，返回全量 ID 既没用又会撑爆响应体；规模以 `*_count` 为准。

### 5.4 删除保护

- 后台删除接口只允许删除 `row_hash IS NULL` 的日志。
- 已封存日志返回 409，避免破坏链条。
- 过期清理任务会物理删除旧日志，属于运维层面的保留策略，应在合规要求内执行。

## 六、日志查询

| 维度 | 参数 |
|------|------|
| 关键字 | `keyword`（用户名/标题/路径/消息） |
| 用户 | `username` |
| 标题 | `title` |
| 节点 | `node` |
| 方法 | `method` |
| 状态 | `status` |
| 状态码 | `status_code` |
| IP | `ip` |
| 参数包含 | `params_like` |
| 结果包含 | `result_like` |
| 时间 | `start` / `end` |
| 链路 | `trace_id` / `action_id` / `session_id` |

数据权限：`owner=user_id`，部门维度可见本部门成员的日志。超管不受限。

### 6.1 登录安全分析

`GET /api/log/login/analysis`：

- 时间范围与粒度（小时/天）。
- 总登录数、成功、失败、失败率。
- 失败用户 Top、失败 IP Top。
- 登录 IP 变化（同一用户前后 IP 不同）。

## 七、保留策略

| 项 | 默认 |
|----|------|
| 归档任务 | 每天 03:10，`cccms.log.archive`，把 90 天前**未封存**日志搬到 `sys_log_archive` |
| 保留天数 | `CCCMS_LOG_KEEP_DAYS=30` |
| 清理任务 | 每天 03:30 |
| 清理范围 | 早于保留期的日志（含已封存行，见下方警告） |
| 租户隔离 | 租户任务只处理本租户；平台租户可全量 |
| 封存保护 | 删除接口拦截已封存行；归档只搬运 `row_hash IS NULL` 的行 |

归档表 `sys_log_archive` 由迁移 `0004_log_archive` 用 `CREATE TABLE ... LIKE sys_log` 创建，
结构与索引与主表一致，可用 SQL 直接查询；它不在 ORM 模型里，**不会**被后台列表接口读到。
归档按 5000 行一批执行「先 INSERT 再 DELETE」，避免长事务与大 binlog。

> ⚠️ **注意**：清理任务会物理删除已封存日志，导致链头与 seal 不一致。若合规要求长期可校验，请延长保留期或先归档再清理。

## 八、审计读取场景

| 场景 | 做法 |
|------|------|
| 用户报错 | 用提示中的操作 ID 查 `action` |
| 接口异常 | 用响应头 `X-Trace-Id` 查 `trace` |
| 异常登录 | 登录分析 + IP 筛选 |
| 越权排查 | 按用户 + 时间 + 节点筛选 |
| 数据被改 | 校验哈希链，定位 `modified` 行 |
| 合规审计 | 导出 CSV（最多 10 万行，防注入处理） |
