# 安装部署

> 从零跑起来：环境准备、数据库初始化、前后端启动、生产反向代理与发布检查。

---

## 一、环境要求

| 组件 | 版本 | 说明 |
|------|------|------|
| Python | 3.12 ~ 3.13 | `pyproject.toml` 限定 `>=3.12,<3.14` |
| uv | 最新稳定版 | 依赖安装与虚拟环境 |
| Node.js | 20.19+ | 前端构建 |
| MySQL | 8.0+ | 需要生成列、JSON、`utf8mb4_0900_ai_ci` |
| Redis | 6.0+ | 令牌、会话、缓存、限流、调度锁 |
| Nginx | 1.20+ | 生产静态托管与反向代理 |

---

## 二、初始化数据库

```sql
CREATE DATABASE cccms DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'cccms'@'%' IDENTIFIED BY 'change-me';
GRANT ALL PRIVILEGES ON cccms.* TO 'cccms'@'%';
FLUSH PRIVILEGES;
```

> **提示**：`sys_config.scope_key` 使用 `coalesce(tenant_id, 0)` 生成列，MySQL 5.7 不支持该写法。

## 三、后端

### 3.1 安装依赖

```bash
cd backend
uv sync
```

### 3.2 配置环境变量

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

最少需要修改：

| 变量 | 说明 |
|------|------|
| `CCCMS_DB_HOST` / `PORT` / `USER` / `PASSWORD` / `NAME` | MySQL 连接 |
| `CCCMS_REDIS_URL` | 例：`redis://127.0.0.1:6379/0` |
| `CCCMS_JWT_SECRET` | 至少 32 字节；`dev` 留空会生成到 `backend/.dev-secrets.env` |
| `CCCMS_DATA_ENCRYPT_KEY` | 敏感配置加密密钥；dev 同样写入 `.dev-secrets.env` |
| `CCCMS_AUDIT_SIGNING_KEY` | 审计链签名密钥；dev 同样写入 `.dev-secrets.env` |
| `CCCMS_COOKIE_SECURE` | 生产必须为 `true` |
| `CCCMS_CORS_ORIGINS` | 前端域名，逗号分隔 |
| `CCCMS_STORAGE_LOCAL_ROOT` | 附件目录，默认 `../shared/uploads` |
| `CCCMS_EXPORT_LOCAL_ROOT` | 导出目录，默认 `../shared/exports` |
| `CCCMS_LOGIN_DEFAULT_TENANT` | 未绑定域名时的默认租户编码，默认 `platform` |

> ⚠️ **注意**：`CCCMS_EXPORT_LOCAL_ROOT` 必须位于 `CCCMS_STORAGE_LOCAL_ROOT` 之外。导出文件含日志与业务数据，只能经 `/api/export/task/download` 鉴权下载。

### 3.3 建表与初始化

```bash
uv run python -m cccms.cli init-db
uv run python -m cccms.cli seed
```

`seed` 会创建：

- 平台租户 `platform`（`is_platform=1`）
- 内置角色 `super_admin`
- 管理员账号（`CCCMS_ADMIN_USERNAME` / `CCCMS_ADMIN_PASSWORD`）
- 内置定时任务：审计封存、过期日志清理
- 菜单树与按钮权限节点

命令可重复执行：已存在的数据会跳过，不会重复插入。

### 3.4 启动

开发：

```bash
uv run uvicorn cccms.main:app --reload --port 8000
```

生产（示例 4 worker）：

```bash
uv run uvicorn cccms.main:app --host 127.0.0.1 --port 8000 --workers 4
```

> **提示**：多 worker 时每个进程都会执行启动校验与数据库连接池初始化；调度器应作为**独立单实例进程**运行，不要放进 web worker。

### 3.5 调度器

```bash
uv run python -m cccms.scheduler
```

调度器每 `CCCMS_SCHEDULER_POLL_INTERVAL` 秒扫描一次 `sys_crontab`，使用 Redis 锁保证同一任务在同一时刻只被一个实例执行。

本地开发希望「一条命令同时起 API 和调度器」时：

```bash
uv run python -m cccms.dev            # 默认 127.0.0.1:8000 + reload
uv run python -m cccms.dev --no-reload --port 8001
```

`uv sync` 只负责安装依赖，不会启动任何进程；`cccms.dev` 在 `CCCMS_ENV=prod` 时会拒绝运行。

### 3.6 生产密钥校验

`CCCMS_ENV=prod` 时，启动阶段会检查：

- `CCCMS_JWT_SECRET` 长度 ≥ 32 字节
- `CCCMS_DATA_ENCRYPT_KEY` 非空
- `CCCMS_AUDIT_SIGNING_KEY` 非空
- `CCCMS_COOKIE_SECURE=true`
- `CCCMS_ADMIN_PASSWORD` 不能是默认值，且长度 ≥ 12

任一不满足直接拒绝启动，避免「带默认密钥上线」。

> `dev` 环境首次启动会把自动生成的密钥持久化到 `backend/.dev-secrets.env`（已加入 `.gitignore`），API、调度器和 CLI 共用同一套；显式写在 `.env` 的值优先级更高。

## 四、前端

### 4.1 安装与开发

```bash
cd frontend
npm ci
npm run dev
```

开发服务器默认 `http://127.0.0.1:5173`，并将 `/api`、`/storage` 代理到 `http://127.0.0.1:8000`（保留 `/api` 前缀）。

### 4.2 构建

```bash
npm run build
```

产物在 `frontend/dist`。构建前会执行 `vue-tsc --noEmit`，类型错误会阻断构建。

### 4.3 环境变量

前端仅使用 Vite 注入的 `VITE_*` 变量；默认同源部署，无需配置接口地址。若前后端分域部署，需在 Nginx 层处理跨域，或修改 `src/utils/request.ts` 的 `baseURL`。

## 五、Nginx 参考配置

```nginx
server {
    listen 80;
    server_name cms.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name cms.example.com;

    ssl_certificate     /etc/nginx/cert/fullchain.pem;
    ssl_certificate_key /etc/nginx/cert/privkey.pem;

    root /srv/cccms/frontend/dist;
    index index.html;

    # ---- 传输压缩 ----
    # 前端首屏关键路径（入口 JS + vue + CSS）约 600 KB，gzip 后约 185 KB，brotli 再少 15%。
    # nginx 默认只压缩 text/html，所以 application/javascript 必须显式列出来，
    # 否则所有 JS 都是裸传输 —— 这是首屏 LCP 最大的单点开销。
    gzip on;
    gzip_comp_level 5;
    gzip_min_length 1024;
    gzip_vary on;
    gzip_proxied any;
    gzip_types application/javascript application/json application/manifest+json
               text/css text/plain text/xml image/svg+xml;

    # 装了 brotli 模块时优先（ngx_brotli）
    # brotli on;
    # brotli_comp_level 5;
    # brotli_types application/javascript application/json text/css image/svg+xml;

    # ---- 缓存策略 ----
    # /assets/ 下的文件名带内容哈希（index-BCrr-RvC.js），内容永不变化 → 一年强缓存
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
        try_files $uri =404;
    }

    # index.html 与 Service Worker 必须每次回源校验，否则发布后用户拿不到新的 hash 清单
    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    location = /sw.js {
        add_header Cache-Control "no-cache";
    }

    # SPA：hash 路由只需回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 64m;
    }

    # 附件：只读静态目录
    location /storage/ {
        alias /srv/cccms/shared/uploads/;
        add_header X-Content-Type-Options nosniff always;
        add_header Cache-Control "public, max-age=86400";
    }

    # 探针与指标不要暴露到公网
    location = /metrics { deny all; }
}
```

> ⚠️ **注意**：不要把 `shared/exports` 配置成静态目录，也不要为它添加 `location`。导出文件只能走鉴权接口。

同时把 `CCCMS_TRUSTED_PROXIES` 设置为 Nginx 的出口地址，否则客户端 IP 会全部变成代理 IP，影响登录限流与审计。

### 5.1 验证压缩与缓存是否生效

```bash
# 1) 压缩：应看到 content-encoding: gzip（或 br），且 content-length 远小于文件体积
curl -sI -H 'Accept-Encoding: gzip, br' https://cms.example.com/assets/$(ls dist/assets | grep '\.js$' | head -1) \
  | grep -iE 'content-encoding|content-length|cache-control|vary'

# 2) 长缓存：应返回 public, max-age=31536000, immutable
curl -sI https://cms.example.com/assets/index-xxxx.js | grep -i cache-control

# 3) HTML / SW 必须回源校验：应返回 no-cache
curl -sI https://cms.example.com/ | grep -i cache-control
curl -sI https://cms.example.com/sw.js | grep -i cache-control
```

> 前端内置了一个只缓存「带哈希静态资源」的 Service Worker（`frontend/public/sw.js`），
> 第二次及以后的访问首屏资源全部命中本地缓存。它**不缓存 HTML**，所以发布新版本后
> 用户会拿到新的 `index.html` → 新的 hash 文件名，不存在“卡在旧版本”的问题。
> 因此 `/sw.js` 与 `/index.html` 都不能被强缓存。

## 六、systemd 示例

`/etc/systemd/system/cccms-api.service`：

```ini
[Unit]
Description=CCCMS API
After=network.target mysql.service redis.service

[Service]
Type=simple
User=cccms
WorkingDirectory=/srv/cccms/backend
EnvironmentFile=/srv/cccms/backend/.env
ExecStart=/srv/cccms/backend/.venv/bin/uvicorn cccms.main:app --host 127.0.0.1 --port 8000 --workers 4
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

`/etc/systemd/system/cccms-scheduler.service`：

```ini
[Unit]
Description=CCCMS Scheduler
After=network.target mysql.service redis.service

[Service]
Type=simple
User=cccms
WorkingDirectory=/srv/cccms/backend
EnvironmentFile=/srv/cccms/backend/.env
ExecStart=/srv/cccms/backend/.venv/bin/python -m cccms.scheduler
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now cccms-api cccms-scheduler
```

## 七、发布与回滚

1. 备份数据库与 `shared/`。
2. 拉取代码，`uv sync`、`npm ci && npm run build`。
3. 如模型有变更，先在预发库验证；当前仓库未附带迁移脚本，生产变更需人工 DDL。
4. 重启 `cccms-api` 与 `cccms-scheduler`。
5. 访问 `/healthz` 确认就绪。
6. 回滚：切回上一版本代码与前端产物，恢复数据库备份。

> **提示**：在线升级接口（`/api/upgrade/*`）默认关闭，仅 `dev` 环境且显式设置 `CCCMS_UPGRADE_ENABLE=true` 时可用；生产请使用上述发布流程。
