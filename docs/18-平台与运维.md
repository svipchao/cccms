# 平台与运维

> 面向平台运营与值班同学：租户生命周期、配置中心、缓存版本、定时任务、容量与发布。

---

## 一、多租户运营

### 1.1 租户模型

- 单库共享表，所有业务表带 `tenant_id`。
- 平台租户（`is_platform=1`）负责租户、菜单、全局配置。
- 租户编码唯一，域名唯一，均可软删除后复用。
- `max_users` 限制租户用户数（创建用户时校验，软删账号不计入），`0` 表示不限；平台租户不受限。
- `expire_at` 到期后无法登录；域名缓存也会检查到期时间。
- 租户级「维护模式」只拦截本租户请求；只有平台租户开启维护才会全局提升会话水位。

### 1.2 创建租户

1. 平台租户超管登录。
2. 「租户管理 → 新增」，填写编码、名称、联系人、到期时间、域名。
3. 为该租户创建管理员账号并分配角色。
4. 按需初始化字典、配置覆盖、通知。

> ⚠️ **注意**：接口忽略 `is_platform` 字段，平台标记只能由 `seed` 写入，避免出现第二个平台租户。

### 1.3 停用与删除

| 操作 | 效果 |
|------|------|
| 停用 | 无法登录；已登录令牌在下一次请求失效 |
| 软删除 | 从租户列表移除；数据保留，可回收站还原 |
| 平台租户 | 不允许修改/删除 |

### 1.4 租户切换

- 仅超管可用。
- 切换后重新签发令牌，`tid` 变为目标租户，`hid` 仍为归属租户。
- 目标租户必须有该用户且状态正常，否则拒绝。

## 二、配置中心

### 2.1 两层配置

| 层 | 载体 | 变更 |
|----|------|------|
| 进程配置 | 环境变量 / `.env` | 重启生效 |
| 业务配置 | `sys_config` | 后台保存，缓存失效 |

### 2.2 全局默认与租户覆盖

```text
tenant_id = NULL   → 全局默认值
tenant_id = 1001   → 租户 1001 的覆盖值
```

读取顺序：租户行 → 全局行 → 代码默认值。

保存规则：

- 平台租户超管可以修改全局默认行。
- 业务租户保存不会修改全局行；若只有全局行，自动复制一条租户覆盖行再写入。
- `secret` 类型提交空串表示清空密钥；未提交的字段保持不变。

### 2.3 缓存

- 键：`cccms:config:all:<tenant_id>`；全局为 `0`。
- 保存后清理当前租户缓存。
- 可调用 `POST /api/system/refresh` 手动刷新。
- Redis 不可用时直接回源数据库，功能降级但不阻断。

### 2.4 常用配置

| 键 | 说明 |
|----|------|
| `system.name` / `logo` / `icp` / `copyright` | 站点信息 |
| `system.maintenance` / `maintenance_notice` | 维护模式 |
| `security.login_captcha` | 登录验证码 |
| `ui.page_size` | 默认分页大小 |
| `ui.theme` / `ui.watermark` | 前端外观 |

## 三、缓存与版本号

| 版本键 | 递增时机 | 影响 |
|--------|----------|------|
| `cccms:auth:ver` | 权限/角色/菜单变更 | 权限上下文缓存 |
| `cccms:config:ver` | 手工 `POST /api/system/refresh`（保存配置只删缓存键，不递增版本号） | 配置缓存 |
| `cccms:dict:ver` | 字典变更 | 字典缓存 |
| `cccms:session:floor` | 全局强制下线 | 会话水位 |

排障顺序：

1. 数据库是否已更新。
2. 对应缓存键是否删除或版本号是否递增。
3. 是否连到了另一个 Redis 库。
4. 是否多实例部署但只清理了其中一台的本地缓存（本项目缓存全部在 Redis，一般不会）。

## 四、定时任务

### 4.1 运行模型

- `cccms.scheduler` 独立进程，按 `CCCMS_SCHEDULER_POLL_INTERVAL` 扫描。
- **`uv sync` 只安装依赖，不会启动调度器**；本地可用 `python -m cccms.dev` 同时起 API 与调度器。
- 用 Redis 选主锁避免多实例重复调度。
- 每个任务执行前获取任务锁，重叠策略 `skip` 时直接跳过。
- 执行结果写 `sys_crontab_log`，失败按策略写 `sys_crontab_retry`。

### 4.2 内置任务

| 名称 | Cron | 作用 |
|------|------|------|
| 封存审计日志链 | `0 */10 * * * *` | 每 10 分钟封存一批日志（`batch=200`） |
| 归档历史操作日志 | `0 10 3 * * *` | 每天 03:10 把 90 天前的日志移入归档表 |
| 清理过期操作日志 | `0 30 3 * * *` | 每天 03:30 清理超过 `CCCMS_LOG_KEEP_DAYS` 的日志 |
| 清理过期任务日志 | `0 50 3 * * *` | 每天 03:50 清理 30 天前的任务执行日志 |
| 清理过期已读回执 | `0 10 4 * * *` | 每天 04:10 清理 90 天前的通知已读回执 |
| 清理过期导出文件 | `0 0 4 * * *` | 每天 04:00 删除过期任务与文件（仅平台租户） |
| 清理未完成分片 | `0 15 4 * * *` | 每天 04:15 删除 48 小时前的分片目录（仅平台租户） |

前 5 条每个租户各有一份，后 2 条只给平台租户（导出目录与分片目录是全局资源）。

> **升级提示**：新增内置任务只写入 `seed`。已有环境升级后需重新执行 `uv run python -m cccms.cli seed`，或在「定时任务」页手动新增。

### 4.3 任务白名单

只允许调用 `services/crontab.py` 中 `TARGETS` 注册的函数。新增任务必须改代码并发布，不能在后台填任意函数名。

### 4.4 运维要点

- 调度器只跑一个实例；多实例时依赖 Redis 锁，但会浪费连接。
- 任务超时时间要小于锁 TTL。
- 大批量清理建议拆分为多个租户任务或分页执行。
- 任务失败日志保留最近若干条，长期趋势看应用日志。

## 五、容量与性能

| 资源 | 关注点 |
|------|--------|
| MySQL | 连接池 `pool_size + max_overflow`；`sys_log` 增长最快 |
| Redis | 在线会话与限流键；内存淘汰策略不要用 `allkeys-lru` 误删令牌 |
| 磁盘 | 附件与导出；`/healthz` 低于 5% 返回 503 |
| 应用 | worker 数 × 连接池 ≤ MySQL `max_connections` |

建议：

- `sys_log` 按月归档或分区。
- 附件按日期分目录（已按 `YYYY/MM/DD`）。
- 导出文件 60 分钟后过期（`EXPORT_KEEP_MINUTES`），由内置任务「清理过期导出文件」删除。
- 大表查询必须带 `tenant_id` 与时间范围。

> ⚠️ **扩容前置（硬约束）**：`docker-compose.yml` 的 `shared-uploads` / `shared-exports` 是**单机卷**，
> 多副本部署时附件会"在 A 节点传的、在 B 节点读不到"。**多节点之前必须先完成对象存储驱动**
> （[16 §九](16-文件与导出.md#九对象存储现状与边界)、开发计划 F-01）；当前只支持单实例或"全部节点共享同一网络卷"。

## 六、发布与回滚

### 6.1 发布

1. 备份数据库与 `shared/`。
2. 构建前端产物。
3. 更新后端代码与依赖。
4. 模型变更先在预发验证 DDL。
5. 重启 API 与调度器。
6. 验证 `/healthz`、登录、权限、上传、导出、定时任务。

### 6.2 回滚

- 代码：切回上一版本并重启。
- 前端：替换 `dist`。
- 数据库：使用发布前备份恢复；若已执行不可逆 DDL，需要单独评估。
- 密钥：回滚时保持与备份一致，否则密文无法解密。

### 6.3 灰度建议

- 先用一个租户验证新版本。
- 观察错误率、慢请求、登录失败率。
- 确认无异常后再全量。

## 七、监控与告警

| 指标 | 来源 | 建议阈值 |
|------|------|----------|
| 接口错误率 | 操作日志 `status=0` | 5 分钟内 > 5% |
| 慢请求 | 应用日志 | `cost > 3000ms` |
| 登录失败 | 登录分析 | 突增 3 倍 |
| 在线会话 | `/metrics` | 异常归零 |
| 错误率 | `/metrics` | `5xx / total` 5 分钟内 > 1% |
| 延迟 | `/metrics` | P95 > 800ms 持续 5 分钟 |
| 连接池 | `/metrics` | `cccms_db_pool_checked_out` 长期接近 `pool_size + max_overflow` |
| 调度器 | `/metrics` | 心跳年龄 > 3 个轮询周期 |
| 磁盘 | `/healthz` | 剩余 < 10% 预警 |
| 定时任务失败 | `sys_crontab_log` | 连续 3 次失败 |
| 审计链异常 | `verify_chain` | `ok=false` |

> **提示**：`/metrics` 默认只允许本机访问，Prometheus 与服务同机时可直接抓取；跨机部署需调整 `CCCMS_METRICS_ALLOW_IPS` 或经内网代理。

## 八、备份与灾难恢复

| 对象 | 频率 | 保留 |
|------|------|------|
| MySQL 全量 | 每日 | 30 天 |
| `shared/uploads` | 每日增量 | 30 天 |
| `.env` | 变更时 | 长期加密保管 |
| 审计链备份 | 随数据库 | 按合规要求 |

恢复演练：

1. 在隔离环境恢复数据库与附件。
2. 使用备份时的密钥启动。
3. 校验审计链。
4. 验证登录、权限、附件下载、导出。
5. 记录恢复耗时（RTO）与丢失窗口（RPO）。
