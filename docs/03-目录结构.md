# 目录结构

> 本文给出仓库整体与前后端的目录职责、命名约定。看懂这一篇，找代码基本靠直觉。

---

## 一、仓库顶层

```
cccms/
├── .github/         # CI 工作流（后端 / 前端）
├── .gitattributes   # 换行符统一为 LF（各平台检出结果一致，否则风格门禁会出假信号）
├── docs/            # 文档中心（含更新日志、开发计划与 nginx.conf.example 部署样例）
├── frontend/        # 管理前端（Vue 3）
├── server/          # 后端服务（Webman）
└── README.md        # 项目主页（面向 GitHub 首页）
```

## 四、命名约定

### 4.1 后端

| 对象 | 约定 | 示例 |
|------|------|------|
| 插件 | 小写，无连字符 | `cccms`、`index`、`shop` |
| 控制器 | `{模块}Controller.php`，位于 `app/controller/` | `UserController.php` |
| 逻辑层 | `{模块}Logic.php`，位于 `app/logic/` | `UserLogic.php` |
| 模型 | 单数大驼峰，位于 `app/model/` | `User.php`、`CrontabLog.php` |
| 表名 | `sys_` 前缀（连接配置自动补全，模型里写 `user`） | `sys_user` / `User` |
| 权限节点 | `{插件}:{模块}:{动作}`，全小写，至少 3 段 | `cccms:user:save` |

### 4.2 前端

| 对象 | 约定 | 示例 |
|------|------|------|
| 页面 | `pages/{插件}/{模块}/index.vue` | `pages/cccms/user/index.vue` |
| 组件名 | **必须等于菜单 slug**（keep-alive 依赖） | `defineOptions({ name: 'cccms:user' })` |
| API 文件 | `api/{模块}.ts` | `api/user.ts`、`api/log.ts` |
| 组件 | `Art{名称}.vue`，位于 `components/core/` | `ArtTable.vue` |
| Store | `stores/{域}.ts`（组合式写法） | `stores/notice.ts` |
| 设计 token | `--art-{语义}` | `--art-primary`、`--art-card-bg` |
| 列宽记忆键 | `cccms_table_width:{路由或 storageKey}` | 与列显隐键 `cccms_table_hidden:v2:` 并列（列**默认全显**，仅用户手动隐藏时才写入） |
| 筛选方案键 | `cccms_table_filter_scheme:{路由或 storageKey}` | 单条方案见 `cccms_table_filter:` 前缀 |

### 4.3 「权限节点 / 控制器 / 页面」三者可互相推导

```
cccms:user:save
   │      │      └─ 动作 → UserController::save()
   │      └──────── 模块 → pages/cccms/user/index.vue
   └─────────────── 插件 → plugin/cccms/
```

这条推导链是 CCCMS 保持结构一致的关键：改一处，另外两处的位置可直接算出。

## 五、约定与边界

- **`plugin/cccms` 只放框架级基础功能**，一切业务功能必须新建业务插件，禁止往 `cccms` 插件里塞业务代码。
- 新建业务插件用 `php webman cccms:plugin-create {name}` 一键生成骨架并自动登记菜单（交互式选前台 / 后台，见 [11-常用命令与运维 §1.13](11-常用命令与运维.md#113-cccmsplugin-create--生成业务插件骨架并登记菜单)）。
- 业务插件只要提供 `plugin/{插件}/db/menu.php`，就会被自动纳入菜单同步、权限扫描、数据权限检查与回收站类型扩展。
- 主应用 `server/app/` 保持干净；业务代码永远落在插件里。
- `server/runtime`、`server/public/storage` 属于运行时产物，不纳入版本控制。
