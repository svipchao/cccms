# 施工模式

## 第 0 步：找到施工依据

1. 找最新体检报告：优先 `reports/`，其次 `docs/`，文件名形如 `项目体检与竞品分析-YYYY-MM-DD.md`。
2. **找不到就停下**，告诉用户"没找到报告，请先执行 `/project-doctor` 做诊断"，不要凭空改代码。
3. 读到后先读完整份报告，再读项目里的 `AGENTS.md` 或同类规则文件。**规则文件的约定优先级高于本技能的默认值。**

## 第 1 步：复核（不许跳过）

| 复核结果 | 处理 |
|---|---|
| 问题真实存在 | 进入分诊 |
| 已在此前修复 | 标注"已失效"剔除 |
| 报告判断有误 | 剔除，说明错在哪、证据是什么 |
| 描述过重/过轻 | 修正级别后分诊 |
| 无法复现 | 单列"无法复现"，不进入施工 |

先输出「复核结果表」：报告条目 → 复核结论 → 证据（文件行号或命令输出）。这张表是后续所有施工的依据。

## 第 2 步：三轨道分诊

**只有轨道 A 允许自动执行。**

### 轨道 A · 直接修（自动做）

问题明确、改动局部、有明确验收标准、不改变对外行为。

例：空指针/类型错误、边界条件遗漏、报错不友好、明显逻辑 bug、死代码、文档与实际不符的文字修正、缺失的异常处理、明显的性能小问题。

### 轨道 B · 完善功能（每项先确认）

需要补一整块能力，或会改变用户可见行为。

例：半成品功能收尾、缺失的异常路径、报告"功能缺口池 → 建议做"的条目。

**不能直接做。** 先出方案（改哪些模块、新增什么、影响什么、怎么验证），等用户点头。功能加错比 bug 难回滚。

### 轨道 C · 改进与重构（默认不做）

结构调整、跨模块改动、依赖升级、数据迁移。

例：拆模块、统一重复逻辑、换实现方案、升级依赖、改数据格式。

**默认不执行。** 只输出方案和风险（为什么值得做、不做会怎样、回滚方案），等用户单独安排。

## 第 3 步：排工单

```markdown
| ID | 来源 | 级别 | 类型 | 改动文件 | 风险 | 验证方式 | 批次 |
|----|------|------|------|----------|------|----------|------|
| A1 | 报告 P2-3 | P2 | 修复 | popup.ts | 低 | 手动打开面板确认 | 1 |
```

排批次规则：

- **一批最多 3 个工单，改动文件合计不超过 5 个。**
- 同批尽量同模块或同类风险，方便回归。
- 有依赖关系的按依赖顺序排。
- **P0 单独一批，优先做，做完立刻验证。**

工单表输出后**直接开始第 1 批**，不用等确认。只在红线处停。

## 第 4 步：逐批施工

每个工单按顺序做，不许跳步：

1. **读真实调用链**：这个函数/模块被谁调用、输出被谁消费。没读清楚就动手是最大返工来源。
2. **锁定改动边界**：只改工单涉及的位置。不顺手重命名、不顺手抽函数、不调格式。
3. **改**：最小必要改动。如果最小改动会留下功能割裂（A 分支修了、B 分支同款问题没修），可以扩大范围，但必须先在进度播报里说明原因和范围。
4. **验证**：跑真实命令，贴真实输出。优先级：项目已有测试命令 → 构建 → 手动复现步骤 → 静态检查。
5. **记录**：写进修改记录（见下）。

每批结束：输出本批小结（改了什么、验证结果、连带影响）→ 更新工单状态 → **继续下一批**，不需等待。用户可随时喊停。

## 进度播报

每个工单开始时输出：

> 🧩 工单：{ID + 一句话}
> 🎯 目的：{解决什么问题}
> ▶️ 改动：{文件 + 具体位置}
> ✅ 验证：{命令 + 结果}
> 🧾 证据：{输出摘要或截图路径}
> 📝 状态：{完成 / 部分完成 / 卡住}

## 修改记录与版本

每批结束追加写入 `reports/修复记录-{YYYY-MM-DD}.md`（目录跟随报告所在目录）。模板见 `templates.md`。

**每条必须有"验证"和"回滚方式"两栏。填不出来说明这条不该算完成。**

版本策略：

- 纯修复（轨道 A）：升 patch 位。
- 补功能（轨道 B）：升 minor 位。
- 版本号在几处维护就同步几处（`package.json`、`manifest.json`、版本常量），不要只改一处。
- 项目没有版本策略时不要自己发明，写进"待确认"。

## 收尾汇报

1. **修复统计**：修了几条、跳过几条、为什么跳过。
2. **验证总览**：哪些跑过测试、哪些只手动验证、哪些完全没验证。
3. **轨道 B 方案清单**：每条一段（做什么、影响什么、建议优先级），等用户决定。
4. **轨道 C 重构建议**：只列方案和风险，明确写"本轮未执行"。
5. **新发现**：施工中发现但报告没有的问题。单独列出，**不要顺手修掉**。
6. **下一步建议**：最该做的 3 件事。
